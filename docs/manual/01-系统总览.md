# 第 1 章 系统总览

## 1.1 coara 是什么

coara 是一个跑在你自己电脑上的**个人 AI 助手**。你在命令行（或网页、手机 App）里用自然语言交代事情，它去理解、动手、把结果交回来。

举个例子。你说：

> 帮我把 stocks 目录下这几份周报汇总成一个 Excel，顺便看看有没有格式异常的数据

接下来发生的事情大致是：coara 先找到并读完那几份文件，发现工作量不小，就派了两个"分身"并行处理；其中一个分身报告某份文件有一列数据全是乱码；最后它把汇总好的 Excel 放到你面前，并告诉你哪份文件有问题、在第几行。

这个过程里它用到了文件工具、子智能体和自己的判断——这些就是本手册要讲的全部内容。先把三个最常用的词解释一下：

- **Root**：和你对话的那个"它"。全系统只有一个 Root，所有入口（命令行、网页、手机）背后都是它
- **工具（tool）**：它的手和脚。读文件、写文件、执行命令、搜网页……每个工具都有名字和说明，它按说明使用
- **工作空间（workspace）**：它帮你照看的一块"地盘"——通常是一个项目目录。你可以让它同时照看多个，各有自己的日程和消息

## 1.2 它是怎么把事情做成的

面对一件事，Root 有三种做法，按事情的形状选：

**自己上手（工具调用）**
事情简单就直接做。读个文件、改两行配置、搜一下资料——一次或几次工具调用就完事。

**派分身去做（子智能体 delegate）**
事情能拆开、或者需要独立忙活一阵时，它会创建**子智能体**。子智能体是轻量的"分身"，拿着 Root 写给它的任务书（目标、范围、方法、规矩）独立干活，干完把结果交回。你能派的分身有两种：

| 分身 | 干什么 | 特点 |
|------|--------|------|
| **coaras** | 工程执行 / 只读摸底：写代码或并行查事实 | 能力最全，相当于 Root 的克隆；只读时在任务书写明禁止修改 |
| **aide** | 资料调研与头脑风暴：后台查资料、发散提案 | 后台运行，不打扰你 |

另有三个**系统专属**分身，不接受主动委派，由系统到点自动调度：`janitor`（工作空间管家：维护概况 + 记忆 + 过目消息）、`daily`（每日整理记录）。

**编成流水线去跑（工作流 workflow）**
步骤多、有依赖关系、要反复跑的事，它会设计成**工作流**：一张由节点和连线组成的图（用 WDL 语言描述），交给独立的工作流引擎执行。引擎里的每个节点同样是一个完整的智能体，不是写死的脚本。

三种做法常常混用：先派 coaras 摸清情况，Root 再设计工作流，工作流节点里又包含分身执行任务。

## 1.3 它由哪些部分组成

从下往上，coara 由四层组成。不用背，混个眼熟即可：

1. **入口层**——你在哪里跟它说话：命令行（`coara`，attach 到常驻内核的 CLI 端）、网页（浏览器访问内核托管的 Web 服务）、手机 App（经 Matrix 协议）。三个端平等独立，背后是同一个**常驻内核**（`coara tray` / `coara daemon` 持有 Root），随时接入、随时断开
2. **运行层**——Root 和它的大脑循环：理解输入 → 调用 LLM → 执行工具 → 整理结果，如此往复，直到给出最终回复。上下文太长时会自动压缩记忆
3. **编排层**——子智能体（同进程的轻量分身）、工作流引擎（独立子进程）、定时与事件触发（事项和事件源）
4. **地基**——配置、日志、存储。你的配置和工作数据放在"coara Home"目录，每个工作空间还有自己的活动记录

还有两个看不见的帮手值得一提：

- **技能（skill）**：写给 LLM 看的领域说明书。比如"长文档写作"技能会教它先列大纲、分章写入、最后合并。遇到匹配的任务它会主动加载
- **宝箱（vault）**：加密存放敏感数据（密码、密钥、私密文档）的地方，用密码解锁，锁定时连工具都碰不到里面

## 1.4 它在哪些地方留了记录

coara 做的每件事都有迹可循：

- **对话历史**：你和它的每轮对话，可随时翻看
- **trace（运行轨迹）**：每次 LLM 调用、每次工具执行都是一条结构化事件，网页端的仪表盘能看到实时滚动
- **工作空间动态**：工作空间发生的变化（文件变动、定时任务结果、工作流状态）按空间归档，手机端有红点提醒
- **错误日志与用量统计**：工具失败进错误日志，token 消耗进用量统计（`coara usage summary` 可查）

## 1.5 它的边界

了解边界能帮你更好地用它：

- **单用户**：一个 coara 进程服务一个用户，没有多租户概念
- **它依赖 LLM 的判断力**：规划是否合理、代码是否正确，上限取决于所用模型
- **写操作集中在工作空间**：它对已登记的工作空间不直接动手改代码，这类活派 coaras 锁定到那个空间去做（这是约定而非硬封锁，但强烈建议遵守）
- **记忆有上限**：对话历史受模型上下文窗口限制。超限会自动压缩成摘要，极长对话可能丢失早期细节

## 1.6 常见误解

| 误解 | 实际情况 |
|------|----------|
| 它是个聊天机器人 | 聊天只是入口，它的主体是"调用工具把事情做成"的执行系统 |
| 子智能体是独立程序 | 它们是同一进程里的轻量分身，共享 LLM 配置，用完即弃 |
| 工作流是定时脚本 | 工作流的每个节点都是完整智能体，能理解任务、调用工具、接受质检 |
| 它会自己乱改文件 | 危险操作有审批闸：危险 shell 命令（sudo、dd、mkfs 等）、删除工作空间、删除工作流会强制弹窗确认；你也可以让它"改之前先问我"，或在配置里加强制审批名单 |
| CLI、Web、手机是三套各自运行的程序 | 它们是同一个常驻内核（`coara tray` / `coara daemon`）的三个显示端：内核持有 Root 并托管 Web/Matrix，端只负责显示与交互，随时接入、随时断开；终端只是端，关掉终端内核照常跑 |

## 1.7 本章小结

- coara 是跑在你电脑上的个人 AI 助手，Root 是唯一对话入口
- 做事三招：自己上手（工具）、派分身（子智能体）、编流水线（工作流）
- 四层组成：入口、运行、编排、地基；另有技能和宝箱两个帮手
- 全程留痕：对话、trace、工作空间动态、用量都可查
