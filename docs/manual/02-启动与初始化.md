# 第 2 章 启动与初始化

## 2.1 第一次运行会发生什么

装好之后在命令行输入 `coara` 回车。如果这是第一次运行、且还没有任何可用的 LLM API Key，它会先弹出一个**首次使用向导**，而不是直接报错退出：

```text
首次使用向导
还没有可用的 LLM API key。选一个 provider，填入密钥后即可开始聊天。
```

向导让你从已配置的 provider 列表里选一个，粘贴密钥，回车即完成。密钥会写入 `<coara_home>/system/.env`，所选 provider 会被记为默认（写入 `<coara_home>/users/default/llm_preferences.yaml`），当前进程立即生效，不用重启。

两种不会弹向导的情况：

- **已有可用密钥**：静默把默认 provider 对齐到"有密钥的那个"，直接进入聊天。
- **非交互环境**（管道、后台服务）：没法弹窗，只做默认对齐；没密钥就按启动失败处理（见 2.5）。

密钥里的占位符（`your-key`、`xxx`、`changeme` 这类）会被当作"没配置"处理。

## 2.2 一个内核，三个端

coara 的核心是一个**常驻内核**——持有 Root 的那份代码。命令行（CLI）、网页（Web）、手机（Matrix 远程通道）都是接在它上面的**显示端**：端与端平等、独立，随时可以接入和断开。

```
coara        # 确保内核常驻，本终端作为 CLI 端接入对话
```

输入 `coara` 只做两件事：

1. **检查内核在不在**。常驻内核还没启动时，先把它拉起来（`coara tray` / `coara daemon`，作为脱离终端的独立进程运行）；已经在跑就直接复用。
2. **本终端 attach 接入**。终端成为 CLI 端，出现提示符开始对话。

几个由此而来的性质：

- **终端只是端，不是内核**。关掉终端窗口，内核照常运行，Web 和手机不受影响。下次打开终端输入 `coara`，接到的还是同一个内核。
- CLI 就是裸 `coara`；Web 和 Matrix 由内核托管，入口在系统托盘（`coara tray`）——右键托盘图标可以「打开 Web 界面」「手机连接（配对二维码）」「退出 coara」。
- **Web / Matrix 不需要单独启动**。内核起来后 Web 服务（默认 8080 端口）和 Matrix 通道就位：浏览器访问本地端口即可打开 Web 界面，手机 App 扫托盘弹出的配对码即可连接。
- **一台电脑一个内核**。再开终端输入 `coara` 会 attach 到同一个内核；同一工作空间的第二条 attach 会被服务端拒绝。
- **非交互环境（管道、脚本）没得聊**。终端不是 TTY 时，裸 `coara` 直接报错退出（见 2.5）。

## 2.3 配置文件都在哪

启动时第一件事是确定"家目录"（coara_home），所有配置和长期数据都围绕它组织。

### coara_home 的确定顺序

1. 配置里的 `coara_home` 字段；
2. 环境变量 `COARA_HOME`；
3. 都没有则用当前目录下的 `.coara`（单工作空间试用模式）。

长期使用建议设 `COARA_HOME`（比如 `D:\coara`），否则运行数据会散在各工作空间目录里。

### 配置文件读取顺序

| 文件 | 位置 | 内容 |
|------|------|------|
| `.env` | `<coara_home>/system/.env` | API Key、Matrix 密码等机密 |
| `providers.yaml` | `<coara_home>/system/providers.yaml` | LLM provider 与模型定义 |
| `config.yaml` | `<coara_home>/system/config.yaml` | 全局行为配置 |
| `config.yaml`（用户级覆盖） | `<coara_home>/users/default/config.yaml` | 个人覆盖项，优先级高于 `system/` |
| `llm_preferences.yaml` | `<coara_home>/users/default/llm_preferences.yaml` | `/model --global` 命令写入的全局默认 |

开发环境下仓库根目录的 `config.yaml` / `providers.yaml` / `.env` 也会加载，优先级高于 `system/` 和用户级覆盖（仅次于 `llm_preferences.yaml`）——这是给开发者放默认值用的，普通用户不用关心。

## 2.4 从回车到"能用了"

中间的过程不用你管，但知道顺序有助于排查问题：

1. **读配置**：按 2.3 的顺序加载 `.env`、`providers.yaml`、`config.yaml`，确定 coara_home。
2. **首次向导**：没有可用 API Key 时弹向导（见 2.1）。
3. **起日志**：文本日志写到 `<coara_home>/workspaces/<id>/logs/`，工具失败等异常进工作空间的错误日志。
4. **连 LLM**：按 `providers.yaml` 构造 provider，确定默认 provider 和默认模型。
5. **创建并初始化 Root**：加载 Root 的提示词，注册工具（详见 2.6），发现技能，启动后台调度循环，订阅事件总线。
6. **登记在线状态**：写入 `<coara_home>/runtime/active.json`（工作空间、进程号、会话号），手机端靠它找到当前这个 coara。
7. **起前端**：内核托管 Web 与 Matrix（裸 `coara` 则本进程作为 CLI 端 attach 接入，见 2.2）。

之后 CLI 出现提示符（或打印"已就绪"），就可以开始交代事情了。

## 2.5 启动失败的常见原因

| 现象 | 可能原因 |
|------|----------|
| 提示找不到 providers.yaml | 文件不在 `<coara_home>/system/`，或 `COARA_HOME` 指错了地方 |
| 提示缺少 API Key | `.env` 没配密钥，或配的是占位符；首次向导被跳过（非交互环境） |
| Matrix 连不上 | homeserver 地址错、账号密码错；gomatrix 由 coara 托管拉起，异常时看托盘「手机连接」能否弹出配对二维码，或检查 `system/.env` 里的 Matrix 配置 |
| Web 打不开 | 端口被占用（可用 `COARA_WEB_PORT` 环境变量改端口，默认 8080）；浏览器访问 `http://127.0.0.1:8080` |
| 改了配置不生效 | 大部分配置要重启；事件源等少数支持热重载 |

## 2.6 进阶：工具为什么分批注册

Root 初始化时工具不是一次全注册，而是分三批：

1. **进程级工具**（`web_search`、`web_fetch`）：与工作空间无关，全进程注册一次。
2. **运行时工具**（文件读写、`shell`、`todo`、`delegate` 等）：绑定到当前工作空间，每个运行节点各自注册；`delegate` 只在 `delegate_depth == 0` 的节点（Root 与各工作空间前台会话）上注册。
3. **Root 专属工具**（`orchestrator`、`reminder`、`ws`、`vault`、`plan_mode`）：只有面向用户的 Root 才有。

分批的意义在于：同一套代码同时服务 Root、子智能体和工作流节点，但三者能力不同——子智能体不能再委派、看不到宝箱，工作流节点更是受限。注册时机决定了"这个节点存不存在某个工具"，这比"注册了再藏起来"更彻底（详见 [第 4 章](./04-工具系统.md)）。

技能也在这个阶段**发现**（内置、用户级、工作空间级三个来源），但只是放进技能池，不进提示词；要用时由 `skill` 工具激活（详见 [第 11 章](./11-技能系统.md)）。

## 2.7 本章小结

- 首次运行无 API Key 时会弹交互向导，选 provider、填密钥即可完成配置。
- 常驻内核由 `coara tray` / `coara daemon` 持有；裸 `coara` 只是 CLI 端 attach 接入——终端只是端，关掉终端内核照常跑。
- Web 与 Matrix 由内核托管，入口在系统托盘；Matrix 配置不全自动降级跳过。
- 配置围绕 coara_home 组织：`system/` 放配置，`users/default/` 放个人覆盖和模型偏好。
- 启动顺序：读配置 → 向导 → 日志 → LLM → 初始化 Root → 登记在线 → 起前端。
- 工具分三批注册，决定了 Root、子智能体、工作流节点的能力差异。
