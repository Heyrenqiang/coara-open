# 第 3 章 对话与轮次

## 3.1 一轮对话里它在干什么

你说：「帮我查一下今天的新闻，写个摘要存成文件。」从按下回车到看到回复，中间通常是这样的：

```text
第 1 次调用 LLM → 它决定用 web_search，系统执行搜索，结果写回上下文
第 2 次调用 LLM → 它决定用 write 写文件，系统执行，结果写回上下文
第 3 次调用 LLM → 它给出文字回复："已搜索并保存到 summary.md"
→ 本轮结束
```

这就是**轮次（turn）**：从你的一条输入开始，到它给出最终回复结束。一轮之内它可以**迭代**多次——每次迭代都是"调用 LLM → 执行它要的工具 → 把结果喂回去"，直到它不再调用工具、直接给出文字，本轮才算完。

所以"问一次只答一次"是错觉：简单问答确实一次 LLM 调用就够，但只要动工具，一轮里往往有好几次调用。每次调用都能看到本轮之前发生的全部对话和工具结果。

## 3.2 它在干活时，你还能做什么

### 接着说（接续输入）

它还在跑的时候你直接再发消息，不会排队等下轮，而是作为**接续输入**插进当前这一轮——下一轮迭代时它就能看到。它按意图处理：闲聊提问会立刻先回你一句、同时继续干活；改方向就按新意思继续；新任务可能开个分身并行。明确说"停/别做了"则收束本轮。

### 打断（Ctrl+C 或 /stop）

打断的含义是**结束当前这一轮**：立刻强制停掉正在跑的 LLM / 工具 / 前台与后台子智能体 / bash 后台任务，本轮不再继续迭代。本轮已经写进对话历史的内容（你的消息、中间输出、已完成的工具结果）**保留**；尚未完成的工具调用会收口成「已取消」，方便下一轮继续接着聊。若打断时有子智能体在跑，历史里会记上它们的 task_id，继续原任务时可用 `delegate(action="resume", task_id=…)` 从断点接着跑。

注意：

- **磁盘上的改动不撤销**。文件已经写了、命令已经跑了，这些副作用留在原地。
- 屏幕上已经打印的内容也不擦除。
- 若只想清空整段对话记忆，用 `/new`，不是打断。

### 重开（/new）

`/new` 直接清空整个会话，开一轮全新对话，旧的全部丢弃。它不是打断，没有回滚概念。

工作空间切换要分两条路径：你手动切换（/ws、Web、手机）不打断进行中的回合，离开空间的这一轮继续跑完；只有 LLM 在回合内自己调 `ws(switch)` 才会结束当前轮次——源工作空间会删掉「切换到 xxx」那条用户输入及其后的 ws 调用链（避免污染后续对话），更早的对话仍保留在该工作空间会话里，切回来还能继续。

## 3.3 它看到的上下文长什么样

它每次调 LLM，发出去的东西分两块：

**系统提示词**：它的"工作规范"，整个会话期间一个字不变。当前日期、工作目录这类易变信息**不放**在这里——放在这里会让 LLM 服务商的缓存失效，变贵变慢。

**消息历史**：你的消息、它的回复、工具结果，以及系统随时注入的补充信息。动态信息全走这条路。第一轮对话时会先注入一条环境消息（今天日期、地点、操作系统、工作目录），伪装成用户消息存在历史里。

### 标签协议

历史里不少内容包着标签，表示不同性质。它按标签决定怎么处理：

| 标签 | 含义 |
|------|------|
| `<系统消息>` | 补充上下文，供参考，不必回复（环境信息、工具失败说明等） |
| `<系统提醒>` | 必须遵守的系统指令 |
| `<事件提醒>` | 外部自动化事件（文件变动、webhook 等） |
| `<工作空间消息>` | 引用的工作空间动态 |
| `<引用内容>` | 引用的会话上文 |
| `<手机消息>` | 经 Matrix / 手机端进来的用户消息 |
| `<web消息>` | 经 Web 端进来的用户消息 |
| `<接续输入>` | 本轮运行期间你继续发来的消息，高优先级 |
| `<state_snapshot>` | 上下文压缩后对更早对话的摘要（见 [第 13 章](./13-上下文窗口与压缩.md)） |

这套标签是它区分"你说的话"和"系统塞给它的资料"的方式。你正常聊天不用关心标签，但排查"它为什么这样理解"时，知道有这层机制会有帮助。

`<手机消息>` / `<web消息>` 是用户消息的来源标签，只在进入模型上下文（message_history）时按来源现包；三端同源同用户，CLI 本地输入不加标签。它们不落带（写入会话事件前剥回裸文本），也不决定端上显示——web 端显示层按来源自行分类。

### @ 服务台（仅 CLI）

在 **CLI（attach）** 里整段输入 `@台名 …`（如 `@daily 今天摘要`、`@配置 换模型`），会投到对应服务台会话，**不换**当前工作空间视图。Web 聊天框与手机没有这套解析，`@…` 会当作普通用户消息交给模型。

## 3.4 它怎么判断"这轮说完了"

每轮迭代后系统检查一次，规则很朴素：

- 这轮调用了工具 → 继续（执行完再问 LLM）。
- 没调工具，但待办清单还有没完的事，且回复很短（不足 400 字）→ 视为中间汇报，继续。
- 没调工具，有待办但回复够长 → 视为已交付实质内容，结束本轮。
- 没调工具，但有**前台子智能体**还没干完 → 注入一次系统提醒（调 `delegate(action="wait")` 等齐，或明确放弃放行；见 [第 5 章](./05-子智能体与委派.md)）。
- 以上都不是 → 输出最终回复，结束本轮。

## 3.5 它原地打转怎么办

两道保险：

**停滞保护**：如果连续几轮犯同一个工具错误（同样的工具、同样的参数、同样的报错），到第 4 次系统直接叫停本轮，报告"疑似卡住"，防止空转烧钱。

**循环检测**：同一个工具用同样的参数反复调（比如一遍遍读同一个文件），读取类到第 3 次、执行类到第 5 次就会被拦下，要求它换个思路。这是拦截不是缓存——它必须改变做法才能继续。

## 3.6 进阶：当 LLM 不会"调工具"时

主流 provider 原生支持函数调用（LLM 直接返回结构化的工具调用），这是最稳的路径。如果所用模型不支持或调用失败，系统会自动降级为 **ReAct 模式**：把工具说明写进提示词，让它用文本输出"思考—行动"，再由系统解析成工具调用。流程对上层透明，但解析稳定性不如原生方式。

同一轮里的多个工具调用默认**并行**执行，只有写同一个文件的操作会排队串行（详见 [第 4 章](./04-工具系统.md)）。工具结果太大时会自动落盘、上下文里只留摘要和头尾预览（spill 机制，见 [第 20 章](./20-存储布局.md)）。

另外，单次输入同一时刻只处理一轮：你再发新消息会变成接续输入，而不是并发开新轮次。

## 3.7 本章小结

- 一轮对话 = 多次"LLM → 工具 → 再 LLM"的迭代，直到它直接给出文字回复。
- 运行中你可以接着说（接续输入）、打断（结束本轮但保留已产生的对话上下文，不撤销磁盘改动）、或 `/new` 重开；少数只读 / 纯 UI 的斜杠命令（`/stop` `/help` `/status` `/usage` `/tools` `/events` `/vault` `/ws` `/report` `/login` `/message` `/model` `/log`）运行中立刻执行，其余命令等本轮结束。
- 系统提示词保持静态，动态信息全部以带标签的消息注入历史。
- 结束本轮由明确规则判定：工具有没有调、待办有没有完、回复够不够长、前台分身有没有回。
- 停滞保护（同错 4 次）和循环检测（读 3 次、执行 5 次）防止原地打转。
