# 第 4 章 工具系统

## 4.1 它能用哪些工具

工具是它的手和脚：LLM 负责想，工具负责做。内置工具按类别分：

| 类别 | 工具 | 干什么 |
|------|------|--------|
| 文件 | `read`、`write`、`edit`、`delete`、`glob`、`grep` | 读、写、改、删文件，按名找文件，按内容搜索；`write` 还能直接生成 `.docx` / `.xlsx` / `.pdf` |
| 网络 | `web_search`、`web_fetch` | 搜网页、抓网页内容 |
| 命令 | `shell` | 执行 shell 命令 |
| 委派 | `delegate` | 派子智能体（见 [第 5 章](./05-子智能体与委派.md)） |
| 计划 | `plan_mode` | 进入/提交/退出计划模式 |
| 调度 | `reminder` | 个人定时提醒 |
| 待办 | `todo` | 它自己的任务清单 |
| 记录 | `record`、`local_search` | 写本地记录、检索记录（record 只挂在 janitor/daily 等系统侧，Root 用挂起的 local_search 读） |
| 技能 | `skill` | 列出、激活技能 |
| 宝箱 | `vault` | 开关加密宝箱 |
| 工作空间 | `ws` | 工作空间管理、动态、事项 |
| 集成 | `tool`、`send_file` | 挂起工具池的搜索与装载；经 Matrix 或 Web 出站通道发文件（target=auto\|matrix\|web） |

除了这些常驻工具，还有**挂起工具**：挂起的内置工具（收藏、宝箱、提醒、截图、邮件、打印机、工作流编排 `orchestrator` 等，名字和一句话说明列在它的系统提示词里）。它们平时不占用注意力、不暴露给模型，需要时先用 `tool(action="search")` 搜索、`tool(action="activate")` 装载，再像普通工具一样调用（`orchestrator` 正是这类：激活 `workflow` 技能后揭示，见 [第 6 章](./06-工作流系统.md)）。

**后台任务**没有独立的 `task` 工具了：长命令用 `shell` 的 `timeout_ms=0` 转后台执行；子智能体后台委派，硬停用 `delegate(action="stop")`（会弹审批）；图/视频生成的查看与取消用 `media(action="status" / "cancel")`。

## 4.2 它怎么知道该用哪个

每个工具都自带一段描述和参数说明，这就是它用工具的"说明书"，而且是**硬约束**——它必须按说明调用，不能只回文字假装做过。

但不是所有注册过的工具它都看得见。每次调 LLM 前，系统会过滤一遍可见工具：

- **白名单**：子智能体只能看到自己名单内的工具（比如 aide 看不到 `write`）。
- **所有者专属**：`vault` 这类工具只有 Root（所有者上下文）可见。
- **计划模式**：计划模式下只放行一组只读为主的工具（`read`、`grep`、`glob`、`web_search`、`web_fetch`、`delegate`、`todo`、`write`、`edit`、`plan_mode`）。
- **挂起装载**：挂起的内置工具默认隐藏，`tool(action="activate")` 装载后才出现。

## 4.3 哪些操作会先问你

大部分工具调用直接执行；以下几类会先弹确认框，等你点"同意"才动手：

**工具自己声明的危险操作**：
- `shell` 以高破坏性命令开头时（`sudo`、`su`、`mkfs`、`format`、`fdisk`、`parted`、`dd`、`mkswap`）
- `write` / `edit` / `delete` 的目标路径（含 `template_path`）在挂载工作空间之外时
- `ws` 的 `remove` 动作（移除工作空间）
- `orchestrator` 的 `delete` 动作（删除草案）
- `delegate` 的 `stop` 动作（硬停子智能体，进行中的结果全部丢弃）

**它自己觉得没把握时**：`write`、`edit`、`delete`、`shell` 这四个工具的参数里有一个 `require_approval` 开关，它可以主动设置并附上理由，把这次调用升级为人工审批。系统要求它对可疑或危险的操作这样做。

**你在配置里强制的**：`config.yaml` 的 `security.call_policy.prompt` 名单里列出的工具，一律先问（例如把 `shell` 整个列进去，则所有命令都要确认）。

确认框有 5 分钟超时，超时不答视为拒绝。拒绝和超时都会作为结果反馈给它，由它决定换方案还是停手。

## 4.4 一轮里多个工具怎么执行

同一轮里它可能一次要求调多个工具。默认**全部并行**——同时读三个文件、同时搜两个关键词，互不等待。

例外是**写锁**：会改同一个目标的操作自动排队。比如对同一文件的 `write` 和 `edit` 会串行执行，避免互相覆盖；对不同文件的写仍然并行。

## 4.5 文件工具的安全边界

文件类工具遵循几条硬规则：

- **只认绝对路径**。`read` / `write` / `edit` / `delete` 传相对路径会被直接拒绝；`glob` / `grep` 不给路径时默认搜工作空间根目录。
- **越界写入先问你**。挂载工作空间内的写入直接执行；目标在挂载之外时弹人工审批确认，你同意才动手。delegate 子智能体是例外——它的边界是硬拒绝，报错"路径不在任何已挂载工作空间内"。
- **拒绝路径花招**。UNC 路径、Windows 扩展路径、备用数据流一律不收。
- **执行时读实时内容**。`edit` / `write` / `delete` 动手前会重新读磁盘，不依赖它"记忆中"的文件内容；所以它改别人刚动过的文件也不会基于过期内容。系统不强制它先 `read` 再 `edit`，但它被教导先读核对。

另外，**超大输出不会撑爆上下文**：工具结果超过阈值时自动落盘保存，上下文里只留引用和头尾预览（spill 机制），它需要时可按位置分段取回。

## 4.6 进阶：一次工具调用的完整旅程

从 LLM 输出工具调用到结果写回历史，中间经过：

1. **前置检查**：循环检测等拦截器先看这一调是否合理。
2. **审批门**：按 4.3 的规则决定放行还是弹窗。
3. **沙箱检查**：工作空间标记为"不受信任"时，命令黑名单、路径黑名单、内网 URL 拦截生效。
4. **执行**：默认 60 秒超时；`delegate`、`orchestrator`、`shell` 自己管理超时，不套外层限制（`shell` 前台默认只等 10 秒，**超时即失败**：进程树被终止并返回明确超时错误；长命令用 `timeout_ms` 放大或 `timeout_ms=0` 转后台）。
5. **输出分三路**：给 LLM 的紧凑文本（进历史）、给你看的富文本（如 `edit` 的 diff 面板，只在终端显示）、给审批框的执行前预览。三路互不污染。
6. **写回历史**：结果作为工具消息进入上下文，触发下一轮 LLM 调用。

你按 Ctrl+C 时，取消信号会传播到所有正在执行的工具，做到一半的工具收到取消；未完成的前台/后台子智能体以及 bash 后台任务也会被**强制**停掉（见 [第 3 章](./03-对话与轮次.md)）。

## 4.7 本章小结

- 工具按类别覆盖文件、网络、命令、委派、调度等；挂起的内置工具（含工作流编排 `orchestrator`）按需经 `tool` 装载；后台任务由 `shell` 后台模式与 `delegate` 承担。
- 工具描述是硬约束；可见性由白名单、所有者上下文、计划模式和挂起装载共同过滤。
- 审批是二元门：工具自声明的危险操作、它主动要求（`require_approval`）、配置强制名单，任一命中即弹确认，5 分钟超时；`call_policy.auto_allow` 名单里的工具可预批准放行（强制名单优先）。
- 多工具默认并行，写同一目标自动串行。
- 文件工具只认绝对路径、越界写入走人工审批、拒绝路径花招；超大输出自动落盘。
