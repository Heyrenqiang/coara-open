# 第 5 章 子智能体与委派

## 5.1 什么时候它会派分身

你说：「帮我把这三个模块的依赖关系都梳理一遍。」这种活一个人干要串行查三遍，它会选择派出三个**子智能体**（也叫分身）同时查，自己居中汇总。

子智能体是 Root 通过 `delegate` 工具创建的临时工作单元：同一进程里的轻量协程，有自己独立的对话上下文和受限的工具集，拿着 Root 写给它的任务书独立干活，干完把结果交回，用完即弃。它不是独立程序，也不会留在系统里。

适合派分身的场合：任务能拆开并行、需要独立忙活一阵、或者会弄脏主对话上下文。简单小活它不会派——吩咐分身的成本比自己做还高。

## 5.2 分身怎么分工

你能派的分身（用户可委派）：

| 分身 | 分工 | 能用什么 | 不能干什么 |
|------|------|----------|------------|
| **coaras** | 工程执行 / 只读摸底：写代码或并行查事实 | 与 Root 基本相同的工具集 | 再派分身；用 `orchestrator`、`ws`、`reminder`、`vault`、`plan_mode`（这些只在 Root 上注册） |
| **aide** | 资料调研与头脑风暴：后台查资料、发散提案 | 只读工具 + `orchestrator` | 改文件、跑命令、打扰你 |

另有**两个**系统专属分身，不接受你或 Root 主动委派，由系统在特定时机自己调度：`janitor`（工作空间管家：维护概况 + 记忆 + 过目消息）、`daily`（每日整理记录）。它们没有双向通道，只回最终结果。

选择时的直觉：

- 要并行**查**或**干活**、任务边界清晰 → coaras（只读时在任务书里写明禁止修改）。
- 想要后台资料调研或头脑风暴提案 → aide（必须后台运行，见 5.4）。
- 工作空间的定时巡检/维护不靠你派——配一个 cron 事件源（`kind: cron`）到点自动触发，事件落消息收件箱由管家 janitor 过目，见 [第 8 章](./08-事项与日程.md)。

以前有过 `explore` / `research` 分身，已移除——只读并行用 coaras；多源调研用 Root 激活 `research` 技能。

计划模式（plan_mode）下派生的分身**强制只读**：`write`/`edit`/`plan_mode` 在白名单里被硬剥离，任务书怎么写都改不了文件。

## 5.3 任务书怎么写

分身看不到你和 Root 的对话，`delegate` 的 `prompt` 参数就是它收到的**全部**任务信息，并且被它当作本任务的**最高约束**——它自己的角色规范之外，一切以任务书为准。

所以 Root 被教导：写任务书不能像下口令，得像师傅带徒弟——交待任务的同时，把方法和规矩也教给它。一份合格的任务书包含六样：

1. **任务目标**：做什么、为什么做（一句话背景）；
2. **范围**：涉及的绝对路径与模块，以及明确不碰的部分；
3. **方法指导**：建议的执行顺序、工具用法、易踩的坑；
4. **规则与禁止项**：本任务的硬约束（只读不改、不动无关代码等）；
5. **验收标准**：怎样算完成；
6. **回报格式**：最终回报必须包含的内容（结论、涉及的绝对路径、关键数据）。

这些约束不是固定模板，而是 Root 针对这个任务量身生成的。分身的角色设定和工具说明它自己知道，任务书不复述。

分身交回的只有最后那条消息（普通过程文字 Root 看不到），所以任务书里规定回报格式很重要。分身可在中途调 `report` 工具显式汇报里程碑消息，以 `<子智能体消息>` 注入父会话。

## 5.4 前台和后台有什么区别

`delegate` 有个 `background` 参数，两种模式差别很大：

**前台（默认）——并行加速**
调用后立即返回一个"已启动"的占位符，Root 不等结果，继续推进自己的活（理想情况下 Root 自己也承担一条分支）。但本轮**不会**在分身回来前结束：当 Root 没有更多事可做时，它会停在那里等首个前台分身完成，把结果纳入推理后才收尾。你按 Ctrl+C 会**强制**停掉未完成的前台分身、后台分身，以及正在跑的后台 bash 任务（`task`），不是软等它们自己收尾。

**后台（`background=true`）——辅助助手**
调用后立即返回一个任务编号，Root 完全不等待，本轮正常结束。分身干完后，结果摘要会自动注入后续的某一轮对话。后台分身用 `delegate(action="status"|"message"|"resume")` 查看/干预。aide 强制用这种模式。

两个后台特有的细节：

- **跨工作空间保护**：后台分身完成时如果你已经切到别的工作空间，结果不会注入新空间的对话（避免串台），只留在任务记录里；切回去后能查到。
- **痕迹擦除**：后台委派成功后，Root 历史里对应的调用痕迹会被清理，你回看对话时不会看到一堆"已启动后台任务"的占位。

## 5.5 有哪些硬上限

- 并发数量不设上限（前台 + 后台），可以同时委派多个子智能体并行。
- **每个分身最多 1500 轮工具迭代**，到顶强制收尾——防止任务书写得太开放导致分身无限跑下去。
- **分身不能再派分身**：它们身上根本没有 `delegate` 工具，递归从机制上不可能。
- **没有外层超时**：分身跑多久由任务本身决定（受 1500 轮上限约束），不会被通用的 60 秒工具超时截断。
- 分身与 Root 同进程、共享 LLM 配置；分身崩溃理论上可能波及 Root，这是轻量的代价。

## 5.6 aide为什么特殊

aide是后台的"资料调研与头脑风暴"分身：它拿到 Root **对话历史最近 50 条的副本**（其他分身只拿任务书），在后台围绕主对话的议题查资料、发散提案——把可能有价值的跟进方向和建议交回 Root。它的行动克制分两档：无事则静默；有线索则把建议交回 Root。

它必须后台运行。收官结果会作为后台完成通知回投你的会话：你正忙时进接续输入（当前回合下一迭代可见），空闲时直接进驻会话历史、不为此单独唤醒一轮对话。你收到后知道即可，无需回应、无需复述，后续对话需要时自然运用。

## 5.7 进阶：分身的档案与取消

每个分身从创建到结束都有档案：编号、类型、任务描述、对话历史、最终状态（`running_foreground` / `running_background` / `idle` / `failed` / `cancelled`）、结果预览，持久化在 `<coara_home>/workspaces/<id>/subagents/` 下。档案既用于状态查询，也是断点：被打断（`cancelled`/`failed`）的分身可用 `delegate(action="resume", task_id=…)` 从档案里的对话历史原地恢复续跑（不重发任务指令）。aide 例外：一次性任务，不支持 resume。

取消是强制级联的：你打断 Root（Ctrl+C / `/stop`），Root 立刻硬取消所有前台分身、后台分身和 bash 后台任务（子进程树终止），并清空待注入的结果队列；对话历史保留已产生的内容（未完成工具会收口为已取消）。单停某一个子智能体用 `delegate(action="stop")`；视频任务用 `media(action="cancel")`。

## 5.8 本章小结

- 子智能体是 Root 用 `delegate` 派的临时分身：独立上下文、受限工具、用完即弃。
- 可委派的分身两种：coaras 工程/只读并行、aide 资料调研与头脑风暴（后台）；janitor/daily 是系统专属，不接受主动委派。
- 任务书是分身收到的全部信息、也是它的最高约束：目标、范围、方法、规矩、验收、回报格式，六样俱全。
- 前台模式结果不自动汇合：LLM 调 `delegate(action="wait")` 一次等齐全部在跑的；收尾时仍有在跑的会收到一次系统提醒，可等或明确放弃（放弃后继续跑，结果稍后作为新消息到达）。后台模式完全不等，完成后注入后续轮次，并有跨工作空间保护。
- 硬上限：并发数量不设上限（前台+后台）、每个 1500 轮迭代、不能再委派、无外层超时。
