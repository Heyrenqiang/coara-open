# 第 7 章 工作空间与多工作空间

## 7.1 先从一个场景说起

你同时在弄三个项目：一个股票盯盘脚本（`stocks-watch`）、一个商店 App、还有本仓库本身。你对 coara 说：

> 把 stocks 和商店 App 都登记成工作空间，以后它们各自的事各自记

登记之后：每个空间有了自己的定时触发（cron 事件源）、自己的工作空间动态（动态）、自己的管家（janitor）。你在聊天里输入 `/ws switch stocks-watch`，整个会话就切到了那个空间——对话记录、待办、已激活的技能都是那个空间自己的；切回来，原来的对话原样还在。手机上看到商店 App 的空间冒出红点，点进去能看到"有 2 条新反馈"。

这就是多工作空间：coara 帮你同时照看多块"地盘"，互不串味。

## 7.2 工作空间是什么

**工作空间 = 磁盘上的一个目录 + 登记表里的一个短名**。比如目录 `D:\projects\stocks-watch`，登记名 `stocks-watch`。登记之后，这个目录就从不相关的文件夹变成 coara 管理的长期单位：能收外部事件、有动态流、能被管家 janitor 照看。

登记信息存在 `<coara_home>/registry/workspaces.yaml`，每条记录包含短名（name）、路径（path）、一句话简介（summary）等。

两个容易混淆的概念，一次说清：

- **工作空间目录**：你的项目文件夹，归你和 git 管；
- **运行时数据目录**：coara 为该空间产生的 trace、日志、子智能体记录等，放在 `<coara_home>/workspaces/<workspace_id>/` 下。`workspace_id` 由目录路径算出来——`{目录名}-{路径 SHA1 前 10 位}`，比如 `stocks-watch-2b4bd8d172`。同一路径永远算出同一个 id，所以数据总能对上号。

两者分开，是为了不让 coara 的运行数据污染你的 git 仓库。

## 7.3 怎么登记、切换、重命名、移除

三条入口语义对齐（**没有**旧的 `use`；会话切换一律叫 `switch`，设默认一律叫 `default`）：

| 做什么 | 离线 CLI | 聊天斜杠 | `ws` 工具 |
|--------|----------|----------|-----------|
| 列出 | `coara ws list` | `/ws` · `/ws list` | `action=list` |
| 登记 | `coara ws add <路径> --name <名>` | — | `action=add` |
| **切换当前会话** | attach 版 CLI 支持 `/ws switch <名>`（独立进程 `coara ws` 做不到） | `/ws switch <名>` | `action=switch` |
| **重命名**（路径不动） | `coara ws rename <旧> <新>` | `/ws rename <旧> <新>` | `action=rename` + `new_name` |
| **设启动默认** | `coara ws default <名>` | `/ws default <名>` · `/ws switch <名> --default` | — |
| 取消登记 | `coara ws remove <名>` | — | `action=remove` |

**登记**（命令行，一次性）：

```text
coara ws add D:\projects\stocks-watch --name stocks-watch --summary "股票盯盘"
```

**在会话里切换**（聊天中）：

```text
/ws                  " 列出所有工作空间（也可输入 /ws 后 ↑↓ 选空间回车切换）
/ws 2                " 按列表序号切换
/ws switch stocks-watch " 切过去
/ws switch stocks-watch --default  " 顺便设为启动默认
```

切换也可以在对话里让 Root 做：`ws(action="switch", name="stocks-watch")`。

**重命名**：只改登记名，路径与磁盘目录不动（动态目录、事件源定义会尽量跟着迁）。内部 `workspace_id` 不变。

```text
coara ws rename android-app coara-app-实验版
/ws rename android-app coara-app-实验版
ws(action="rename", name="android-app", new_name="coara-app-实验版")
```

勿用 remove+add 代替 rename——那样会换掉内部 id，动态与事件源容易断联。

**移除**：`coara ws remove stocks-watch` 只是取消登记，磁盘目录不动；加 `--delete-disk` 才会连目录一起删（不可逆）。

**注意**：`coara ws default <名>` 在独立进程里只写登记表「启动默认」标记后退出，**不会影响正在运行的 coara 会话**。要切换当前会话，用会话内的 `/ws switch`。

## 7.4 切换之后：每个空间各有一本账

切换工作空间不是改个路径那么简单。coara 为**每个**工作空间（含启动时所在的那个）维护对等的**独立会话容器**（WorkspaceSession）：独立的对话历史、独立的待办清单、独立的已激活技能、独立的会话编号。Root 只做进程宿主，不充当某个空间的对话 agent。

实际效果：

- 你在 A 空间聊到一半切去 B，A 的对话原封不动留在 A 的容器里；切回 A，接着聊；
- 切换后新产生的 trace、日志写到新空间的数据目录，旧的留在原地；
- 如果切换发生在回合中途：你手动切（/ws、Web、手机）不会打断 A 的回合——它继续跑完，输出带 `[A]` 空间名前缀照常显示；只有 LLM 自己调 `ws(switch)` 才结束当前轮，并把触发切换的那条输入及其后的切换尝试从源空间历史中清理。

会话状态会落盘（`<coara_home>/workspaces/<workspace_id>/session_state.json` 加对话记录），所以重启 coara 后切过去还能恢复。每个空间按自己的最后活动时间判定新鲜度（超时常量同 `session.idle_timeout_seconds`，默认 2 小时，0 表示禁用）：切入一个超过 2 小时没发过消息的空间会开新会话，并提示「新会话」；尚无真实对话的空会话同样提示「新会话」；有对话且未过期则提示「上次对话 HH:MM」（跨天带昨天/日期）。2 小时计时只在三端**发消息**时刷新，切换工作空间不会刷新。

全局服务（事件总线、调度器、工作流、宝箱、提醒、事件源）则始终只有一份，不随切换复制。

> **已知限制**：宝箱是全局共享的，切换工作空间时不会自动锁定。如果 A 空间的宝箱已解锁，切到 B 空间后 B 的 LLM 仍可读取 A 已解锁的私密内容，直到空闲超时自动关门。`/new` 新会话会强制锁定宝箱，但工作空间切换不走此路径。详见 [第 10 章 §已知限制](./10-宝箱.md) 和 [第 18 章 §18.10](./18-安全与治理.md)。

## 7.5 人不在场时的事，进"动态"

工作空间的动态（updates）是每个空间的工作空间动态：外部事件（App 反馈、文件落地）、定时触发的结果、工作流的终态，都按空间归档在这里，而不是直接打断你当前的对话。

- 命令行里：`/ws updates` 看当前空间的未读动态，`/ws updates list <空间名>` 看指定空间，`/ws updates read <编号>` 读全文，`/ws updates archive <编号>` 归档；
- 对话里 janitor 用 `review(action=list/read/…)` 做同样的事；
- 手机端靠 Matrix 同步未读数，空间有新动态就亮红点（详见 [第 9 章 事件源与工作空间动态](./09-事件源与工作空间动态.md)）。

动态存在 `<workspace>/.coara/inbox/`，和工作空间目录里的业务文件（比如 `feedback/inbox/`）是两回事：前者是 coara 管理的消息队列，后者是项目源码的一部分，由管家 janitor 或你决定怎么处理。

## 7.6 Root 和 janitor 怎么分工

多工作空间下有一条重要约定：

| 角色 | 干什么 | 不干什么 |
|------|--------|----------|
| **Root** | 和你对话、看各空间动态、决定派谁干活 | 不直接改动已登记空间的代码（可以 read/grep 快速看一眼） |
| **janitor** | 某个空间的管家：维护概况、写记忆、过目消息（勾掉噪音 / 呈阅要拍板的 / 能自己处理的处理掉） | 不面对用户，只向 Root 汇报；处置结果只写消息轨迹 |

`/ws switch stocks-watch` 是"你本人走过去"；配一个 cron 事件源让管家定时去那个空间巡检，是"派人过去"。前者改变你的会话，后者是系统到点自动派活，你的会话还在原地。

这条"Root 不动手写登记空间"的规矩是提示词级约定，不是代码硬封锁——靠它保证每个空间的上下文干净、改动可审计。

## 7.7 手机怎么知道你在看哪个空间

手机端（Matrix）与内核常驻进程（tray/daemon）之间用隐藏包同步空间状态：

- **内核托管模式（默认）**：Matrix 由常驻内核托管，和 Web/CLI 共享同一个内核 Root。你在任一端 `/ws switch`（CLI attach 支持；Web/手机用界面切），Root 切完会经事件总线立刻推 `[COARA_WORKSPACES]` / `[COARA_STATUS]` 隐藏包到 Matrix，手机 App 缓存这两个包来显示当前空间和空间列表。手机不读任何本地文件。
- **独立 bot 进程（`python -m src.matrix_client`）**：bot 有自己的 Root，和内核是两个进程。内核会把当前各端绑定写到 `<coara_home>/runtime/active.json`（工作空间路径、短名、进程号、会话编号等）；bot 启动时读它做一次绑定，之后每 10 秒重读一次跟随切换（跟随切换不会覆写 active.json）。coara 正常退出时会清理这个文件。

反向也成立：手机里切空间走的是同一条 `switch_workspace`，CLI / Web 靠事件总线同步跟上。注册表的增删改（add / remove / rename）同样会广播 `workspace_registry_changed` 事件，三端的工作空间列表都会即时刷新。

## 7.8 边界与限制

- 目录必须先登记，才有动态、事件源、管家这些完整能力；
- 同一台机器不要同时跑两个指向同一空间的 coara 进程，trace 和后台任务会打架；
- 移出登记表后，该空间的历史运行数据和动态不会自动删除；
- 切换工作空间必须在会话内做（`/ws switch` 或 `ws` 工具；attach 版 CLI 同样支持 `/ws switch`）；独立进程的 `coara ws default` 只设启动默认。

## 7.9 本章小结

- 工作空间 = 目录 + 登记短名；运行数据按 workspace_id（路径哈希）单独存放，不污染项目目录；
- `coara ws add` 登记；`/ws switch` 在会话内切换；`rename` 只改登记名；`coara ws default` 只设启动默认；每个空间有独立会话容器，切回即恢复；
- 动态是各空间的工作空间动态，未读数会同步到手机红点；
- Root 负责对话和编排，janitor 负责空间内照看；Root 不直接改登记空间的代码（约定）；
- 手机经 Matrix 隐藏包镜像当前空间；`runtime/active.json` 仅供独立 bot 进程启动绑定与周期跟随。
