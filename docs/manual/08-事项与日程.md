# 第 8 章 日程与事件源

## 8.1 先从一个场景说起

你对 coara 说：

> 给 stocks 空间加个日程：每天早上 8 点巡检一遍，有异常再叫我

几天后你又会发现另一种需求：

> 商店 App 的反馈一落地就让人去看看，别等我翻消息

这两件事都由**事件源**承接：挂在某个工作空间名下的触发配置。第一种用 `cron` 事件源按时间表触发，第二种用 `file_watch` / `webhook` 事件源按事件触发。事件内容**无条件**落该工作空间的**消息收件箱**，`salience` / `handle` 决定曝光与处置。

打个比方：工作空间是一家工厂，工作流是自动化流水线，事件源是**传感器与钟表**——"每天早上 8 点响一次"、"反馈口一有东西落下就响"。响完之后，挂住等你批示（park），或叫醒管家 janitor 先过目（handle: janitor）。

## 8.2 事件源和"提醒我"不是一回事

coara 里有两套容易混淆的调度：**事件源**面向工作空间，**提醒（reminder）**面向你本人。

- 事件源：`file_watch` / `interval_poll` / `webhook` / `cron`，事件落消息收件箱，可驱动工作流、可叫醒 janitor
- 提醒（reminder）：你口头说「20 分钟后叫我」，到点落一条 high 消息挂前台待处理，不跑任何 agent

## 8.3 四种触发钟

| kind | 机制 | 典型场景 |
|------|------|---------|
| `file_watch` | 监听目录（非递归，短防抖） | 反馈目录落文件即通知 |
| `interval_poll` | 定时扫目录文件名集合 | 文件事件不可靠时的兜底 |
| `webhook` | `POST /webhook/{id}` JSON | App / 后端 / 远程主动推 |
| `cron` | cron 表达式到点触发（Asia/Shanghai） | 每天 8 点巡检、每工作日拉行情 |

事件源定义存 `<workspace>/.coara/matters/definitions/*.yaml`，一个文件一个源。用 Root 工具 `event_source(action=add)` 创建（写操作走人工审批），或用聊天命令 `/events` 查看。

最小 cron 示例：

```yaml
id: stocks-daily
kind: cron
workspace: stocks-watch
cron: "0 8 * * 1-5"
message_template: |
  [定时巡检 — {{source_id}}]
  到点：{{details}}
  例行拉行情写 brief；无异常可忽略，需要决策的呈阅
```

## 8.4 事件落箱之后

1. 事件内容无条件写入该 ws 消息收件箱（事实记录，任何 salience/handle 都写）
2. 工作流 trigger 注册表命中该事件 → 直启 WDL（事件 payload 整体作为 inputs）
3. `handle: janitor` → 后台叫醒管家 janitor 过目：勾掉（dismiss）/ 呈阅（elevate）/ 自处理（resolve），理由写进消息处置轨迹
4. 挂住等你的消息（park）：`salience: high` 进前台待处理视图；其余只占红点

低价值事件建议配 `salience: low` 或 `ttl_seconds`（保质期）：过期未读会被纯规则过目自动勾掉，不打扰你。

## 8.5 消息与处置轨迹

每条消息带处置轨迹：`pending`（待过目）/ `elevated`（呈阅）/ `resolved`（已处置）/ `dismissed`（已勾掉），以及过目人、时间、备注。你在 Web 或手机上的**批示**就是一次 `resolved`；janitor 的勾掉/呈阅/自处理都会留下轨迹。消息页能看到完整流转：原始内容在上，处置时间线在下。

管理入口：`/ws updates [list|pending|read|dismiss|elevate|resolve|archive|mark_read|stats] [工作空间名]`。

## 8.6 与工作流的分工

- 事件源：**什么时候** + 曝光/处置（salience/handle/ttl）
- 工作流：**怎么转**（steps/edges、inputs/outputs）
- janitor：**谁看着办**（过目、决策提示、处理）

事件源不是第二套工作流语言：业务载荷（payload）可以长得很不一样，用 `event_type` + `message_template` 约定表达即可。
