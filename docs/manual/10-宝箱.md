# 第 10 章 宝箱

## 10.1 宝箱是什么

你迟早会想让 coara 帮你处理一些不方便明说的东西：身份证号、服务器密码、证书文件、简历、合同扫描件。这些内容直接丢进对话历史不太妥当——它们会留在消息记录里，也会随着每次 LLM 请求发给模型服务商。

**宝箱**就是为这类东西准备的加密抽屉：

- 锁定时，里面的每个文件都是独立加密的密文，谁也读不了
- 你用主密码开门后，它变成一个普通文件夹，coara 用平时那套文件工具在里面读写
- 用完关门（或它自己关门），明文被擦掉，只留下密文

比如你说：

> 把我的护照扫描件收进宝箱，顺便把里面登记的证件号读出来核对一下

coara 会调用 `vault` 工具开门——这时候**你屏幕上会弹出密码输入**，输入正确后它才开始干活。

## 10.2 开门、干活、关门

一次典型的宝箱操作长这样：

1. coara 调用 `vault(action=open)`
2. 系统向你发起对话的那一端弹出密码框（详见下一节）
3. 密码正确 → 宝箱打开，coara 拿到里面 `open/` 目录的路径，继续完成你原来的请求
4. 它在 `open/` 里用普通的 `read`/`write`/`edit`/`glob`/`shell` 操作，和普通文件夹没有任何区别
5. 从最后一次碰 `open/` 算起约 **2 分钟**没再操作 → 自动关门：重新加密、擦掉明文

几点说明：

- **界外对话不续期**。只有真正访问 `open/` 里的路径才算活动；你跟它聊别的事情不会让宝箱保持打开
- 想立刻关门，直接说"关上宝箱"（它会调用 `vault(action=close)`）
- **新会话自动上锁**。`/new` 或任何原因产生新会话时，系统会把 `open/` 明文封存回密文并清除内存密钥——新会话不会默认继承上一会话的解密状态，再操作需要重新输密码
- 宝箱的绝对路径只有 coara 内部可见，它被明确要求**不要在回复里透露该路径**；你也无需关心它在哪里

## 10.3 密码在哪输入

密码框只出现在**发起当前对话的那一端**，不跨端同步：

| 发起端 | 密码输入方式 |
|--------|--------------|
| CLI | 终端弹出密码输入，不回显 |
| Web UI | 浏览器弹出「宝箱解锁 / 创建宝箱」弹窗 |
| Matrix / coara App | 聊天里出现一张内联解锁卡片，输入后卡片变成掩码 + ✓ 的静态展示 |

系统按当前回合的交互通道判断发起端，只向该端推送弹窗。密码走系统侧通道进入 coara 进程，**不会出现在 AI 对话上下文里**——模型永远看不到你的密码，只知道"门开了"。

两个边界情况：

- 密码框最多等 **60 秒**。超时后工具调用返回"解锁超时"，coara 会告诉你需要重试
- 主动点取消会立即结束等待，coara 收到"用户取消了宝箱解锁"，通常会停手或问你怎么办

> 进阶：在个人机器上可以设置环境变量 `COARA_VAULT_PASSWORD` 让可信进程自动解锁，免去输密码。共享设备上不建议这么做。

## 10.4 安全边界

宝箱的防护是三层叠加的：

1. **密码旁路**：密码经 CLI 密码框、Web `vault_reply`、Matrix `[COARA_VAULT]` 卡片进入进程，全程不进 LLM 上下文
2. **锁定时硬拒绝**：宝箱处于锁定状态时，任何工具（`read`、`shell` 都不行）都无法触碰已封存的宝箱路径，访问会被直接拦截
3. **关门即擦除**：关门时 `open/` 明文被清除，磁盘上只剩密文；内存中的密钥也被丢弃

加密本身使用 scrypt（N=2^17，OWASP 推荐值）派生密钥 + AES-GCM，元数据文件只存盐值、校验值和 KDF 参数，不存密码。早期宝箱的 meta 没有 KDF 参数（按旧值 N=2^14 派生），首次成功解锁后会自动重新加密升级到当前参数，密码不变、无感知。

还有一个设计细节：`vault` 工具的开门弹窗**不经过工具审批**，密码框是独立通道，和"是否允许执行某工具"的审批弹窗互不相干。

### 已知限制

如实说明，宝箱在安全方面有以下已知限制（详见 [第 18 章 §18.10](./18-安全与治理.md)）：

- **Matrix 通道明文传输**：手机 App 解锁时，密码以明文拼入 Matrix 消息体发送，被服务端 SQLite 永久保存。密码不进 LLM 上下文，但能读房间事件的人可看到明文。LAN 可信环境下风险较低，修复需跨端设计 challenge-response 协议（已立项）
- **切换工作空间不锁箱**：宝箱是全局共享的，从工作空间 A 切到 B 时不会自动锁定。B 的 LLM 可用普通文件工具读取 A 已解锁的私密内容，直到空闲超时自动关门。`/new` 新会话会强制锁定，但工作空间切换不走此路径

## 10.5 自己动手：宝箱 CLI

不想经过 AI 对话，也可以直接在终端管理宝箱。以下子命令全部可用：

| 命令 | 作用 |
|------|------|
| `coara vault status` | 查看初始化/锁定状态和已封存文件数 |
| `coara vault init` | 首次设置主密码（≥8 位且字母数字混合） |
| `coara vault unlock` | 验证密码（仅当前进程有效） |
| `coara vault lock` | 本进程上锁（清除内存密钥） |
| `coara vault list` | 列出 `open/` 里的文件（会提示输密码） |
| `coara vault read <路径>` | 读取 `open/` 下的文本 |
| `coara vault write <路径>` | 向 `open/` 写入文本 |
| `coara vault import <文件>` | 把磁盘上的文件复制进宝箱 |
| `coara vault passwd` | 修改主密码（旧密码验证，全部密文重新加密） |

两点要记住：

- **离线 CLI 按进程生效**。`coara vault unlock` 解锁的会话随命令进程退出就结束；`list`/`read`/`write`/`import` 会在当前命令里提示输密码，一气呵成。加 `--no-prompt` 可改为要求 `COARA_VAULT_PASSWORD`（适合脚本/CI）
- **密码管理两个入口**：PC 终端（`init`/`passwd`）或 WebUI 配置页「宝箱」卡片（设置/修改/重置，开关立即生效）；手机和 Matrix 端只能解锁

聊天里也有 `/vault` 斜杠命令可以查看状态；AI 侧则只有 `vault(action=open|close|status)` 三个动作（`unlock`/`lock` 是别名）。

## 10.6 进阶：磁盘布局

宝箱数据放在 coara Home 的用户目录下（`<coara_home>/users/default/assets/vault/`）：

```text
assets/vault/
  vault.meta.json        # 盐值 + 校验值，不含密码
  sealed/<uuid>.cvault   # 锁定时：每个文件一份独立密文
  open/**                # 仅开门后存在的明文工作树，关门时擦除
```

修改密码（`coara vault passwd`）会先把 `sealed/` 快照到 `.rekey_backup`，全部重新加密成功后才删除备份，失败则回滚。

## 10.7 本章小结

- 宝箱是加密抽屉：锁定时全是密文，开门后是 `open/` 普通文件夹，coara 用日常文件工具操作
- 开门靠 `vault(action=open)` + 密码弹窗；约 2 分钟不碰自动关门；`/new` 新会话强制上锁
- 密码只在发起端输入（CLI / Web / 手机），60 秒超时，全程不进 AI 对话
- 锁定时工具碰不到宝箱路径，关门即擦除明文
- 终端可用 `coara vault` 子命令手动管理；设密码、改密码仅限 PC
- 已知限制：Matrix 传输为明文、切换工作空间不锁箱（详见 §10.4 已知限制）
