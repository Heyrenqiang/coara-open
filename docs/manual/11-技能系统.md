# 第 11 章 技能系统

## 11.1 先从一个场景说起

你说："帮我写一份两万字的项目白皮书。"

这是一个有套路的任务：直接让模型一口气写完，质量多半不行。技能的思路就是给模型一份"长文档写作说明书"：先列大纲、分章写入、最后合并、统一润色，让它照这个套路一步步做，而不是硬写。

**技能（skill）就是一份写给大模型看的领域操作手册**——纯文本，不是代码。它不注册新函数、不扩展工具列表，只是告诉模型"这类任务应该按什么步骤、什么标准来做"。具体能不能做，仍然取决于现有的工具和模型自己的能力。

## 11.2 为什么手册是文本而不是插件

传统软件的技能往往意味着动态加载代码模块，对一个人智能体来说问题不少：执行外部代码有安全风险、版本耦合难升级、出错难排查、用户不会写代码就没法扩展。

把手册设计成纯文本后：加一个技能 = 建一个目录写一份 Markdown；系统对技能只有"读"没有"执行"；不会写代码也能自己动手改。

## 11.3 一份技能长什么样

每个技能是一个目录，里面必有一个 `SKILL.md`：

```text
my-skill/
├── SKILL.md        # 必需：元数据 + 正文
├── references/     # 可选：参考文件（如 WDL 规范）
└── scripts/        # 可选：辅助脚本
```

`SKILL.md` 分两段：

1. **YAML 头**（三条横线包住）：`name` 和 `description`，用于列表展示和挑选；
2. **Markdown 正文**：真正给模型读的指南。

## 11.4 技能从哪儿来

启动时按以下顺序发现技能，**同名后加载的覆盖先加载的**：

| 顺序 | 位置 | 说明 |
|------|------|------|
| 1 | 仓库内置 `skills/` | 随系统分发 |
| 2 | `<coara_home>/users/default/skills/` | 你的个人技能，所有空间可见 |
| 3 | `<工作空间>/.coara/skills/` | 该空间专属；空间受信任才加载 |
| 4 | 启动时额外传入的路径 | 临时扩展 |

**增删改都在磁盘上做**：新建目录加 `SKILL.md` 就是加技能，删目录就是删技能。没有 add/remove 命令。

注意一个坑：改完 `SKILL.md`，当前会话里已激活的旧版本**不会自动刷新**——它已经躺在对话历史里了。要让模型看到新版，输入 `/new` 开新会话再重新激活。

## 11.5 怎么用：search 和 activate

`skill` 是 Root 专属工具（分身没有），两个动作：

| 动作 | 干什么 |
|------|--------|
| `search` | 按关键词查全部技能（含挂起），返回候选名+一句话描述；query 留空返回全量目录 |
| `activate` | 把指定技能的完整正文加载进当前对话 |

典型流程：你提出领域任务 → Root 判断需要技能 → `search` 看一眼有哪些 → 挑最匹配的 `activate` → 正文进入对话历史 → 模型照着手册执行。

列表里可能出现两个标签：

- `[default]`：`config.yaml` 的 `skills.default_include` 配置的推荐标记，只是"建议常用"的记号，**不会**自动加载；
- `[activated]`：本会话已经激活过，正文已在历史中。

激活后，技能正文包在 `<activated_skill>` 标签里作为工具结果进入对话历史，之后每一轮对话模型都看得到。这也意味着**没有"取消激活"**——想让它忘掉旧手册，只能 `/new` 开新局。

为什么不把技能列表预先写进系统提示词？因为系统提示词保持静态才能命中 LLM 的提示词缓存；技能按需加载进历史，既灵活又不破坏缓存。

## 11.6 内置技能一览

| 技能 | 一句话 |
|------|--------|
| `research` | 多源调研：网络搜索与本地证据交叉验证，产出可核查的报告 |
| `event-source` | 事件源设计：教 Root 写事件源 YAML 并接线 |
| `工作空间管理` | coara Home 侧配置指引：事件源 YAML、AGENTS 模板、体检清单 |
| `skill-creator` | 元技能：教模型帮你编写、审查、改进新的 `SKILL.md` |

（`workflow` 技能已退役为挂起工具 orchestrator；`long-document` / `PPT` / `frontend-design` 已于 2026-08-19 裁撤。图/视频生成由内置 `media` 工具承担，原 `agnes` 技能已移除；Agnes 文本聊天仍可用 `agnes` provider）

想自己造技能，最省事的方式就是激活 `skill-creator`，让它带你写。

## 11.7 边界与常见误解

- 技能不扩展工具集，只影响模型的思路；
- 只有 Root 能激活技能，分身不行；
- 已激活技能留在历史中直到 `/new`，没有卸载动作；
- 工作空间级技能只在空间受信任时加载（防止打开陌生目录就执行来路不明的指令）；
- 误解："`[default]` 的技能自动生效"——它只是推荐标记，不注入历史。

## 11.8 本章小结

- 技能是写给大模型的领域操作手册，纯文本，不是插件；
- 一个技能 = 一个目录 + 一份 `SKILL.md`（YAML 头 + Markdown 正文）；
- 发现顺序：内置 → 用户级 → 工作空间级（需信任）→ 额外路径，同名覆盖；
- 用法：`skill(action="search")` 挑选 → `skill(action="activate")` 加载；正文进对话历史，`/new` 才能翻篇；
- 增删技能只在磁盘上操作；`skill-creator` 能帮你写新技能。
