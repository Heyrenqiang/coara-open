# 第 12 章 待办系统

## 12.1 先从一个场景说起

你交代了一件不小的活："把这三个模块的重构做完，跑通测试，再更新文档。"

如果没有待办，模型容易做到一半忘了后面的事。有了待办，它会先给自己列一张单子：

```text
[ ] 1 重构模块 A
[ ] 2 重构模块 B
[ ] 3 重构模块 C
[ ] 4 跑通测试
[ ] 5 更新文档
```

然后它开始干活：把第 1 项标成"进行中"，做完就整表更新勾掉，开始第 2 项……进度写在工具回执里（命令行没有单独的待办面板）。全部做完，它才把最终总结交给你。

**待办（todo）就是它的自我任务清单**——它自己列、自己勾，框架只负责存起来、在回合结束时催促。

## 12.2 它和工作空间定时触发不是一回事

名字像，定位完全不同：

| | 待办（todo） | cron 事件源 |
|--|-------------|-------------|
| 一句话 | 当前这一局对话的内部工单 | 工作空间的定时触发钟 |
| 谁列的 | 模型自己 | 你（或管理流程） |
| 怎么触发 | 干活过程中随手建立 | cron 表达式到点触发 |
| 谁执行 | 模型本人逐项推进 | 事件落消息收件箱（可叫醒管家 janitor 或直启工作流） |
| 活多久 | 随会话结束失效 | 长期存在 |

待办存在 `<工作空间>/.coara/todos/<会话编号>.json`，一个会话一份。落盘的好处是：崩溃重启能恢复进度；CLI、网页、手机看到的是同一份。

## 12.3 模型怎么操作这张单子

通过 `todo` 工具，两个动作：`read` 读全表；`update` 用完整步骤数组**整表覆盖**（空数组 = 清空）。

**`update`（整表覆盖）**——每次提交当前完整清单。新建、改状态、增删步骤、清空，都是同一次 `update`。内容（content）必填；状态省略默认 pending。可选 `explanation` 写改计划理由。每次必填 `description`（命令行 ✓ 行展示）。

每项字段：内容（content）、状态（status）、可选编号（id）、优先级（priority）、备注（notes）。编号可省略（同文案会续用旧编号）。**priority 只影响展示排序**，不决定执行顺序。

## 12.4 四种状态和「单焦点」规矩

状态机：

| 状态 | 含义 |
|------|------|
| `pending` | 待处理 |
| `in_progress` | 正在做 |
| `completed` | 做完了 |
| `failed` | 失败了 |

正常的推进是 `pending → in_progress → completed`。不合常规的跳变不会报错，只会记警告日志。

**单焦点**：全表同时最多一项 `in_progress`（硬校验）。做完立刻整表把该项标 completed，并把下一项标 in_progress。

## 12.5 待办怎么推着它把活干完

待办不是摆设，它深度参与回合的结束判定：

```text
模型这一轮没有再调用工具
  → 还有待办没完成？
      ├─ 有 → 这轮回复够不够 400 字？
      │        ├─ 够 → 视为实质性交付，先交给你（避免"不做完不许说话"的僵局）
      │        └─ 不够 → 继续干活，不许结束
      └─ 没有 → 正常结束
```

也就是说：列了单子就必须推进，不能只说不做；但如果它已经写出了足够长的实质内容（比如阶段性总结），允许先交付给你。

## 12.6 你在界面上看到什么

命令行**不单独展示**待办清单（没有 sticky 面板）。进度由模型在对话里概括；需要核对清单时可让它 `todo(read)`，或看工具回执。

模型每次 `update` 后拿到的回执是：一份紧凑清单 + 系统提醒（不要复述整表、完成项点名下一步）。这就是它不会忘掉进度的原因。

## 12.7 边界与常见误解

- 待办只活在当前会话：`/new`、切换工作空间后就是另一份；
- 写盘失败会明确报错给模型（不会假装成功）；
- 没有审批、没有历史版本——它是轻量机制；
- 不会自动完成：某项做完必须由模型显式 `update` 标记；
- 误解一："待办会按优先级自动执行"——priority 只管排序；
- 误解二："可以多项同时进行中"——同时只能一项 in_progress。

## 12.8 本章小结

- 待办是会话级的自我任务清单：`todo(action=read/update)`，`update` 整表覆盖，按会话存盘；
- 四态状态机；同时最多一项进行中；
- 有待办未完成就不许轻易收工，除非本轮已交付 400 字以上的实质内容；
- CLI 不单独渲染清单，工具回执即展示通道。
