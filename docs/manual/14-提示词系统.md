# 第 14 章 提示词系统

## 14.1 这一章回答什么

你可能注意过：coara 说话有固定的一套风格——中文回复、代码和路径保留英文、改文件前喜欢先读一遍、遇到大活会先列待办。这些"性格"从哪来？为什么它记得住当前目录，却不会把时间写进自己的"本能"里？这一章解释它发给大模型的提示词是怎么组装出来的。

这章比其他章略技术，但我们会先讲价值：理解了这套机制，你就知道**改哪里能影响它的行为，以及为什么有些信息它"看得见"却不在系统提示词里**。

## 14.2 系统提示词从哪来：一份配置加一份正文

每次请求大模型，提示词由三部分组成：**系统提示词**（它是谁、守什么规矩）、**工具定义**（它有哪些工具、怎么用）、**消息历史**（对话至今的全部内容）。

系统提示词不是一大坨写死的字符串，而是每个智能体一对文件配对生成的：

```text
src/coara/prompts/agents/
  root.yaml  + root.md    # Root：你的对话对象
  coaras.yaml  + coaras.md
  aide.yaml  + aide.md    # aide：资料调研与头脑风暴（后台）
  janitor.yaml + janitor.md   # 管家：概况维护 + 记忆 + 消息过目（系统专属）
  daily.yaml   + daily.md     # 每日整理记录（系统专属）
```

分工很直白：

- **YAML 是配置**：名称、描述、工具白名单（`tools.include` / `tools.exclude`）、继承关系、正文里要替换的变量
- **Markdown 是正文**：给模型看的自然语言行为规范——角色定位、什么时候直接动手、什么时候派分身、输出约定

所以你看到的"性格差异"，本质是这两个文件的差异：Root 的正文教它做任务编排，coaras 的正文教它交付子任务（含只读摸底时的探索打法）；再配上 YAML 里不同的工具白名单（aide/janitor 相对收紧），就从"说法"和"能力"两头锁死了行为边界。

工具定义不走系统提示词文本——每个工具类的 `description` 写在工具自己的代码里，运行时通过 function calling 的工具通道单独发给模型。工具说明和工具实现放在同一个文件里，不会出现"文档说要这样、代码却那样"的脱节。

## 14.3 为什么不把所有信息都写进系统提示词

假设系统提示词每轮都带上当前时间、待办清单、刚完成的后台任务——看起来信息很全，但代价是：**模型服务商的提示词缓存会全部失效**。

缓存的原理是：请求前缀逐字节一致时，服务商可以复用上次算过的部分，显著降低延迟和费用。系统提示词一旦有任何一个字变化，缓存就从头作废。所以 coara 定了一条铁律：

> **系统提示词保持静态，动态信息一律走消息层注入。**

系统提示词里允许出现的运行时变量只有两类：

- `${COARA_WORK_DIR}`：当前工作目录的绝对路径
- YAML `system_prompt_args` 里显式声明的键（正文模板里的占位符）

装好之后，这份系统提示词在整个会话内一个字都不变。操作系统、Git 状态、时间感、待办、技能正文、后台任务结果……全部以**消息**的形式进入历史，追加在末尾，不碰前缀。

这条铁律有一个用户可感知的推论：**想让模型"忘掉"某条注入过的信息，没有办法从历史里删掉它**。想清除已激活的技能或旧提醒，只能 `/new` 开新会话。这与 [第 13 章 上下文窗口与压缩](./13-上下文窗口与压缩.md) 的压缩设计是同源的。

## 14.4 动态注入都有什么

动态信息以不同身份进入消息历史，各管一段：

**首轮环境种子**
会话第一轮，系统伪造一条用户消息，告诉模型当前环境：地点（可在 `config.yaml` 配置）、操作系统、工作目录、Git 状态快照等。模型因此"知道自己在哪"，而系统提示词保持干净。

**标签化的提醒消息**
后续每轮，各种运行时信息包着中文 XML 标签进来。标签区分语义强弱：

| 标签 | 语义 | 典型场景 |
|------|------|----------|
| `<系统消息>` | 信息性上下文，供参考 | 环境种子、后台任务完成通知、工具异常包装 |
| `<系统提醒>` | 权威指令，应当遵守 | 工作空间动态指引、shell 输出命中哨兵模式 |
| `<事件提醒>` | 外部事件入站，先报告再行动 | 事件源 / webhook 触发的自动运行 |
| `<工作空间消息>` | 你引用的工作空间动态 | 手机端引用某条动态发问（引用协议） |
| `<引用内容>` | 你引用的上文片段 | 客户端拼入的引用 |
| `<手机消息>` | 消息来自手机端 | Matrix / 手机端发来的消息 |
| `<web消息>` | 消息来自网页端 | Web 端发来的消息 |
| `<接续输入>` | 回合进行中你又补了一句 | 它干活时你追加的输入 |
| `<state_snapshot>` | 压缩摘要 | 旧历史被压缩后的替代表示 |

来源标签 `<手机消息>` / `<web消息>` 只在注入模型上下文时按来源现包；CLI 本地输入不加标签（三端同源同用户），落带前剥回裸文本，与端上显示无关。

**技能正文**
技能（见 [第 11 章 技能系统](./11-技能系统.md)）激活时，完整 SKILL.md 作为消息注入历史——系统提示词里**不**预置技能清单，它想知道有什么技能得自己调 `skill(action="search")`。技能因此是"按需加载的说明书"，而不是常驻指令。

**工具结果**
工具执行的返回内容本身就是消息。框架会做一些包装：工具报错或输出为空时包一层 `<系统消息>` 说明，帮助模型正确理解失败语义。

## 14.5 计划模式：另一种提示词约束

复杂任务中，模型可以自己进入**计划模式**：调用 `plan_mode(action="enter")` 后，工具白名单收缩为只读 + 规划类（`read`、`grep`、`glob`、`web_search`、`web_fetch`、`todo`、`delegate`），外加只能写计划文件的 `write`/`edit`——试图改工作空间文件会被拦下并提示"先提交计划审批"。

它调研、把方案写进计划文件，然后 `plan_mode(action="submit")` 提交给你审批；你确认后恢复正常工具集再动手。你在 CLI 里按 Shift+Tab 也能触发。这是"提示词引导 + 工具白名单硬约束"配合的典型例子：提示词告诉它什么时候该规划，白名单保证规划期间它真的动不了文件。

## 14.6 进阶：加载机制

给想改提示词的读者。

YAML 加载器（`src/prompt/yaml_loader.py`）支持三种组装机制：

- **`extends`**：引用一个或多个共享模块文件，把内容拼到正文前面。路径先相对 YAML 所在目录解析，再相对提示词根目录
- **`{{INCLUDE:path}}`**：在正文任意位置内联嵌入另一个文件
- **`system_prompt_args`**：声明键值对，替换正文里的 `${键名}` 占位符（大小写不敏感）

加载产物交给 `PromptBuilder`（`src/prompt/builder.py`）做最后的运行时变量替换（`${COARA_WORK_DIR}` + `system_prompt_args`），结果作为系统提示词固定下来。

几点边界：

- 内置智能体的提示词路径固定，运行时不能从外部目录加载新 agent 提示词
- 工作目录变化不会改写已加载的系统提示词，切换工作空间后新会话才重新装配
- 子智能体与 Root 共用同一套 YAML-first 机制，能力差异由 YAML 白名单 + 运行时注册条件（如 `delegate_depth`）共同保证

## 14.7 本章小结

- 系统提示词 = YAML（配置）+ Markdown（正文）配对装配；Root 与各分身各有一对（`root`/`coaras`/`aide`，另有系统专属的 `janitor`/`daily`），行为差异由此而来
- 工具描述写在工具自己的代码里，经工具定义通道发给模型，不进系统提示词文本
- 铁律：系统提示词静态，动态信息走消息层注入——这是提示词缓存命中率的前提
- 动态注入四类：首轮环境种子、标签化提醒消息、技能正文、包装后的工具结果
- 计划模式 = 提示词引导 + 工具白名单收缩，规划期间只能写计划文件
- 想忽略已注入的信息（技能、提醒）只能 `/new`；想改行为，从对应 agent 的 yaml/md 入手
