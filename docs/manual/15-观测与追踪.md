# 第 15 章 观测与追踪

## 15.1 出了问题先去哪看

| 问题类型 | 去哪里 |
|----------|--------|
| **过程**（刚才调了哪些工具） | Web 右侧「工具活动」侧栏，或 CLI 输入框上方动态区；完整事件在 `traces/trace_events.jsonl` |
| **错误**（工具失败、调用被拒） | `<工作空间>/.coara/logs/errors.jsonl` |
| **成本**（用了多少 token） | Web `/usage`，或 `coara usage summary` / 聊天 `/usage` |

没有单独的 Web「Trace 复盘页」。结构化事件只落盘一份（TraceStore），界面按需取用。

## 15.2 Trace：每个关键动作一条记录

执行路径由模型临时决定，没有写死的流程可翻。**Trace** 就是为此准备的结构化事件流：时间、类型、参与者、详情。

典型类别：

| 类别 | 例子 |
|------|------|
| 会话与调用 | `turn_start` / `turn_end`、`llm_turn_start`、`llm_turn_complete` |
| 工具 | `tool_call`、`tool_result`、`tool_complete` |
| 子智能体 | `subagent_start`、`subagent_complete`、`background_task_complete` |
| 审批 / 异常 | `turn_interrupted`、`context_compressed` |

用户打断（Ctrl+C）结束当前回合并保留对话历史；**已写入的 trace 不回滚**。

## 15.3 落盘在哪（只这一套）

| 文件 | 用途 |
|------|------|
| `trace_events.jsonl` | 全部追踪事件（主数据源；超 50MB 轮转） |
| `trace_details/` | 过大 payload 外置 JSON（约 5000 个软上限） |
| `dashboard_runtime.json` | 运行时心跳快照（模型 / running 等） |

路径：

- 有 coara Home：`{coara_home}/workspaces/{工作空间ID}/traces/`
- 无全局 Home：`<工作空间>/.coara/data/`

**已停用**：`activity/activity_events.jsonl`（曾与 Trace 双写）。启动时会删除遗留的 `activity/` 目录。CLI 动态区只用内存投影，不写盘。

四类记录不要混：

| 类型 | 路径 | 用途 |
|------|------|------|
| Trace | `…/traces/trace_events.jsonl` | 结构化过程事件 |
| Log | `…/logs/coara.log` | 人读文本日志 |
| 错误 | `{workspace}/.coara/logs/errors.jsonl` | 仅错误 |
| 用量 | `…/usage/events.jsonl` | token / 工具次数 |

### 日志级别（对话屏 vs 文件）

交互终端默认 **控制台 `WARNING`、文件 `INFO`**：

| 级别 | 典型用途 | 默认是否上屏 |
|------|----------|--------------|
| DEBUG | 开发探针；`COARA_DEBUG=1` 才在控制台打完整堆栈 | 否 |
| INFO | 可自动恢复的痕迹（如 LLM 瞬时网络重试、流式降级） | 否（只进 `coara.log`） |
| WARNING | 需留意但仍继续 | 是 |
| ERROR | 调用失败 | 是 |

排查瞬时重试等问题：看 `{coara_home}/workspaces/…/logs/coara.log`（或工作空间 `.coara/logs/coara.log`），不必开调试模式。

## 15.4 界面怎么用 Trace

**Web**

- 聊天页：对话气泡（`chat_chunk` 等）
- 各页右侧：**工具活动**侧栏（最近主会话工具调用；连接时从 `trace_events.jsonl` 轻量补给）
- `/usage`：用量看板（读 `usage/events.jsonl`，不是 Trace）

WebSocket 把相关事件每 100ms 打成 `trace_batch` 推送；心跳每 5s，只带轻量 runtime。

**CLI**

- 动态区：进行中的工具 / 子智能体
- 滚动历史：关键完成摘要

**aide** 子智能体：事件照常落盘；CLI 动态区与滚动历史不显示（后台运行）。

## 15.5 事件总线 vs 调度器

Trace 走 **EventBus**（发后即忘 → TraceStore / CLI / Web 推送）。需要 Root 读进对话并可能回复的通知走 **UnifiedScheduler**。后台任务完成按**发起会话**回注，不因切工作空间串台。

## 15.6 本章小结

- 过程：侧栏 / CLI 动态区；完整复盘看 `trace_events.jsonl`
- 错误：`.coara/logs/errors.jsonl`；成本：用量页或 `coara usage`
- 无 Web Trace 页；无 `activity/` 双写
- 打断保留对话与已落盘 trace
