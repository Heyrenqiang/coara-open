# 第 16 章 CLI 与 Web UI

## 16.1 一个内核，三个端

你和 coara 打交道的地方有三类：**CLI**（终端里的交互对话）、**Web UI**（浏览器里的可视化界面）、**手机 App**（经 Matrix 协议）。它们不是三个系统——背后是同一个**常驻内核**、同一份模型上下文、同一套工作空间。**三端视图独立**：CLI、Web、手机各持自己的"当前工作空间视图"（view），互不镜像、互不拖拽；内核没有特权的「全局前台」，「前台」只是某一端当前盯着的空间。**输出归属 = 最近一次注入端**：一个回合由哪一端发起，最终答复就显示在哪一端——CLI 会带 `[Web]` / `[Matrix]` 前缀显示它端回合的收尾答复方便盯场，Web 只显示本端聊的内容。**同空间共看时模型一致**：任一端 `/model`，共看该空间的其它端状态栏/顶栏立刻跟上。

这一章回答：两端各自怎么启动、CLI 里有哪些命令可用、Web 界面能做什么。

## 16.2 启动方式

```bash
coara          # 确保内核常驻，本终端作为 CLI 端 attach 接入对话
coara tray     # 启动系统托盘常驻内核（右键：开 Web / 手机二维码 / 退出）
coara daemon   # 无头常驻内核（无 pystray 时 tray 的退化形态，等同后台运行）
coara attach <空间名>   # 外挂 CLI：另开终端接入指定工作空间
```

裸 `coara` 只做一件事：保证内核在跑（没有就先拉一个 `tray` / `daemon`），然后把自己 attach 上去。终端只是端——关掉窗口内核照常运行，Web / 手机不受影响；再开终端输入 `coara` 接的还是同一个内核。

内核（tray / daemon）启动时托管 Web 与 Matrix：Web 服务默认 8080 端口（`COARA_WEB_PORT` 可改），gomatrix 由 coara 自动拉起（`matrix.host_enabled` 默认开）。Matrix 没配置或拉不起来会安静跳过，不影响其它端。

常用启动选项（`coara` 与 `coara tray` / `coara daemon` 通用）：

| 选项 | 作用 |
|------|------|
| `--workspace <目录>` | 指定工作空间目录（默认当前目录） |
| `--workspace-alias <名>` | 激活已登记的工作空间别名 |
| `-p` / `--provider`、`-m` / `--model` | 指定本次使用的 LLM 提供方和模型 |

## 16.3 CLI 里怎么操作

输入框由 prompt_toolkit 驱动，带补全和历史：输入 `/` 提示斜杠命令，输入 `@` 补全**服务台**名（如 `@daily`、`@配置`），把整段消息投到对应服务台会话（不换当前工作空间视图）。**仅 CLI（attach）**；Web / 手机把 `@…` 当普通文本。

几个高频快捷键：

| 快捷键 | 作用 |
|--------|------|
| Ctrl+C | 输入框有内容时先清空；空闲且无输入时退出；运行中无输入时打断当前回合（保留本轮已写入的对话历史；磁盘副作用保留） |
| Ctrl+B | 退后台：本窗口 CLI 退出，内核继续常驻（Web / 手机不受影响，可关窗口） |
| Shift+Enter | 输入换行（仅支持 kitty 键盘协议的终端；conhost 用 Ctrl+Enter） |
| Ctrl+U | 清空输入 |
| Ctrl+V / Alt+V | 粘贴文字 / 粘贴剪贴板图片 |
| Shift+Tab | 切换计划模式 |
| Tab | 补全 |

两个行为细节：

- **运行中再输入会排队**。它干活时你发的消息不会丢，会作为"接续输入"在当前回合后处理，输入框上方有排队提示。例外是少数只读 / 纯 UI 的斜杠命令（`/help` `/status` `/tools` `/events` `/login` `/vault` `/ws` `/report` `/message` `/model` `/log` `/qrcode`），运行中立刻执行，不排队（白名单见 `src/coara/commands/registry.py` 的 `RUN_WHILE_BUSY`）
- **会话历史跨重启保留**。每轮结束与退出时，完整 `message_history` 以事件形式追加到 `<coara_home>/workspaces/<id>/session_events.jsonl`（录像带，全端冷备 / 审计，含工具调用与接续输入）。`/new` 换新 session_id，新会话的事件从头积累（旧会话事件保留可审计）。**注意 Web 聊天区不读录像带**——它读的是服务端视图存储（见 16.6），录像带只是冷备

## 16.4 斜杠命令全表

聊天里以 `/` 开头的命令，在会话内直接改变 Root 的运行状态。以下逐个核对过命令注册表（`src/coara/commands/`）：

| 命令 | 作用 |
|------|------|
| `/help` | 常用命令与快捷键 |
| `/new` | 新开一轮对话（清历史，宝箱同时上锁） |
| `/report` | 向开发者提交问题报告（可先 `/report` 再描述；或 `/report 描述`；经 webhook 发到开发者本机「用户反馈」） |
| `/stop` | 打断当前回合（保留但不宣传；打断主走 Ctrl+C / 端内打断按钮） |
| `/status` | 状态摘要：模型、工作空间、各项偏好开关 |
| `/usage` | 本轮用量；`/usage 7` 看最近 7 天 |
| `/model` | 列出 / 切换模型（如 `/model 2`、`/model minimax`） |
| `/ws` | 工作空间列表；输入 `/ws` 后 ↑↓ 选空间回车即切换；也可 `/ws <序号>` / `/ws switch <名>`；`/ws rename` / `/ws updates` / `/ws default` |
| `/events` | 事件源管理 |
| `/tools` | 可用与已隐藏的工具 |
| `/sandbox` | 切换执行沙箱 |
| `/thinking` | 思考模式开关 |
| `/vault` | 宝箱状态 |
| `/login` | 邮箱验证码登录（Web 在跑时打开登录页，纯 CLI 走终端向导；不登录也能用） |
| `/qrcode` | 在终端显示手机配对二维码（需 gomatrix 与隧道就绪） |
| `/message`、`/messages` | 查看全局系统消息历史（`/messages <N>` 看最近 N 条） |
| `/log` | 回看最近工具执行（`/log <n>` 展开第 n 条；`--seq` / `--tool` 按录像带定位） |
| `/email` | 配置 / 查看邮箱（写入 COARA_EMAIL*，供邮件工具使用；`/email status` 查看配置） |
| `/theme` | CLI 配色主题（`/theme dark` / `/theme light`） |
| `/compact` | 手动压缩当前会话历史（LLM 摘要，被替代部分归档可回取） |

## 16.5 coara 子命令全表

另一类命令在进程启动时解析，通常是**离线**操作：加载配置、执行、退出，不进入对话。适合脚本化和快速查看：

| 命令 | 作用 |
|------|------|
| `coara tray` | 启动系统托盘常驻内核（右键：开 Web / 手机二维码 / 退出） |
| `coara daemon` | 无头常驻内核：托管 Web/Matrix，无 CLI 界面 |
| `coara attach <空间名>` | 外挂 CLI：另开终端接入指定工作空间（瘦客户端，不抢锁） |
| `coara status` | 当前工作空间与默认模型 |
| `coara providers` | 已配置的 LLM 提供方 |
| `coara llm-profiles` | 解析后的模型档案 |
| `coara search <词>` | 搜索宝箱 `open/` 文件名（会提示解锁） |
| `coara vault …` | 宝箱管理（init/unlock/list/read/write/import/passwd 等，见 [第 10 章](./10-宝箱.md)） |
| `coara ws list` | 已登记工作空间 |
| `coara ws add <路径> --name <名>` | 登记工作空间 |
| `coara ws rename <旧名> <新名>` | 重命名（路径与磁盘不动） |
| `coara ws remove <名>` | 取消登记（`--delete-disk` 同时删目录） |
| `coara ws default <名>` | 设为启动默认（不影响正在运行的会话；运行中切换用 `/ws switch`） |
| `coara usage summary`、`coara usage session <id>` | 用量统计 |
| `coara workflow list` | 工作流草案与实例 |
| `coara examples install stocks-watch` | 安装内置示例项目 |

两套命令的分工：**斜杠命令管"这场对话"**（切换模型、开新会话、打断），**子命令管"这台机器上的资产"**（登记工作空间、查用量、管宝箱）。少数操作两边都有入口但语义不同——比如 `coara ws default` 只改注册表默认值，而 `/ws switch` 立刻切换当前会话。

## 16.6 Web UI 有什么

Web 由**常驻内核托管**，不需要单独启动。内核起来后访问 `http://127.0.0.1:8080`（默认端口，可用 `COARA_WEB_PORT` 修改）即可打开；最省事的方式是右键系统托盘图标 →「打开 Web 界面」。地址栏里带的 `?token=...` 是访问令牌，页面刷新后由 sessionStorage 继续持有。

界面按页签组织：

| 页面 | 内容 |
|------|------|
| `/chat` | 对话主界面：顶栏左侧切换工作空间、右侧「新会话」；聊天与审批/宝箱弹窗；右侧为最近工具活动（Web 不用 `/new`/`/ws` 斜杠，点界面即可） |
| `/review` | 消息中心（工作空间动态收件箱，带未读角标） |
| `/files` | 工作空间文件浏览与查看 |
| `/workflow` | 工作流草案与实例列表 |
| `/workflow/editor/:id` | 可视化工作流编辑器（拖拽节点、连线、编辑 WDL） |
| `/usage` | 用量（侧栏独立路由） |
| `/records` | 本地记录（笔记 / 收藏分 Tab） |
| `/config` | 配置（侧栏独立路由） |
| `/me` | 个人页：账户（邮箱验证码登录 / 退出登录）+ 配置助手；LLM log 已移入独立开发者工具（coara-devtools） |
| `/login` | 登录页（未登录时 `/me` 内嵌同一表单） |

侧栏模块：对话 / 消息 / 文件 / 用量 / 配置 / 工作流 / 记录，左下角是个人入口（未登录灰显，登录后显示邮箱）。手机接入（配对二维码）已从 Web 移入系统托盘。

Web 端有几个值得知道的机制：

- **宝箱解锁走专属侧信道**。AI 触发开箱时浏览器弹密码框，密码经 `vault_reply` 消息直达进程解锁，不进聊天、不进 LLM 上下文；60 秒超时，取消立即返回
- **工作流运行管理在这里**。`interrupted`（引擎异常退出）的实例可在 /workflow 页点"恢复"继续；草案编辑、实例状态与结果查看也在这
- **聊天区读服务端视图存储**。Web 聊天区的唯一数据源是 `ui/web_views.py` 维护的会话视图存储（每会话一文件，回合帧逐帧落盘）——实时显示与刷新恢复读同一份数据，不受录像带格式影响；前端另有 IndexedDB 秒渲染缓存，永远可被视图存储校正。录像带（`session_events.jsonl`）退为全端冷备 / 审计，不参与 Web 聊天区

## 16.7 进阶：两端如何共用一套状态

**CLI 的三通道显示**：终端输出分三路——`process_message` 的产出（最终回复、工具完成摘要）进滚动历史；追踪事件更新输入框上方的动态区（进行中的工具、子智能体心跳，上限 12 行）；另有少量关键事件（子智能体工具完成、待办增量、后台完成摘要）直接打印进滚动历史。所以子智能体长时间阻塞时你依然能看到内部进展。多工作空间时，后台空间的运转状态（`[空间名] 动作 计时`，标签带空间色）并入输入框上方唯一 spinner 行，一行看全所有空间；跨空间回合收尾时以带空间色边框的块投递最终答复全文，回合失败必显 `[空间名] 回合失败：…`。

**Web 的实时性**：工具与回合相关事件每 100ms 打成 `trace_batch` 经 WebSocket 推送（供聊天流式与右侧工具活动侧栏）；每 5 秒一次轻量心跳只带状态字段，无变化不推。完整状态快照只在连接建立时发一次。侧栏可在连接后从 `GET /api/trace/events?kinds=tool` 补给最近工具事件。

**对话气泡显示矩阵**（模型上下文仍是一份；「显示」指最终答复投递到哪一端的聊天界面）：

| 发起端 \\ 看见端 | CLI | Web | 手机 |
|------------------|-----|-----|------|
| CLI | 本地 | 不显示 | 不显示 |
| Web | 显示（`[Web]`） | 本地 | 不显示 |
| 手机 | 显示（`[Matrix]`） | 不显示 | 本地 |

规则一句话：**输出归属 = 最近一次注入端**。谁的回合的最终答复就显示在哪一端的聊天界面里；CLI 作为"盯场"端会带 `[Web]` / `[Matrix]` 前缀显示它端回合的收尾答复，Web 和手机只显示本端。回合中途切走工作空间后，离开空间的回合在收尾时把最终答复投递回发起端，并带空间名标记（CLI 形如 `[shop]`，Web 事件带 `detached` + `workspace_name` 标记）。

**三端共存时的生命周期**：内核（tray / daemon）持有 Root 与追踪落盘，各端只经 EndChannel / WS 接入。任一端的退出只断开自己的连接——CLI 关窗口、浏览器关页签、手机退出 App，都不影响内核与其他端；内核退出（托盘「退出内核」）才停掉一切。工作空间切换（无论从哪端发起）只改该端的视图指针，其它端各自保持自己的视图。

## 16.8 本章小结

- `coara` 确保内核常驻并 attach：终端只是端；Web / Matrix 由内核托管，入口在系统托盘
- CLI：`/` 补全命令、`@` 投递服务台（仅 CLI）、Ctrl+C 打断当前回合（保留上下文）、运行中输入自动排队
- 斜杠命令管对话内状态，`coara` 子命令管机器上的静态资产——两套都已按代码逐个核对
- Web UI：对话、消息、文件、工作流、记录、用量、配置 + 个人页（账户/配置助手）；右侧工具活动侧栏；token 认证；宝箱密码走侧信道
- 三端视图独立、互不镜像；输出归属 = 最近一次注入端；录像带是冷备，Web 聊天区读服务端视图存储
