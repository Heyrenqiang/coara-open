# 第 20 章 存储布局

## 20.1 你的文件和它的文件分开放

coara 跑起来后，磁盘上有两类目录：

| 类型 | 是谁的 | 放什么 |
|------|--------|--------|
| **工作空间目录** | 你的 | 源码、文档、业务文件——你的项目本来就在那 |
| **coara Home** | 它的 | 配置、trace、日志、宝箱、动态、工作流草案等一切运行时数据 |

原则一句话：**coara 产生的东西一律进 coara Home，不往你的工作空间里塞**（只有两个例外，见 20.5 和 20.6）。这样工作空间可以随便进 git，不会被运行垃圾污染。

coara Home 默认是 `<当前目录>/.coara`；配置了 `COARA_HOME` 或 `coara_home` 字段后（如 `D:\coara`），变成全局统一目录，多个工作空间的运行数据都收拢到里面。怎么配置见 [第 19 章](./19-配置系统.md)。

## 20.2 全局 Home 里有什么

配置了全局 Home 后，完整布局如下：

```text
<coara_home>/
├── system/                        # 机器级配置（见第 19 章）
│   ├── config.yaml
│   ├── providers.yaml
│   ├── .env
│   ├── skills/                    # 系统级技能
│   └── logs/                      # 系统级日志（仪表盘等）
│
├── users/default/                 # 用户级资产
│   ├── config.yaml                # 用户级配置覆盖（可选）
│   ├── llm_preferences.yaml       # /model --global 写入的全局默认
│   ├── skills/                    # 用户级技能（enabled.json、custom/）
│   ├── matters/
│   │   ├── definitions/*.yaml     # 事件源定义（file_watch / interval_poll / webhook / cron）
│   │   └── .state/                # 事件去重状态
│   ├── workflows/                 # 系统级子系统：锚定 config home，与工作空间无关
│   │   ├── drafts/{草案id}.json    # 工作流草案（内核投影，唯一活模型；编排写穿 + 编辑器同源）
│   │   ├── triggers.json          # 工作流触发器
│   │   └── instances.db           # 工作流实例数据库
│   ├── assets/
│   │   └── vault/                 # 宝箱
│   │       ├── vault.meta.json    # 盐值 + 校验值（不含密码）
│   │       ├── sealed/*.cvault    # 密文（锁定时）
│   │       └── open/              # 明文工作树（仅解锁期存在）
│   ├── records/
│   │   ├── agent/                 # agent 笔记、digests、curator_state
│   │   └── user/                  # 用户收藏
│   ├── works/  logs/  sessions/
│
├── registry/
│   └── workspaces.yaml            # 工作空间登记册：名字 → 目录绝对路径
│
├── runtime/
│   └── active.json                # 当前本机正在运行的 coara 绑定（工作空间、PID、会话）
│
└── workspaces/{workspace_id}/     # 每个工作空间一个运行时数据目录
    ├── traces/
    │   ├── trace_events.jsonl         # 结构化事件流（可观测、侧栏补给）
    │   └── trace_details/             # 大事件详情（超 5000 条自动裁剪最旧）
    ├── logs/coara.log             # 人类可读文本日志
    ├── artifacts/                 # 产物
    ├── subagents/                 # 分身运行状态落盘
    ├── tool_outputs/              # 超大工具结果落盘（spill）
    ├── usage/events.jsonl         # token / 工具用量
    ├── session_state.json         # 会话状态（session_id、更新时间）
    ├── session_events.jsonl       # 会话事件日志（录像带：全端冷备/审计，web 聊天区不读它）
    └── web_views/                 # web 端会话视图存储（每会话一个 {subject}__{session_id}.jsonl）
```

**断电与损坏自愈**：提醒、records 索引、config.yaml 回写等关键落盘一律走 临时文件 + fsync + 原子替换，要么完整生效、要么保持原样，不会留下半截文件。提醒的 `store.json` 若已损坏，coara 会把它改名保留为 `store.json.corrupt` 并暂停该文件的回写（防止空数据覆盖坏文件），人工修复或删除后重启即恢复。遗留的 `matters/store.json` / `runs.jsonl` 启动时直接删除。宝箱封存时先把旧密文整体让位到 `sealed.prev`，新密文就位后才删除备份；若断电恰好落在窗口内，下次启动自动从 `sealed.prev` 回滚，密文不丢。

记不住没关系，用的时候回来查 20.6 的速查表。

## 20.3 一个工作空间的数据散在哪几处

"一个工作空间"在 coara Home 里有四个落点，靠**名字**和 **workspace_id** 串起来：

| 落点 | 路径 | 内容 |
|------|------|------|
| 登记 | `registry/workspaces.yaml` | 名字 → 磁盘目录、一句话简介 |
| 事件源 | `<workspace>/.coara/matters/definitions/*.yaml` | 属于它的 webhook / 文件监听 / 轮询配置 |
| 动态 | `<workspace>/.coara/inbox/` | 它收到的外部事件，手机端红点就靠这个 |
| 运行时数据 | `workspaces/{workspace_id}/` | trace、日志、分身、用量 |

**workspace_id** 由工作空间目录路径算出来：

```text
workspace_id = {目录名 slug}-{路径 SHA1 前 10 位}
```

例如 `D:\code_ws\v8` → `v8-bd788e1c25`。同一路径永远算出同一个 id，所以 trace 和日志总能找到归属，改名工作空间也不影响。

## 20.4 没配全局 Home 时

不设置 `COARA_HOME` 也不在配置里写 `coara_home`，所有数据退回**当前工作空间目录下的 `.coara/`**：

```text
<工作空间>/.coara/
├── data/          # 相当于 workspaces/{id}/traces/
├── logs/          # coara.log、errors.jsonl
├── tasks/         # 后台任务记录
├── todos/         # 待办（按会话一个 JSON）
├── skills/        # 工作空间级技能
└── llm/           # LLM 调用镜像（每实例一行全文，coara-devtools 读取）
```

适合单工作空间试用；要长期用、管多个工作空间，建议配全局 Home。

## 20.5 想翻记录，去哪找

| 你想找 | 路径 |
|--------|------|
| 某次工具调用、LLM 请求的结构化记录 | `<coara_home>/workspaces/{id}/traces/trace_events.jsonl`（Web 工具活动侧栏 / CLI 动态区会用到；也可直接翻文件） |
| 会话记忆（录像带：跨进程恢复、冷备/审计） | `workspaces/<id>/session_events.jsonl`（web 聊天区不读它） |
| web 聊天区对话行（Web hydrate） | `<coara_home>/workspaces/{id}/web_views/{subject}__{session_id}.jsonl`（web 端唯一数据源，实时显示=刷新恢复读同一份） |
| dashboard 等从录像带投影的派生视图 | `workspaces/<id>/session_events.jsonl` 经 `src/session_log/conversation_projection.py` 投影派生 |
| 人类可读的排错日志 | `<coara_home>/workspaces/{id}/logs/coara.log` |
| 工具失败、被拦截的记录 | `<工作空间>/.coara/logs/errors.jsonl`（**故意放在工作空间里**，方便在源码旁边直接看） |
| token 和工具用量 | `<coara_home>/workspaces/{id}/usage/events.jsonl`，或直接 `coara usage summary` |
| 宝箱 | `<coara_home>/users/default/assets/vault/` |
| 工作流草案 | `<coara_home>/users/default/workflows/drafts/` |
| 工作空间动态 | `<workspace>/.coara/inbox/` |
| 待办清单 | `<工作空间>/.coara/todos/{session_id}.json` |
| 后台任务记录（TaskStore JSON） | `<coara_home>/.coara/tasks/` |
| 后台任务输出日志（output.log） | `<工作空间>/.coara/tasks/{task_id}/`（始终写在工作空间本地） |
| 哪台机器哪个 coara 在线 | `<coara_home>/runtime/active.json` |

注意两个"故意在工作空间里"的例外：错误日志和待办。前者为了就近排查，后者因为待办本来就是会话级的临时物。

## 20.6 常见误解

| 误解 | 实际 |
|------|------|
| `workspaces/` 里是各工作空间的源码 | 是运行时数据；源码在登记册 `path` 指的目录 |
| 宝箱是每个工作空间一个 | 全局只有一个，在 `users/default/assets/vault/` |
| 动态存在工作空间目录里 | 就在 `<workspace>/.coara/inbox/`（空间自治）；工作空间目录里的业务 inbox（如 `feedback/inbox/`）是另一回事 |
| 所有日志都在 coara Home | 错误日志（`errors.jsonl`）和待办在工作空间的 `.coara/` 下 |
| 删了 `workspaces/{id}/` 会丢配置 | 不会；配置在 `system/`，登记在 `registry/`，那里只有可再生的运行数据 |

## 20.7 本章小结

- 你的文件在工作空间目录，coara 的文件在 coara Home，互不污染
- 全局 Home 分四层：`system/`（配置）、`users/default/`（用户资产：动态、事项、工作流、宝箱、技能）、`registry/`（登记册）、`workspaces/{id}/`（按工作空间的运行时数据），外加 `runtime/active.json`
- `workspace_id` 由目录路径稳定哈希生成；一个工作空间有登记、事件源、动态、运行时数据四个落点
- 不配全局 Home 就退化为工作空间内的 `.coara/`
- 两个故意的例外：错误日志和待办放在工作空间自己的 `.coara/` 下
