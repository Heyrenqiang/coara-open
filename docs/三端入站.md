# 三端入站

> **Canonical**：三端进内核的输入先归类，再定要不要过征求同意门。  
> 对照：[三端运行显示出站](./三端运行显示出站.md) · [架构契约](./架构契约.md)

内核对话只有两个入口：空闲 `process_message` · 忙 `submit_continuation_input`。下面分类管的是：**进这两个入口之前**，端上发来的东西分别算哪一类。

---

## 1. 三类（先认类）

| 类 | 一句话 | 要不要征求同意 |
|----|--------|----------------|
| **A 对话注入** | 普通说话（含图、跟话） | **不要**。任何端随时可发，先来后到；注入即开段，显示归属跟注入端 |
| **B 影响共享会话** | 对**整段共享会话**生效的操作（打断、新会话、压缩、切模型等） | **要考虑**。他端在跑 → 先确认；没在跑 → 直接做。做成后必夺 source，效果见 §2.1 |
| **C 端本地 / 旁路** | 本端视图、查询、审批回执、取消排队等 | **不要**（对会话所有权）。端独立或定向回执，不当作「对话注入」 |

「项目视差」归 **C**：各端自己的工作空间视图 / pin（`/ws switch`、Web 切空间 chrome）。视图本来就可以不一样，**默认不过 B 门**；不广播 `workspace_switched` 给其它 attach。

---

## 2. 各类盖什么

### A 对话注入（随意）

| 形态 | 三端入口（示意） | 进内核 |
|------|------------------|--------|
| 闲时发消息 | attach/web `chat`；手机房间文本 | `process_message(source=端)` |
| 忙时跟话 | `continuation`；手机忙时跟话 | `submit_continuation_input(source=端)` |
| 附图 / 引用图 | 同上 + image_blocks / mxc | 同上 |

不问谁在跑、不弹确认。注入瞬间开段 → 后续 **Ⅰ 运行显示**跟该端。

### B 影响共享会话（要确认 + 三条硬规则）

覆盖：`/new`、`/compact`、切模型、思考/沙箱/工具写开关、打断（Ctrl+C / Web 停止 / `/stop`）。  
只读（裸 `/model`、列表）不算 B，算 C。

他端在跑且端族不同 → 统一同意门；同端族或空闲 → 直接做。

#### 2.1 三条硬规则（B 必守）

**① 对整个会话生效（不是只掐一条 UI）**

获批后的打断等，作用面是**当前共享会话整段**，含：

- 该会话正在跑的回合  
- 该会话归属端在本空间拉起的后台任务（与回合同属一端的后台一并停）

`/new` 另：停回合、不杀后台；并清空段落归属（新会话不继承上一会话的 mid_turn 段）。

例：Web 在跑（含它开的后台）。CLI 打断 → 确认 → 同意 → Web 的回合停、Web 开的后台也停。不是「只停 CLI 自己看见的那点东西」。

**② 一定夺 source（与普通输入同权）**

B 做成之后，操作端经段机制成为当前 source（与 A 注入开段一样）。此后：

- **Ⅰ 运行显示**只投新 source 端  
- 原 source 端上的运行显示全部停掉（不再续画该会话的正文/工具树/Thinking）

例：本来在 Web 对话。CLI 主动切模型或压缩并做成 → source 变 CLI；后续输出只在 CLI；Web 侧该会话运行显示停。

**③ 非 source 端必须能看见「谁在跑」**

本端不是 source、但共享会话上有回合在跑时，本端要有一个**小标志**标出当前 source 端在跑（CLI / Web / 手机对称）。用于知道「会话在谁手里」，避免误以为死机或误以为本端在跑。

例：CLI 上看着，Web 是 source 且在跑 → CLI 展示「Web 在跑」类小标；其它端类推。

### C 端本地 / 旁路（不过 B 门）

| 形态 | 说明 |
|------|------|
| 切本端视图 / 工作空间 pin | `/ws switch`、Web 空间切换——视差，各端可看不同空间 |
| 只读 slash | `/help` `/status` `/usage` 列表、裸 `/model` 等 |
| 审批回执 | `approval_reply` |
| 取消跟话排队 | `cancel_continuation` |
| 连接保活等 | `ping` / `pong`、drain 对账帧 |

## 3. 与显示文档的衔接

| 入站 | 出站 |
|------|------|
| A 注入 | 开段 → **Ⅰ** 按当前段投注入端 |
| B 获批并做成 | **夺 source** → 原端 **Ⅰ** 停；新 source 端接后续 **Ⅰ**；配置类可走 **Ⅱ chrome** |
| C | 一般不产生跨端 **Ⅰ**；旁路 UI 属显示出站 **Ⅲ** |
| 非 source 看他端在跑 | 占用小标（§2.1 ③），不是把 **Ⅰ** 镜像过来 |

### 3.1 注入信封不上屏（与出站同源口径）

- 后台任务 / 子智能体结果**永不上屏**：以注入信封形态存在的完成结果与提示，三端一律不上屏；只留「后台 N 项」计数与 trace 层摘要。
- 子智能体过程正文与最终结果**只折进 delegate 工具行**（帧 kind `subagent_chunk` / `subagent_result`），三端一致，绝不进主消息流。回归：`tests/test_ui/test_subagent_frame_leak_guard.py`。

---

## 4. 改动自检

1. 新入口属于 A / B / C？  
2. 若是 B：他端在跑是否过同意门？做成后是否夺 source？作用面是否覆盖会话回合 + 该端后台？非 source 端是否有「谁在跑」小标？  
3. 若是 A：是否只进两入口且 `source` 正确？  
4. 切空间／视图是否误做成 B？（默认应是 C）

## 5. 与代码对照

| 规则 | 原则 | 现状 |
|------|------|------|
| A 随意注入 | 两入口 | **符合** |
| B 同意门 | 他端在跑先确认 | **符合**（命令门 + 打断门；owner 取段归属优先） |
| B ① 打断含该端后台 | 会话归属端后台一并停 | **符合**（`hard_cancel` 按空间 + 归属端收窄） |
| B ① `/new` 与后台 | 停回合、不杀后台；清段落归属 | **符合**（`settle`/`interrupt` 均 `cancel_delegates=False`；`_clear_session_state` 调 `_segments.clear()`） |
| B ② 打断夺 source | 获批开段 | **符合**（`take_ownership_source`） |
| B ② 切模型 / 压缩等夺 source | 与输入同权开段，原端 **Ⅰ** 停 | **符合**（`settle_b_class_before_handler`：忙则打断+夺权，闲则开段夺权） |
| B ③ 非 source 运行标 | 标出哪一端在跑 | **符合**（Web 侧栏「运行中 · 手机」；CLI 状态槽 `● 手机 端运行中`） |
| C 切空间 | 端独立 | **符合** |

## 6. 入口索引

| 端 | A | B | C |
|----|---|---|---|
| CLI attach | `chat` / `continuation` | `command`（写）、`interrupt` | 读命令 / 切视图、`approval_reply`、`cancel_continuation` |
| Web | `chat` 等 | `command`、`interrupt` | 切空间 chrome、`approval_reply` |
| 手机 | 房间文本 → 两入口 | `/new` `/stop` `/model`… | `/ws switch`、审批 |
