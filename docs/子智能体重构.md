# 子智能体设计：并行优先

> 子智能体职责划分以本文为准。配置事实来源：`src/coara/prompts/agents/{name}.yaml` + `{name}.md`，加载逻辑在 `src/coara/builtin_agents.py`。

---

## 1. 设计理念

子智能体 ≈ **Root 无法在单上下文里同时做的多路并行工作**。

| 层级 | 职责 |
|------|------|
| **Root** | 主对话、规划、串行执行、技能激活、上下文压缩下的长任务 |
| **Skill（技能）** | 领域方法论与交付规范（调研、PPT、工作流……）——不占独立上下文 |
| **Sub-agent** | Root 无法在单上下文里同时做的**多路并行**工作 |

Root 真正解不了的是：快速、多子任务、**并行**——例如同时扫多个代码库、多路只读探索、多路互不干扰的独立改动。大部分任务 Root + 上下文压缩 + 技能激活即可胜任，不必开子上下文。调研是技能（`research`），不占 delegate 槽位与并行预算。

### 内置子智能体（共 4 个）

| 类型 | 职责 | 工具白名单（yaml `tools.include`） | 并行 |
|------|------|-----------------------------------|------|
| `coaras` | 工程子任务 / 只读摸底：并行多路或拆出独立子任务；只读时在 prompt 写明禁止修改 | `["*"]`（继承 Root 可见工具集，见 §4.3） | ✓ 可多个同时 |
| `aide` | 资料调研与头脑风暴：后台查资料、发散提案；不对用户提及 | `read` `grep` `glob` `web_search` `web_fetch` `todo` `orchestrator`（exclude：`write` `edit` `delete` `shell` `delegate` `skill`） | 强制 `background=true` |
| `janitor` | 工作空间管家（系统专属，SYSTEM_ONLY）：维护概况、写记忆、过目消息（勾掉/呈阅/自处理写轨迹）；由空闲 /new / 启动补扫 / `handle: janitor` 调度 | `read` `write` `edit` `delete` `grep` `glob` `shell` `todo` `orchestrator` `ws` `record` `local_search`（exclude：`delegate` `skill`） | 通常单工作空间单实例 |
| `daily` | 每日整理记录（系统专属，SYSTEM_ONLY） | `read` `glob` `grep` `record` `local_search`（exclude：写工具） | 单实例 |

补充事实：

- `delegate(action="message")` 可向运行中的子智能体发**途中指令**（调整方向/补充约束，经其 continuation 队列生效）；`delegate(action="stop")` 可硬停前台/后台 delegate。
- **双向通道挂所有任务型 `coaras`（前台 + 后台）**：子智能体经 `report` 工具把途中消息发到父会话、支持主→子途中消息；通道节直接写在 `coaras.md`（coaras 恒有通道）；aide静默无通道；janitor / daily 是系统派发（无父会话续接概念）无通道，只回最终结果。「不要中间输出」纪律直接写进每个子智能体 `.md`。
- **断点恢复**：`delegate(action="resume", task_id=…)` 从 `SubagentStore` 加载被打断（cancelled/failed）子智能体的完整历史断点，重建 CoaraBase 原地续跑（收口中断 tool_calls + 注入恢复提示，不重发原始 prompt，沿用原 task_id 与前后台模式）。
- `delegate(subagent_type="explore")` / `"research"` 会被**拒绝**（`REMOVED_SUBAGENT_TYPES`）。只读并行用 `coaras` + prompt 约束；调研用 `skill(action="activate", name="research")`。
- **plan_mode 下 delegate 的子代理强制只读**：子代理是新实例，`is_plan_mode=False`，executor 的「write/edit 只能写计划文件」检查不适用；因此 delegate 计算白名单时若父级处于 plan_mode，先交集 plan_mode 安全集再剥离 `write`/`edit`/`plan_mode`（`_resolve_tool_whitelist`）。剥离结果经白名单继承传递到孙代。
- `aide` / `janitor` 的 `orchestrator` 工具在 delegate bootstrap 时注册，action 接线到**父 Root**（`_bootstrap_subagent`）。
- `aide` 创建时**深拷贝** Root `message_history` 的最近 50 条（尾部窗口，丢弃孤儿 tool_result）作为初始上下文；`delegate` 的 `background` 参数对aide强制为 `true`。
- `coaras` 的首个用户轮会额外注入 Git 快照（`git status -sb`，环境种子 `include_git=True`）。
- 所有子智能体都是 IN_PROCESS asyncio 协程（同进程，非子进程），`delegate_depth >= 1` 时不能再 delegate；子智能体澄清在汇报中说明歧义（`report`）。

## 2. 决策表：Root / Skill / Delegate

| 场景 | 推荐 |
|------|------|
| 单库调研 + 写报告 | Root + `skill(action="activate", name="research")` |
| 单库多文件改动 | Root 直接 `read/edit/shell` |
| 长文档 Map-Reduce | Root + `long-document` 技能 |
| 同时查 3 个目录/仓库的事实 | 并行 `delegate(coaras)` × N，prompt 写明只读 |
| 同时改互不影响的两套代码树 | 并行 `delegate(coaras)` × N，`prompt` 写清边界 |
| 某已登记工作空间的巡检 / 维护 | cron 事件源 + `handle: janitor`（系统派管家过目）；临时动手用 `delegate(coaras, workspace=…)` |
| 有步骤依赖、要反复跑、要后台无人值守的多步流程 | `orchestrator` + `workflow` 技能 |

**不要 delegate 的情况**：

- 只为「省 context」——用上下文压缩；
- 只为「用 web_search 规范」——激活 research 技能；
- 单线程可完成的顺序步骤——Root todo 或 workflow。

## 3. 并行委派模式

### 3.1 多路只读摸底（coaras）

```text
# 同一轮 tool_calls 并行（示例）
delegate(subagent_type="coaras", description="auth 模块", prompt="只读…")
delegate(subagent_type="coaras", description="支付模块", prompt="只读…")
delegate(subagent_type="coaras", description="配置与 env", prompt="只读…")
```

合并：Root 读各子智能体的回报，交叉验证后回复用户。

### 3.2 多路工程 coaras

用于**边界清晰、互不写同一文件**的工程子任务：

```text
delegate(subagent_type="coaras", description="frontend fix", prompt="仅改 src/ui/…")
delegate(subagent_type="coaras", description="backend fix", prompt="仅改 src/api/…")
```

`prompt` 必须自洽完整（子智能体看不到对话上下文）：任务目标、路径范围（绝对路径）、方法指导、规则与禁止项、验收标准、回报格式。

### 3.3 与 Workflow 的边界

- **Delegate 并行**：轻量、同质、无复杂 gate，结果回到 Root 对话；
- **Workflow**：有步骤依赖、QC、人工审批、跨天执行。

## 4. delegate 机制

### 4.1 前台 / 后台异步委托

无论前台还是后台，子智能体均**异步启动**，父进程不等。区别在结果汇合时机与等待的决策者：

| 模式 | 启动方式 | 父进程行为 | 结果汇合 |
|------|----------|------------|----------|
| **前台**（`background=false`，默认） | `asyncio.create_task` | 可继续推进其他工作 | **LLM 显式 `delegate(action="wait")` 等齐**；回合出口对在跑的只注入一次系统提醒，提醒后仍不等则放行，迟到结果忙则注入、闲则驻会话历史 |
| **后台**（`background=true`） | `BackgroundAgentManager.start()` | 完全不等，轮次可正常结束 | 完成后注入到**后续某个轮次** |

### 4.2 前台委托流程

```text
delegate(background=false)
├── asyncio.create_task(_fg_coro())            # 异步启动子智能体
├── register_foreground_delegate(task_id, …)   # 登记到 _pending_foreground_delegates
├── add_done_callback(on_foreground_delegate_done)
└── 立即返回占位符 ToolResult（metadata.mode = "foreground_async"）

delegate(action="wait")
└── asyncio.wait(gather(全部在跑任务), 用户输入事件, FIRST_COMPLETED)
    # 一次等齐全部在跑的前台子智能体；用户新输入提前唤醒
    # 只等事件不搬结果——结果由 done 回调注入，无双份送达竞态

子智能体完成
└── on_foreground_delegate_done(task_id, desc, task)
    ├── task.cancelled() → 直接返回（轮次清理期间的取消不注入）
    ├── 已放行且会话空闲 → 结果 append 进 message_history + 持久化（下轮可见）
    └── 其余 → submit_continuation_input(<系统消息>[前台子智能体已完成]…)
        下一次 ReAct 迭代 drain_continuation_inputs() 拾取 → LLM 继续推理
```

### 4.3 轮次退出守卫

LLM 返回**无 tool_calls** 但仍有前台委托未完成时，不退出轮次、也不空转轮询，而是用 `asyncio.wait(FIRST_COMPLETED)` 阻塞等首个委托完成（可被 abort 打断）。结果已在 continuation 队列 → `continue` → 下一轮 drain → LLM 带着子智能体结果继续推理。

### 4.4 后台委托流程

```text
delegate(background=true)
├── BackgroundAgentManager.start(_bg_coro)
│   记录 launch_workspace_dir = 发起时的工作空间路径
└── 立即返回 task_id（metadata.mode = "background"）

子智能体完成
└── BackgroundAgentManager 收尾
    ├── 当前工作空间已切换（≠ launch_workspace_dir）→ 跳过 EventBus 注入
    │   （trace + TaskStore 仍记录；切回后可经任务列表查看）
    └── EventBus.publish(background_task_complete)
        └── RootCoara._on_background_task_complete（按发起 session 路由）
            ├── Root 繁忙 → submit_continuation_input（当前轮次下一迭代拾取）
            ├── Root 空闲（前台会话）→ 经 UnifiedScheduler 排一个 auto-run 轮次
            └── 非前台空闲会话 → 直接 append 历史并持久化（切回可见）
```

### 4.5 并发、上限与取消

- 子智能体并发数量不设上限（前台 + 后台）。
- 单个 子智能体最多 **1500 轮**工具迭代（`SUBAGENT_MAX_TOOL_ITERATIONS`）；`delegate` 工具本身**禁用**通用执行超时（`get_execution_timeout()` 返回 `None`）。
- 取消传播：轮次中断 → **立刻**硬取消全部前台/后台 delegate 与 bash `task`（`hard_cancel_all_running_delegates`：子 `interrupt` + `asyncio.Task.cancel()`，bash 顺带杀进程树），并清空 continuation 队列；父级 abort 信号经 listener 也会调用子智能体 `interrupt_current_turn(cancel_delegates=False)`。
- 后台 delegate 成功后，assistant 消息中对应的 `tool_calls` 会被剥离、不写 TOOL_RESULT（`turn_loop/tool_results.py`，仅 `mode == "background"`；前台 `foreground_async` 走正常工具结果路径）。

### 4.6 工具白名单解析

`DelegateTool._resolve_tool_whitelist()`：

1. yaml `tools.include` 非空且非 `["*"]` → 用该列表（aide / janitor / daily）；
2. 否则（如 coaras 的 `["*"]`）→ 继承父实例的绑定工具集（`get_bound_tool_names()`，为空则取可见工具定义）。

### 4.7 `workspace` 参数

指定工作空间别名时：经 `workspace_manager.registry` 解析出根路径作为子智能体的工作目录，并挂只含该工作空间的 VFS mounts。不填则用父实例当前工作目录。

### 4.8 持久化

- 每次 delegate 启动即写入 `SubagentStore`（running 状态），结束时更新终态（含 `result_preview` 前 2000 字符、error）；
- 后台委托同时写 `TaskStore`（统一任务查询入口）。

## 5. 关键文件

| 文件 | 职责 |
|------|------|
| `src/tools/builtin/delegate/delegate.py` | action=spawn/message/resume/wait/stop（主→子途中指令与硬停）；前台 `asyncio.create_task` + 占位符 / 后台 `BackgroundAgentManager`；前台 coaras 双向通道（`interact` 工具途中消息 + 环境节）；并发上限可配（默认 10）；迭代上限 1500；白名单解析 |

| `src/coara/builtin_agents.py` | 从 `prompts/agents/{name}.yaml + .md` 加载子智能体（LLM 可见 `coaras`/`aide` + 系统角色 `janitor`/`daily`）；explore/research 类型拒绝文案 |
| `src/coara/prompts/agents/*.yaml` / `*.md` | 各子智能体的工具白名单与系统 prompt（事实来源） |
| `src/coara/base.py` | 前台委托登记 / 完成回调 / `submit_continuation_input` / 取消 |
| `src/coara/turn_orchestrator.py` | 轮次退出守卫（`asyncio.wait`）；中断时取消前台委托 |
| `src/coara/background_agent.py` | 后台任务生命周期；跨工作空间注入防护 |
| `src/coara/root.py` | 后台完成通知注入（continuation / auto-run） |
| `src/coara/turn_loop/tool_results.py` | 后台 delegate 的 tool_call 剥离 |
