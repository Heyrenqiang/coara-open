## 1. 30 秒结论

```text
Workspace（工作空间名）= coara 管理的长期单位
  · workspace  … 代码 + 数据的场地（registry 登记 name → path）
  · workflow   … 可选：挂在本 ws 上的程序（WDL 草案）
  · janitor    … 管家本 ws 的系统维护管道（概况 / 记录 / 过目）
  · 事件源     … 唯一的触发钟：file_watch / interval_poll / webhook / cron

事件源到点 → 事件内容无条件落该 ws 消息收件箱
  · handle: park   → 挂住等你批示（或纯规则过期勾掉）
  · handle: janitor→ 叫醒管家 janitor 过目（勾掉/呈阅/自处理，轨迹写回消息）
  · 工作流 trigger → 命中即直启 WDL（不经 janitor）
```

**不是每个 ws 都必须有 workflow**；重复、有 I/O 的运转（定时看股票、拉新闻）定型后，把步骤收成 WDL 草案，由 cron 事件源或 `handle: janitor` 触发执行。

## 2. 四件事各是什么

| 概念 | 本质 | 是智能体？ | 向谁汇报 |
|------|------|-----------|---------|
| **Workspace** | 长期 `name` + path 登记 | 否 | — |
| **Workflow** | 本 ws 上的**程序**（WDL） | 否（程序本身） | 不汇报；产出 outputs / 实例状态 |
| **Janitor** | 本 ws **管家**（概况 + 记忆 + 消息过目） | 否（系统维护管道） | 处置轨迹写回消息；不注入主会话 |
| **事件源** | **触发钟**（何时、显著性、处置模式） | 否 | — |
| **Skill** | 操作手册 | 否 | — |

```text
用户 ↔ Root
         ↑
    janitor（管家自己的 ws：概况、记忆、消息过目）

Workspace
  ├── workspace（path、动态、目录约定）
  ├── workflow?（可选）
  └── 事件源*（file_watch / interval_poll / webhook / cron）
```

## 3. Workspace 的三种形态

| 形态 | 有什么 | 典型 | 事件源用法 |
|------|--------|------|--------------|
| **A 看护型** | workspace + janitor，**无 workflow** | 刚登记的 repo | cron 定时巡检（`handle: janitor`） |
| **B 程序型** | + 已保存的 WDL 草案 | 定时新闻、定时看股票 | cron 到点直启工作流（trigger 绑定） |
| **C 双轨型** | workflow + janitor 各管一块 | App 维护 | 低价值事件 `handle: janitor`，定型任务走工作流 |

何时从 A 补成 B：满足「固定 inputs → 固定步骤 → 固定 outputs，且会**重复跑**」时，把步骤收成 WDL 草案保存；仍在摸索规则阶段就先用 A。

## 4. Workflow — 挂在 ws 上的程序

- **不是**子智能体；**不对话**；**不主动汇报**。用户与 Root 打磨后保存为 WDL 草案。
- 草案的 `schedule` / 事件源绑定是**程序触发时机**，**不是**对外日程。
- 启动来源：
  1. 用户经 Root：`orchestrator(action="run", draft_id=…)`
  2. 事件源命中 WDL `schedule.kind: event|webhook` 的事件注册表（见本文 §4）——事件源 fire 时自动启动，事件 payload 整体作为 inputs
  3. janitor 过目时自决 `orchestrator(action="run", draft_id=…)`（工具白名单含 orchestrator）
- WDL 的 `schedule`（`kind: event|webhook`）只管「事件源命中时自动启动」；**定时执行就是 cron 事件源**（`kind: cron` 到点发 `cron.tick` 事件，再经 trigger 注册表直启工作流，或 `handle: janitor` 让管家决定）。

## 5. Janitor — ws 的管家

- **三职责**：① 维护工作空间概况（`ws.md`，会话边界/idle 触发）② 记录（`record`，推动用户成长）③ **消息过目与巡检**（事件源 `handle: janitor` 或定时叫醒时）。
- **只对一个 ws 负责**；产出留本空间；**不是** workflow 节点。
- 出场方式（系统维护管道 `janitor_maintenance.py`，模型不可经 `delegate` 点名）：空闲 /new / 启动补扫（概况维护）；事件源 `handle: janitor`（消息过目）。跨空间工程动手用 `delegate(coaras, workspace=…)`。
- 消息过目三选一（处置轨迹写回消息，`review` 工具，note 写理由）：
  - 低价值或噪音 → `review(dismiss)` 勾掉
  - 需用户拍板 → `review(elevate)` 呈阅（上浮前台待处理视图）
  - 能自己处理 → 处理完后 `review(resolve)` 写结论
- 纯规则过目（不经 LLM，janitor watcher 每拍执行）：过保质期 / low 超龄的消息自动 dismissed。
- 工具集：`read/write/edit/delete/shell/grep/glob/todo/review/record/local_search`（见 `prompts/injections/janitor.yaml`）。

## 6. 事件源 — 唯一的「什么时候」

四种 `kind`（定义在 `<workspace>/.coara/matters/definitions/*.yaml`，每文件一个源）：

| kind | 机制 | 典型 `event_type` | 何时用 |
|------|------|-------------------|--------|
| `file_watch` | 监听目录（非递归，短防抖） | `file.created` / `file.modified` | 本地目录落文件即可触发 |
| `interval_poll` | 定时扫目录文件名集合 | `poll.new_files` | 文件事件不可靠时的兜底 |
| `webhook` | `POST /webhook/{id}` JSON | 请求体 `event_type` | App / 后端 / 远程主动推 |
| `cron` | cron 表达式到点触发（Asia/Shanghai） | `cron.tick` | 定时巡检 / 定时跑工作流（停机错过不补发） |

公共字段（`salience` / `handle` / `ttl_seconds`）决定曝光与处置，见 [工作空间动态模型.md](./工作空间动态模型.md)。

> 定时巡检与看护：用 cron 事件源到点发事件；需要管家过目时设 `handle: janitor`。启动时幂等删除遗留的 `matters/store.json` / `store.json.corrupt` / `runs.jsonl`（不触碰 `definitions/` 与 `.state/`）。

## 7. 事件之后：完整处置链

```text
事件源触发（file/poll/webhook/cron）
  → 去重冷却 → 内容无条件落该 ws 消息收件箱（external_sensor）
  → 工作流 trigger 注册表命中 → 直启 WDL（不经 janitor）
  → handle: janitor → 系统派发 janitor 过目
        ├─ review(dismiss)（勾掉，note 理由）
        ├─ review(elevate)（呈阅，上浮待处理视图）
        └─ review(resolve)（自处理完，note 结论）
  → 纯规则过目（watcher 每拍）：过期/low 超龄 → dismissed（不经 LLM）
  → 用户批示（Web / 手机批复入口）→ resolved（reviewed_by=user）
```

事件内容**无条件**先落箱（事实记录），曝光与处置是叠加在其上的视图——消息永不因「没被处理」而消失，只会被勾掉（留轨迹）或归档。

---

## 8. 消息与处置轨迹

每条消息（`WorkspaceUpdate`）带处置轨迹字段：`disposition`（pending/elevated/resolved/dismissed）+ `reviewed_by`/`reviewed_at`/`review_note` + `expires_at`（保质期）。规则详见 [工作空间动态模型.md](./工作空间动态模型.md) §2。

- 用户批示 → `resolved`，备注为批示摘要
- 用户或 janitor 勾掉 → `dismissed`（不再占红点，条目保留可回查）
- 待处理视图 = 未勾掉/未处置的 **high** 条目 ∪ 被**呈阅**的条目（无论显著性）
- 纯规则过目只动 `pending`：过期 / low 超龄 → dismissed；`elevated` 不受规则触碰（大臣已呈阅，等皇帝）

## 9. 操作入口：CLI、聊天、REST

| 入口 | 命令 | 说明 |
|------|------|------|
| 事件源 | `event_source(action=list|add|update|toggle|remove|reload)` | Root 工具（写操作走人工审批） |
| 事件源 | `/events list` 等 | CLI 查看（`src/coara/commands/`、`src/ui/handlers/commands.py`） |
| 消息 | `review(action=board|list|pending|read|dismiss|elevate|resolve|archive|salience|mark_read)` | janitor 专属批复工具 |
| 消息 | `/ws updates [list|pending|read|dismiss|elevate|resolve|archive|mark_read|stats] [名]` | 聊天命令（无需 LLM） |
| 消息 | `/api/updates/review` | Web / 手机批示入口（`src/workspace/updates/review.py`） |
| 工作流 | `orchestrator(action=…)` / Web 编辑器 / `PUT /api/workflow-drafts/{id}` | 程序编排 |

## 10. 跨 ws：只交接数据，不借管家

```text
上游 ws 的 workflow 产出 → 工作空间动态 / 文件 / outputs
下游 ws 的事件源或 cron → 本 ws 的 janitor / workflow

✗ 上游 flow 直接调用下游 ws 的 janitor
```

## 11. 完整例子

内置示例：`examples/stocks-watch/`（事件源模板 + cron 事件源示例 + 工作空间 AGENTS.md），一键安装：

```bash
coara examples install stocks-watch
```

**阶段 A（看护型，无 workflow）**：cron 事件源定时巡检，`handle: janitor` 让管家过目：

```yaml
# <workspace>/.coara/matters/definitions/stocks-watch-daily.yaml
id: stocks-watch-daily
kind: cron
workspace: stocks-watch
cron: "0 8 * * 1-5"
salience: normal
handle: park          # 或 janitor：到点叫醒管家过目
message_template: |
  [定时巡检 — {{source_id}}]
  到点：{{details}}
  例行拉行情写 brief；无异常可忽略，需要决策的呈阅
```

**阶段 B（程序型）**：步骤定型后保存 WDL 草案，cron 事件源 + 工作流 trigger 绑定直启（或 `handle: janitor` 由管家自决 `orchestrator(action="run", draft_id=…)`）。

**事件型**：`file_watch` 监听 inbox 目录，新文件落消息；需要立即处理的配 `handle: janitor`。

**临时对话**（「顺便查一下 OpenAI 昨天发了啥」）→ Root 直接 `web_search` 或激活 `research` 技能，**不进**事件源链。

## 13. 常见误解

| 误解 | 正解 |
|------|------|
| 每个 ws 必须有 workflow | 最小 ws 只有 workspace + janitor；程序后挂 |
| 定时必须靠事项 | 定时 = cron 事件源（`kind: cron`） |
| janitor 只维护概况 | janitor 是管家：概况 + 记忆 + 消息过目三职责 |
| janitor 是 workflow 节点 | janitor 管家 ws；workflow 的 run 节点是另一套池化子智能体（见 [节点即智能体.md](./节点即智能体.md)） |
| workflow 向用户汇报 | 程序不汇报；Root 上菜 |
| janitor 面向用户 | 只汇报 Root；消息处置只写轨迹不注入主会话 |
| 事件源 = 工作流 | 事件源只管「什么时候 + 曝光/处置」；「怎么转」是工作流 |
| cron 事件源 = 闹钟 | 闹钟（reminder）提醒你本人；cron 事件源驱动工作空间运转 |

## 14. 术语速查

| 术语 | 含义 |
|------|------|
| **Workspace** | `name` + path + 可选 workflow + 事件源 |
| **Workflow** | 本 ws 的程序（WDL）；自转；不汇报 |
| **Janitor** | 管家（概况+记忆+消息过目）；只报 Root |
| **事件源** | 触发钟：file_watch / interval_poll / webhook / cron |
| **消息（动态）** | 事件与运行结果的事实流，带处置轨迹 |
| **Reminder** | 用户 one-shot/间隔提醒（≠ 事件源） |
| **工作空间动态（updates）** | 按 ws 记录的事实流（含事件、工作流终态） |
