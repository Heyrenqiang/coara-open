## 1. 30 秒结论

```text
工作空间 = 磁盘上的一个文件夹（工作空间目录）+ 登记表里的一个名字（如 test-coara）

源码、AGENTS.md、业务文件   →  工作空间目录（用户/git 管）
trace、log、子代理持久化    →  {coara_home}/workspaces/{workspace_id}/（coara 管）
宝箱（vault）               →  {coara_home}/users/default/assets/vault/（全局加密文件夹）
登记、事件源、事项、动态     →  {coara_home}/registry/、users/default/（按工作空间名组织）

在哪开 coara，就操作哪个工作空间；trace 跟当前活动工作空间走，
/ws switch 切换时 TraceStore 随之重建，新 trace 写入新工作空间的槽位。
```

## 2. 四种「目录」——最易混淆

| # | 名称 | 典型路径/取值 | 是什么 | 常见误判 |
|---|------|---------------|--------|----------|
| **A** | **工作空间目录** | `D:\code_ws\v8\test-coara` | 用户的工作场地：源码、`AGENTS.md`、业务数据 | ✗ 以为 trace 一定在这下面的 `.coara/`（配置了全局 coara Home 时不会） |
| **B** | **workspace_id 槽位** | `D:\coara\workspaces\test-coara-2b4bd8d172\` | coara 为该**路径**分配的运行时数据目录 | ✗ 以为里面放的是源码 |
| **C** | **工作空间名（name）** | `test-coara` | 登记表里的短名；事件源、事项、动态、`delegate` 都按它路由 | ✗ 以为 name 必须等于文件夹名（默认同名，但可另起） |
| **D** | **启动 cwd** | 执行 `coara` 时所在的文件夹 | **本次会话的操作根**：决定 trace/log 写入哪个 workspace_id 槽位 | ✗ 以为存在一个全局唯一的「当前工作空间」与 cwd 无关 |

**记忆口诀**：**A 写代码，B 记运行，C 做路由，D 定本次会话。**

## 3. 一个工作空间的完整身份

一个工作空间在系统里由 `WorkspaceEntry`（`src/workspace/types.py`）描述：

| 字段 | 示例 | 含义 |
|------|------|------|
| `name` | `test-coara` | 人类短名；CLI/工具调用里写它 |
| `id`（workspace_id） | `test-coara-2b4bd8d172` | 由 path 稳定哈希；对应 **B** 槽位目录名 |
| `path` | `D:\code_ws\v8\test-coara` | 工作空间目录绝对路径（**A**） |
| `kind` | `managed` | 登记类型（`managed` / `reference` / `internal`） |
| `status` | `active` | `active` / `archived` / `suspended`；只有 active 参与挂载 |
| `mode` | `rw` | 挂载模式（`rw` / `ro`） |
| `tags` | `[]` | 标签列表 |
| `summary` | 一行摘要 | `ws(list)` 展示用 |

**workspace_id 算法**（`workspace_id_for()`，`src/core/coara_home.py`）：

```text
workspace_id = {目录名 slug}-{path 的 SHA1 前 10 位}
slug = 目录名小写，非 [a-zA-Z0-9_.-] 字符替换为 -
```

同一绝对路径永远得到同一 workspace_id；改文件夹位置会得到新 id（新槽位）。

## 4. 登记表 registry/workspaces.yaml

登记表是唯一的工作空间名册，路径 `{coara_home}/registry/workspaces.yaml`：

```yaml
version: 1
default_workspace: test-coara-2b4bd8d172   # 「启动默认」标记，见 §8
workspaces:
  test-coara-2b4bd8d172:                   # 注意：键是 workspace_id，不是 name
    name: test-coara
    id: test-coara-2b4bd8d172
    path: D:\code_ws\v8\test-coara
    kind: managed
    status: active
    mode: rw
    summary: "一行摘要"
```

要点（`src/workspace/registry.py`）：

- **字典键永远是 `entry.id`**（加载时会自动把不一致的键规范化为 id）。
- `ensure_workspace()` 按**解析后的绝对路径**判重：同一路径重复登记会返回已有条目，不会产生两条。
- 未指定 name 时从目录名生成（小写、非法字符转 `-`），撞名时自动加 `-2`、`-3` 后缀。
- pytest 临时目录（ ephemeral 工作空间）会被自动从登记表清除且不持久化。
- 启动时若已登记工作空间的 `path` 在磁盘上不存在，只记警告日志，不自动除名。
- 登记表文件被外部改动（如另一个 `coara ws` 命令）时，运行中的进程经 `reload_if_stale()` 按 mtime 重新加载。

## 5. coara Home 与工作空间目录如何对应

配置 `coara_home: D:\coara`（或环境变量 `COARA_HOME`）后：

```text
┌────────────────────────────────────────────────────────────────────┐
│  coara Home: D:\coara                                              │
│  ┌──────────────────┐  ┌─────────────────────────────────────────┐ │
│  │ registry/        │  │ users/default/                          │ │
│  │  workspaces.yaml │  │  matters/definitions/*.yaml（事件源）    │ │
│  │                  │  │  matters/.state/（事件源去重状态）        │ │
│  │                  │  │  inbox/{name}/（工作空间动态）           │ │
│  │                  │  │  assets/vault/（宝箱）                  │ │
│  └────────┬─────────┘  └─────────────────────────────────────────┘ │
│           │ path 指向                                              │
│           ▼                                                        │
│  用户工作空间目录 A：D:\code_ws\v8\test-coara（源码，git 管理）      │
│           │ path 哈希 → workspace_id                               │
│           ▼                                                        │
│  workspaces/test-coara-2b4bd8d172/（运行时槽位 B，非源码）           │
│    traces/  logs/  subagents/  tool_outputs/  usage/               │
│  runtime/active.json ← 本机正在运行的 CLI 绑定（手机 Matrix 用）     │
└────────────────────────────────────────────────────────────────────┘
```

未配置 `coara_home` 时退化为 `<工作空间>/.coara/` 单工作空间布局。完整目录清单与每个子目录的内容见 [STORAGE_AND_WORKSPACES.md](./STORAGE_AND_WORKSPACES.md)。

## 6. 生命周期：从登记到运行

| 阶段 | 操作 | 结果 |
|------|------|------|
| **登记** | `coara ws add <path> --name <名> [--summary "..."]` | 写入 `workspaces.yaml`；path 必须已存在（CLI 会校验） |
| **自动登记** | 在未登记的目录里直接启动 `coara` | `WorkspaceManager.initialize()` 自动把 cwd 登记进 registry |
| **挂事件** | 在 `<workspace>/.coara/matters/definitions/` 放事件源 YAML（模板见仓库 `events/*.yaml.example`） | 外部输入无条件进动态收件箱，`salience`/`handle` 决定曝光与处置，见 [多工作空间与工作空间动态.md](./多工作空间与工作空间动态.md) |
| **启动** | 在工作空间目录（或其子目录）执行 `coara` | 创建/打开 `workspaces/{id}/` 槽位；发布 `runtime/active.json`；恢复上次会话（2 小时内） |
| **会话** | 聊天、`/new`、`/ws switch` | 同一工作空间可反复启停；`/ws switch` 切换见 §9 |
| **跨工作空间执行** | `delegate(subagent_type="coaras", workspace="<名>")` | coaras 子代理锁定**目标**工作空间目录执行 |
| **移出** | `coara ws remove <名>`（或 `ws(action="remove")`，需确认） | 默认只取消登记、磁盘目录保留；`--delete-disk` / `delete_disk=true` 才删目录（不可逆）；`workspaces/{id}/` 历史数据仍保留 |

跨空间工程动手（读反馈、改代码、跑构建）走 **coaras** 委派（`workspace` 锁定目标空间）；「工作空间管理」技能（`skill(action="activate", name="工作空间管理")`）只管登记/挂事件/体检/移出这套生命周期。`ws.md` / 消息过目由系统 **janitor** 负责。

## 7. 当前工作空间 vs 跨工作空间操作

| 用户意图 | 正确做法 | 错误做法 |
|----------|----------|----------|
| 在 test-coara 里改文件 | 在 `test-coara` 下开 CLI（或 `/ws switch test-coara`），直接对话 | 在别的目录开 CLI 却以为在改 test-coara |
| 查看 xuan 的未读动态 | `review(action=list, name="xuan")`（janitor 专属）或 `/ws updates list xuan`（用户 CLI） | Root 自己 `grep` xuan 的工作空间目录 |
| 处理 暄 反馈、改 暄 代码 | `delegate(subagent_type="coaras", workspace="暄", ...)` | Root 直接对 xuan 目录 read/grep/shell |
| 列出所有在册工作空间 | `ws(action="list")` 或 `coara ws list` | 去 coara Home 下猜目录 |

分工原则：**Root 是用户的对话入口与编排者，不亲自进入其它已登记工作空间做读写执行**；看动态用 `/ws updates`（用户）或交由 janitor `review`（系统过目），动手用 coaras（`workspace` 锁定）；事件/定时触发的无人值守过目走管家 janitor（系统专属，`handle: janitor` 或 cron 事件源唤醒）。完整角色边界见 [多工作空间与工作空间动态.md](./多工作空间与工作空间动态.md)。

## 8. 启动 cwd、active 工作空间、默认工作空间

三个相关但不同的概念：

| 概念 | 机制 | 何时变 | 影响 |
|------|------|--------|------|
| **startup_cwd** | `WorkspaceManager.startup_cwd` | 进程启动时确定，**永不变** | 「本次会话从哪启动」的锚点；`cwd_display_suffix()` 显示 cwd 相对活动工作空间的子路径 |
| **active 工作空间** | `WorkspaceManager.active_id` → `active_name` / `active_path` | `/ws switch <名>` 或 `ws(action="switch")` | 当前操作的工作空间；VFS 挂载的活动项 |
| **registry 的 default_workspace** | `workspaces.yaml` 顶层字段 | `coara ws default <名>`、`/ws default <名>`、`/ws switch <名> --default` 写入 | 「启动默认」**标记**，在 `coara ws list` 里显示为「默认」；启动时实际操作哪个工作空间仍由 **cwd 决定** |

另外启动时可用 `coara --workspace-alias <名>` 请求指定工作空间（找不到则回退 cwd 工作空间并记警告）。

```text
在 D:\code_ws\v8\test-coara 启动 coara
  → startup_cwd = test-coara（永不变）
  → active = test-coara，trace → workspaces/test-coara-xxx/traces/

会话中 /ws switch v8
  → active = v8，trace → workspaces/v8-xxx/traces/（TraceStore 重建）
  → startup_cwd 仍是 test-coara
```

## 9. 切换工作空间：/ws switch

**切换必须用 `ws(action="switch")` 工具或 `/ws switch` 斜杠命令。** 不要对运行中的会话用 shell 调 `coara ws default`——那是独立 CLI 子命令，只把名字写进 registry 的「启动默认」字段，**不影响正在运行的进程**。

`/ws switch <名>` 触发 `RootCoara.switch_workspace()`（`src/coara/root.py`），依次：

1. 在 registry 解析 name/id；`WorkspaceManager.switch()` 更新 active 工作空间
2. 切换前台会话：为该空间创建或复用对等的 `WorkspaceSession`（独立 `CoaraBase`：message_history、session_id、todo、工具状态；切回即恢复原对话）
3. `os.chdir()` 到新工作空间目录
4. 重新发布 `runtime/active.json`（手机 Matrix 路由跟到新工作空间）
5. 发出 `workspace_switched` 事件 → CLI / Web UI 重建 TraceStore，新 trace 写入新工作空间槽位

**人类切换（忙时）**：A 空间正在跑长回合时可切到 B；A 的那一轮继续跑完（不中断），对话焦点在 B。切回 A 可见已完成的历史。

**回合中 LLM 切换**：若 LLM 在对话回合内调用 `ws(action="switch")`，当前回合以 `CoaraRunCancelledError` 结束并通知「已切换到工作空间 X」；源工作空间用 `strip_ws_switch_tail` 清理切换尝试尾部——从 `ws(switch)` 上溯到**触发切换的那条用户输入**，该用户输入及其后所有内容（含 `ws(list)` 等调用链）从历史移除，避免切换指令污染后续对话；strip 后若本回合已有工具落盘，追加一条磁盘副作用注记（与 Ctrl+C 中断、未预期异常回滚同源），模型不会误判磁盘未改动；目标工作空间的历史不受影响。

**会话恢复与过期**：每个工作空间的 `session_state.json` 记录最近 session_id 与时间；超过 2 小时（阈值取自配置 `session.idle_timeout_seconds`，默认 7200，0 为禁用；`is_session_stale`）未**发消息**则视为过期。计时只在 CLI / Web / Matrix **用户发消息**时刷新（`record_user_activity`）；切换工作空间、`/new`、空闲自动新会话都不会刷新。过期且仍有对话时切入会 `start_new_session(interrupt_source="workspace_stale")`，回执「新会话」；有对话且未过期则「上次对话 HH:MM」。

多会话架构的完整说明见 [多工作空间与工作空间动态.md](./多工作空间与工作空间动态.md) §会话隔离。

## 10. 手机 Matrix 与 active.json

手机 coara App **不是独立工作空间**，而是绑定**本机正在运行的 coara 进程**：

```json
// {coara_home}/runtime/active.json
{
  "workspace_id": "test-coara-2b4bd8d172",
  "workspace_path": "D:\\code_ws\\v8\\test-coara",
  "workspace_name": "test-coara",
  "pid": 12345,
  "session_id": "...",
  "coara_id": "root",
  "coara_name": "考拉",
  "started_at": "2026-07-25T10:00:00+00:00",
  "matrix_enabled": true,
  "matrix_room_id": "!xxx:server"
}
```

- 进程启动时写入（`publish_active_runtime()`），优雅关闭时按 pid 清除。
- `/ws switch` 切换后立即重发，指向新工作空间。
- 读取方忽略 pid 已死的陈旧条目（`load_active_runtime()` 会探活）。
- Matrix 入站消息优先路由到 `workspace_path` 指向的工作空间目录（`resolve_matrix_workspace_path()`）。

## 12. 自检清单与常用命令

### 12.1 我现在在哪个工作空间？

```powershell
# 1. 看启动 banner（coara 启动时打印 workspace / workspace_id / coara_home / trace / log / errors 六行）
# 2. 聊天中：/status 或 /ws
# 3. live 进程绑定（手机/Matrix 也用）：
type D:\coara\runtime\active.json
# 4. 登记表：
coara ws list
```

### 12.2 trace 在哪、怎么分析耗时？

trace 跟**当前活动工作空间**走：`{coara_home}/workspaces/{workspace_id}/traces/trace_events.jsonl`。分析脚本见 [`scripts/dev/README.md`](../scripts/dev/README.md) § analyze_turn_timing。

### 12.3 登记与体检

```powershell
coara ws add "D:\path\to\workspace" --name myapp --summary "一行摘要"
coara ws list
coara ws remove myapp              # 只取消登记；加 --delete-disk 才删目录
coara ws default myapp                 # 设为「启动默认」标记（不影响运行中的进程）
```

Agent 侧：`ws(action="list")`；生命周期操作激活 `工作空间管理` 技能。

## 13. 常见误解

| 误解 | 实际 |
|------|------|
| coara Home 的 `workspaces/` 里是源码 | 是运行时数据；源码在 registry 的 `path` 指向的目录 |
| 一个 name 只能对应 coara Home 下的文件夹 | `path` 可以是任意绝对路径 |
| registry 的键是工作空间名 | 键是 **workspace_id**；name 是条目的一个字段 |
| `/ws switch 暄` 不会把 trace 切到 暄 | 会。切换时重建 TraceStore，trace 跟当前活动工作空间走（§9） |
| registry 的 default_workspace 决定每次启动操作哪个工作空间 | **启动 cwd 决定**；default_workspace 只是持久化的「启动默认」标记与展示 |
| `coara ws default xuan` 能切换正在运行的会话 | 不能。它只写 registry 标记；切换运行中会话用 `/ws switch` 或 `ws(action="switch")` |
| 工作空间动态 = 工作空间目录里的 feedback/inbox | 动态在 `<workspace>/.coara/inbox/`；工作空间目录里的 inbox 是业务数据，归用户/管家 janitor 管，见 [工作空间动态模型.md](./工作空间动态模型.md) §与工作空间内 inbox 的区别 |
| 手机连的是「某个工作空间服务器」 | 手机连 Matrix 房间；PC 进程的 `active.json` 决定上下文工作空间 |
