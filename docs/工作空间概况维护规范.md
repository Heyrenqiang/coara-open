# 工作空间概况维护规范

> 概念背景见 [`工作空间概况.md`](./工作空间概况.md)；本规范管如何写 `ws.md`（提示词见 `src/coara/prompts/injections/janitor.md`）。

---

## 1. 定位

`ws.md` 经环境种子注入每会话头部。读完全文，智能体应对该空间有基本把握——不是 changelog。

输出：`<工作空间目录>/.coara/ws.md`。

---

## 2. 骨架与写法

概况块顺序固定：先「目录文件」，再「用户行为」，再「其它」，最后一行固定为「上面是该工作空间的一些情况，仅供参考」。

- 「其它」无内容则整块省略
- 「用户行为」没有值得记的就只留标题、下面不写条目（宁缺毋滥，不要凑数）

```text
# 目录文件
……

# 用户行为
……

# 其它
……（无可省略整块）

上面是该工作空间的一些情况，仅供参考
```

| 块 | 要点 |
|----|------|
| 目录文件 | 空间物理样子；有 AGENTS.md 时只写进门地图并指向它，不抄 AGENTS 目录树/架构长文 |
| 用户行为 | 情境（时间、问题）- 用户输入（想法、意图、观点）- 现状（完成情况、方案建议） |
| 其它 | 悬置方案、未决问题等；无可整块省略 |

注意事项：宁缺毋滥，每一条都要能说出放在这里的理由；总量有限，动态变化。

若 AGENTS.md 与 ws.md 重复：把能放到 ws.md 的放到 ws.md 并去重。

**ws.md 正文不写格式说明或维护规则。**

---

## 3. 维护流程（机制）

1. 读 ws.md + 会话快照 + 按需 review/glob
2. 更新各块（目录有变才动目录；用户行为宁缺毋滥）
3. 临时文件 → 原子替换 `.coara/ws.md`

篇幅软目标 ≤12KB，硬顶 ≤24KB（注入侧另有截断）。

---

## 4. 黑名单

技术 changelog、排障过程、提交测试态、复制 AGENTS 全文、敏感信息、一次性闲聊、把格式说明抄进正文。
