# 批复中心与移动端模块化：现状与推进

> 进展文档（2026-08-08）：批复系统三端落地情况 + Android 侧栏模块化分期路线。
> 数据模型权威见 [工作空间动态模型](./工作空间动态模型.md)；通信链路权威见 [MATRIX_APP_LINK](./MATRIX_APP_LINK.md)（§6.5 REST 代理）；手机端交互见 [Android远程控制与输入交互](./Android远程控制与输入交互.md)。

## 1. 批复系统现状

批复 = 工作空间动态收件箱里「等着人来处理」的条目，三端均可处理，状态全端同步。

### 1.1 数据底座（PC）

- 存储：工作空间动态收件箱（`<workspace_dir>/.coara/inbox/*.json`，空间自治布局，2026-08 迁移；旧 coara Home 级 SQLite/目录布局仅兼容），每条含 workspace / type / salience（high/normal）/ status（unread/read/archived）/ payload。
- 来源：事件源（`event_source`）、提醒到点（`reminder`）、工作流终态（`workflow`）、用户反馈 webhook。后台任务完成结果只回发起会话历史，不落收件箱。
- 批复语义：`review_workspace_update` 把「内容引用 + 用户指示」以 `<工作空间消息>` 标签注入所属空间的会话处理；已读/忽略/整空间已读纯改状态。

### 1.2 Web 批复中心（2026-08-07 落地）

- REST：`/api/updates/summary|list|pending|read|archive|mark_read|review`（`src/ui/web_server.py`）。
- 推送：WS 推 `updates_state`（pending 计数 + 高显著预览，去重），状态变更后补发 `updates_changed`。
- 前端：`/review` 页（`views/ReviewView.tsx`）——分组卡片、滑动已读/忽略、内联批复输入、「切入处理」切换到对应空间会话；侧栏「待批复」带未读角标。

### 1.3 Android 批复（2026-08-07 二期 + 08-08 一期）

- Matrix 信道（不进 LLM 上下文，后台同步）：
  - PC→App `[COARA_UPDATES]` 信封：全量 `state` / 增量 `unread`；增量只带 `update_increment` 并入既有消息；高显著预览进推送包 `preview`；App 冷启动走 `updates_pull` RPC 拉全量。
  - App→PC `[COARA_UPDATE_CMD]`：`read` / `archive` / `mark_read` / `review`，PC 处理后回新信封闭环。
  - 解析层：`coara/UpdatesSyncParser.kt` + `UpdatesStateCache.kt`（`[COARA_` 前缀过滤先于 JSON 解析）。
- UI：原抽屉「待批复」卡片区 → 一期提升为全页批复中心（`ui/ReviewScreen.kt`），滑动已读/忽略、内联批复、切入处理与抽屉版逐字对齐。

## 2. Android 侧栏模块化现状（一期，2026-08-08 完成）

### 2.1 导航骨架

- 抽屉从「纯工作空间列表」重构为 WebUI 侧边栏形态：顶部当前空间下拉（展开空间列表点选切换），下挂六模块——对话 / 批复（待办角标）/ 工作流 / 记录 / 用量 / 配置。
- 页面切换：`ui/AppScreen.kt` sealed 状态机 + `ChatViewModel.currentScreen`，ChatScreen 顶层分发；子页返回键回对话页；不引 Navigation 库。

### 2.2 数据通道（关键架构决策）

- gomatrix 反向代理：`/coara-api/*` → `127.0.0.1:8080/api/*`，挂在 Matrix 鉴权组内，转发注入 `X-Coara-Token`（读本机 dashboard_token，mtime 热重载）。App 只用已有 Matrix 令牌，dashboard token 永不下发；web server 保持 localhost 绑定。授权语义：有 Matrix 账号 = 有全部 REST 权限。
- App 侧 `coara/CoaraApiClient.kt`：Bearer 复用 Matrix access token，错误四态（Success / Unauthorized / PcUnreachable / Error）。

### 2.3 已落地模块页

- 批复页：全页版待批复（Matrix 信道，未走 REST）。
- 用量页：REST 拉 `/api/usage/dashboard`，总览卡 + 按模型/智能体/工作空间/天四段。
- 占位页：工作流 / 记录 / 配置（导航与页面骨架就位，二期填内容）。

### 2.4 验证与产物

- gomatrix：`go test ./...` 全绿（代理 6 例：路径重写、token 注入与热重载、上游宕机、token 缺失、鉴权拦截）。
- App：`:app:compileDebugKotlin` + `:app:testDebugUnitTest` 全绿（新增 ApiClient 7 例 + 用量解析 2 例）；新 APK 已部署 `gomatrix/coara-app.apk`。

## 3. 接下来推进

### 二期（下一次开工）

- 记录页：`/api/records` 列表（类型/时间/摘要）+ `/api/records/item` 详情，经 `/coara-api`。
- 工作流页：实例列表 + 详情只读（节点状态时间线）；编辑与拖拽编排不上手机。
- 顺手项：子页（批复/用量等）内开抽屉的入口（当前只有返回箭头回对话页）；用量页「按工作空间」段去留（契约自带，渲染成本为零）。

### 三期

- 配置页（收窄为「自动化」）：定时事项 / 提醒 / 事件源的列表 + 启用开关（设置中心 API）；provider/model 等重配置留在 WebUI。

### 部署与运维备忘

- 代理生效需重启 gomatrix（改 Go 代码后 `go build` 重编译，下次 coara 拉起即生效）；新 APK 需安装；Python 侧改动需重启 coara。
- 批复 Matrix 信道与 REST 代理并存不冲突：批复走 Matrix（实时推送已就绪），其余模块走 REST。
