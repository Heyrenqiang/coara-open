# 架构契约（一页纸）

> 这是 coara 的四梁八柱。任何改动先对照这一页；违反契约的改法直接不做。
> 最后更新：2026-09-02（端独立为默认；同空间模型 chrome 统一同步）

## 一句话模型

一个无头内核，里面跑多路工作空间、多路会话，经 EndChannel 连接多个显示端；
端自由切换空间、彼此独立、共享上下文与配置；对话先来后到（显式 FIFO）；
同时操作加原子锁。

## 分层（自上而下，依赖只能向下）

| 层 | 包 | 职责 | 不得依赖 |
|---|---|---|---|
| 显示端 | `cli` `ui` `matrix_client` `matrix_host` | 渲染、交互、审批展示，经 EndChannel/WS 接内核 | 内核私有状态（`_` 字段） |
| 内核 | `coara` | 回合编排、会话生命周期、输出路由、端注册表 | 显示端实现 |
| 执行 | `agent` `tools` `workflow` | ReAct 循环、工具、子智能体、工作流 | 内核、显示端 |
| 领域服务 | `records` `todos` `vault` `skills` `session_log` `workspace` `context` `background` `account` `llm` | 单一领域的数据与服务 | 内核、显示端、执行层（除自身消费的工具接口） |
| 基础原语 | `core` `runtime` `utils` | 零业务语义的公共原语 | 一切上层包 |

铁律：**支撑层与 core 严禁 import `coara`/`cli`/`agent`/`tools`**。
共享逻辑一律下沉为 core 原语，由上层各自薄适配，绝不反向引用。

## 内核不变量

- **单一写者**：一个会话的上下文只能由持有它的回合写，端只读视图。
- **输出归属 = 最近一次注入端**：段模型（segment）+ EndRegistry 统一路由，
  分界插在回合内两次 LLM 调用之间；CLI 永不显示它端正文。
- **先来后到**：多端输入经显式 FIFO turn 队列串行，不并行写同一上下文。
- **端独立（默认）**：CLI / Web / Matrix（及多路 attach）各持独立
  `view_workspace`，互不拖拽；聊天气泡、工具树、spinner、跟话回显、切空间
  chrome **一律按端**——它端发生的事默认不镜像到本端。内核只有平等的
  `WorkspaceSession`，**无**特权「全局前台」。「前台」= 该端当前 view；
  多端可共看同一空间（turn 串行，输出按 origin）。
  API：`set_view_workspace(end, name)` / `resolve_view_coara(end)`。
- **每段正文恰有一条投递通道**：流式路由与收尾补发互斥，防双发/防丢。
- **同空间少数共享事实**（不是「全内核全局」）：共看同一 `WorkspaceSession`
  时共享一份上下文与会话上的生效模型；任一端 `/model` 写该空间 last-run，
  **共看该空间的各端 chrome 立刻同步**。不同空间、未共看的端互不影响。
  janitor / 重启加载用空间 last-run。切空间、活动树、正文仍端独立。

## 输出归属：注入分段（segment）模型

**谁最后输入，后续内容送谁显示。** 每一次「用户输入注入上下文」（首次输入、或
turn loop 迭代头 drain 到接续输入）开启一个新**注入段**；段之后产生的所有输出
归属该段，直到下一个注入点（本批接续靠后的注入端赢）。CLI 永不显示其它端的段，
各端独立零镜像。

- **开段**：首段在 `process_message` 入口（`base.py`）；mid-turn 接续在迭代头
  （`turn_orchestrator.py`），段来源 = 本批注入最后一条交互端。
- **权威载体**：`coara._segments`（`segment.py:SegmentTracker`）→ `current.source`；
  开段同步写录像带 `record_segment_open(seq, source, turn_id, mid_turn)` 与
  `session_origin`。
- **归属规则分两类**：
  - **正文 chunk / 主会话工具 diff**：归属**当前段**（动态）——每次 LLM 回复
    都落在最新段。
  - **子智能体活动**（子智能体内部所有 edit 产生的 diff + 最终结果）：**全部固定
    归属一个端** = delegate 工具被调用时父会话的当前注入段。锚点是派发时登记的
    段来源快照（`subagent._subagent_origin`），**不随子智能体运行中用户换端漂移**
    ——一次派发的内容不分裂显示到多个端。哪次用户注入之后调用了 delegate，
    子智能体活动就送哪端。
- **实现贯穿**：delegate 派发登记段快照 → diff 由 executor 在 `tool_complete` 附带
  `subagent_origin`（CLI/web 按它过滤，手机 `diff_bridge` 按它路由）→ 最终结果由
  完成通知携带同一段来源（后台 payload / 前台 ToolResult metadata）→ 注入
  continuation 的 `agent_origin` → `turn_orchestrator` 归位 `subagent_sources`。
- **三端消费**：CLI `cli_shows_source(origin)` 本端才显示；web `origin=="web"` 才
  显示 diff 块与结果气泡；手机 `diff_bridge` 按 origin 路由。子智能体最终结果不走
  注入路径直推，统一由 delegate 经端 registry 帧路由投递，未命中时按发起端兜底同形态。

## 端/通道状态载体职责表（2026-09-16 收口，台账 #7）

「当前端」概念由四套载体表达，**权威域各自清晰、互不越界**；改任何一处前先看这张表，
判定谓词唯一事实源是 `turn_source.py`（显示门 `cli_shows_source`/`web_shows_source`、
族判定 `turn_source_family`/`same_turn_family`）。分派门（`continuation_leftover.py`）
与族判定的历史差异是有意的，勿统一。

| 载体 | 权威域 | 生命周期 | 备注 |
|------|--------|----------|------|
| `SegmentTracker`（`segment.py`，挂 `coara._segments`） | **输出帧路由**：正文/diff/工具帧按段 source+channel_id 经 EndRegistry 投递 | 会话级，随注入点推进 | 输出归属的唯一权威 |
| `EndChannel` ContextVar（`turn_context.py`） | **审批/交互通道**：审批送哪端、send_file/vault 旁路落点 | 协程 context 内单回合 | 回合收尾 `_active_turn_source` 置空后本载体仍持有来源（ws.py 显式依赖此时序） |
| `_active_turn_source`（base.py 实例字段） | **回合归属/可观测**：trace payload source、spinner/慢工具行跟随判定 | 单回合（入口置值、收尾置空） | 置空窗口是功能不是 bug |
| `session_origin`（base.py 字典） | **后台唤醒回投端**：background/event 唤醒回合的输出归属 | 会话级，最后一次真实用户输入端 | 与 `_last_user_input_source` 语义重叠但更新点不同（入队 vs 注入） |

规则：新增「按端分流」逻辑时先判定属于哪个权威域，只读对应载体；
**禁止**新引入第五套载体或绕过 `turn_source.py` 硬编码来源集合。

## 模型归属：空间统一（显示跟空间，不是跟端）

**段记「最近一次注入端」（显示路由）；空间会话记「当前生效模型」（执行 + chrome）。**
同一 `WorkspaceSession` 只有一份 `provider/model`：任一端切换即改该会话并写
last-run；共看该空间的其它端只刷新 chrome，不改自己的 view。

- **只算正常对话写 last-run**：cli/web/matrix/cli-attached 开段时
  `touch_entry_llm`；janitor / 后台 / 事件不更新。
- **端 `/model`**：作用调用端**当前 view 所在空间**的 session + last-run；
  回合中连接可延迟到回合结束，**显示立即同步**到共看该空间的各端。
- **`/model --global`**：只改全局默认（新/未绑定空间种子），不强迫已绑定空间。
- **同空间共享一份 provider/model**：共享一份上下文，跨模型交替接续会乱
  成本高且易炸协议；显示与执行都以空间会话为准。

## web 端数据载体（视图存储）

web 聊天区的唯一数据源是**服务端会话视图存储**（`ui/web_views.py`），不是录像带投影。
web 是**持久化展示系统**（与手机 app 同等级的数据模型），不是临时渲染层——端上显示的
每一条内容都必须有可恢复的持久化载体，刷新/切页/重启后与实时读同一份数据。

**存储模型**：每个会话一份 `<coara_home>/workspaces/<id>/web_views/{subject}__{session_id}.jsonl`，
帧协议 `{view_seq, turn_id, kind, source, session_id, payload}` 逐帧追加，`view_seq` 是
自增对账键（重启尾部校准，与录像带 seq 不同源）。

**帧类型与落盘覆盖（显示矩阵，缺一不可）**：

| 显示内容 | 帧 kind | 落盘路径 |
|----------|---------|----------|
| 回合起点/结束 | turn_start / turn_end | TurnStream 持久回调；web 跟话它端回合由订阅补 turn_end |
| 用户消息 | user_message | TurnStream.emit_user_message（新回合与跟话同一入口） |
| 正文（每条 chunk 帧独立气泡） | chunk | TurnStream（微批 150ms） |
| 工具 diff | diff | TurnStream → make_persist 映射 payload.diff（广播帧顶层 display_blocks/diff_lines 与落盘键分离） |
| 附件 | files | TurnStream |
| 错误 | error | TurnStream |
| 命令结果（/compact 等会话变更） | turn_start + chunk | `_persist_command_result_view`（独立回合） |
| 子智能体最终结果（web 派发） | turn_start + chunk | `_on_web_subagent_result_view`（订阅 continuation_input_injected） |

**读写分离**：广播帧（实时渲染）与落盘帧（持久化）共用 TurnStream，但字段语义分离——
广播帧顶层带 display_blocks/diff_lines 供前端/CLI 直读，落盘由 make_persist 统一映射
（如 diff → payload.diff）。两条路径不能各自漂移（历史教训：diff 曾因 payload 包裹
导致三端读不到、测试桩未走真实路径未暴露）。

**前端数据层**（`web/src/lib/store.ts` + `sessionCache.ts`）：
- 内存 store：实时回合帧驱动（`handleServerMessage`），逐帧与视图存储同构
- IndexedDB 秒渲染缓存：刷新首帧预览，永远可被 hydrate 覆盖（非权威）
- hydrate（GET /api/session/messages）：从视图存储聚合，seq 对账覆盖校正，
  保留未落带实时尾部（user/assistant/diff 去重防双显）
- 完整时序与多端矩阵见 [`docs/WEB_DISPLAY.md`](./WEB_DISPLAY.md)

**聚合规则**（`WebViewStore.build_messages`）：主会话逐帧输出（每条 chunk 帧独立气泡，
与实时渲染逐帧一致；diff 按帧序插入正文之间）；模块会话合并（其实时追加同一气泡）。
刷新后气泡划分、diff 位置、消息集合与实时完全一致——这是「稳定一致性」的验收标准。

**孤儿回合**（重启前进行中、无 turn_end）逐 chunk 显示并标 `recovered`：视图存储相对
录像带的核心增量（录像带保不住半途回合）。

## 端接入规矩

- 端经 EndChannel 通道收发，不直接读写内核 `_` 私有字段。
- 审批、渲染、对话展示全部外移到端；内核进程自己零渲染零弹窗。
- 新端接入 = 实现 EndChannel + 注册到 EndRegistry，不动内核回合循环。

## 防退化检查（改代码前自问）

1. 这个共享函数该在 core 还是只在当前层？（放 core 才能被下层复用）
2. 我是否在支撑层 import 了 coara/cli/agent/tools？（是 → 违规，下沉或注入）
3. 端是否碰了内核 `_` 私有字段？（是 → 在 Root/CoaraBase 加公共面收口）
4. 内核进程是否在自己渲染/弹窗？（是 → 旧单体残留，改走 EndChannel）
