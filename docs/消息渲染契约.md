# Web 显示与渲染契约

> **本文是 web 端显示链路的唯一权威**（渲染、刷新、顺序、折叠区、多端隔离、存储与快照、切空间时序）。
> 历史分册 `Web设计体系.md` §0 与 `WEB_DISPLAY.md` 已并入本文；两者不再各自表述渲染口径。
> 与代码不一致时**以本文为准并同步更新**；改渲染链路前先读这里。
>
> **一句话**：一条消息的**身份**（这是哪一条）与**位置**（排在哪里）是两个独立问题。
> 身份必须由**服务端键**唯一确定，位置必须由**线上序号（view_seq）**唯一确定；
> 端上只允许「到达得更快」，不允许「猜」，也不允许「留得更久」。
>
> **第二句话（I8，硬要求）**：气泡一旦上屏，位置就固定——后续任何事件（实时帧 / 增量对账 / 重连回放 / 同文再发）只允许 ① 尾部追加新行、② 就地改某行内容；**不允许改变任何已显示行的相对顺序，也不允许整行重挂**。顺序重建只允许发生在「整条线重建」那一次（刷新全量重取 / 切空间 / epoch 变），且重建后必须等于 `view_seq` 升序。

**单一事实**：屏幕上的一切只有一个来源——该空间的视图带（服务端权威）+ 它此刻的 runtime。端侧的一切手段（UI state、乐观回显、滚动锚）只允许用于「更快更稳地到达这份事实」，**不得成为第二份真相，更不得先行上屏**。

- **允许慢，不允许跳。** 宁可等权威数据回来一次到位，也不用可能过期的本地副本先铺一屏再被覆盖。加载期间该空就空、该显示骨架就显示骨架。
- **判据**：任意时刻把端上显示与该空间视图带按 `view_seq` 前缀比对，必须一致；不一致就是 bug，不必再分「缓存旧了」还是「合并漏了」。
- **豁免：本端动作的即时回显不算第二份真相。** 自己发的消息（乐观气泡）与正在流式生成的正文可以先上屏——它们表达的是「我做了什么」，不是「服务端已经是什么」；权威数据到达后必须被**等价替换**（同一条内容不变成两行）。除此之外的持久内容，端侧不许自行合成。

## 一、不变量（硬约束）

| # | 不变量 | 可执行判据 |
|---|--------|-----------|
| I1 | **身份唯一**：同一条消息在列表里最多一个 item | 合并优先级 `seq` → `clientMsgId` → 内容 key（`_mergeSnapshotRows` 一对一枚举） |
| I2 | **追加即冻结**：新内容只能追加在尾部；已显示行**永不被重排、跨位搬移或删除** | `_appendRow`（唯一追加入口）；`_mergeSnapshotRows` 命中既有行只改内容 |
| I3 | **两条落定通路**：① 追加（实时帧 / 回放帧 / 认领 / 命令输出）；② 对账（快照：命中即改内容、命不中追加尾部）。整表重排只在**整线重建**（`replace`） | `_sortBySeqAsc` 只被 `_mergeSnapshotRows(replace=true)` 调用 |
| I4 | **键稳定**：item key 与滚动锚键取服务端键（内容行 `s<view_seq>`、工具行 `t<tool_call_id>`、diff 行 `d<tool_call_id>`、带端上标识的用户行 `c<client_msg_id>`）；本地 uuid 只在「尚无服务端键」时兜底，拿到键的那一刻就地升级 | `store.ts::chatRowKey`；`MessageList` 的 `key` 与 `data-msg-key` 同源 |
| I5 | **隐藏即不存在**：可见性过滤必须先于间距 / 缩进 / 计数 / 邻接计算 | 插入任意条隐藏工具行，可见行的间距与折叠区计数逐字不变 |
| I6 | **端上零猜测**：不从正文文本推身份、位置或类型 | 渲染层不出现「按文本前缀判类型 / 判归属」的分支（认领的文本兜底只影响「配到哪一行」，不改变顺序） |
| I7 | **状态出口**：store 里写下的用户可见字段，必须既有渲染分支、又在 memo 比较器名单里 | 逐字段核对 `ChatMessage` ↔ `MessageBubble` |
| I8 | **已显示前缀不变式**：任一非重建落定后，已显示前缀的服务端键、内容与相对顺序**逐项不变**，新行只出现在末尾 | `store.selftest.ts`「已显示前缀不变式」块；整线重建后顺序 = `view_seq` 升序 |
| I9 | **子智能体产出不投影**：子智能体的任务指令、过程、最终结果一律钉在发起它的 delegate 工具行里，**不进主消息流** | 快照三张映射 + 实时帧 `parent_tool_call_id`；回归 `tests/test_ui/test_subagent_frame_leak_guard.py` |
| I10 | **注入信封不上屏**：内核注入内容（`<后台结果>` / `<系统提醒>` / `<子智能体消息>` 等预格式化信封）只给模型看，三端显示出口一律拦截 | `is_preformatted_injection`；三端出口回归 |

## 二、一条消息的完整生命（7 步）

| # | 环节 | 所在 | 关键点 |
|---|------|------|--------|
| 1 | 端上生成即时气泡 | `lib/store.ts` `addUserMessage` · `views/ChatView.tsx` `sendChat` | 生成 `clientMsgId`（身份）+ 乐观气泡（无 seq）；位置=列表尾部 |
| 2 | 发送 | `lib/ws.ts` `ClientMessage.chat` | 帧带 `text / attachments / workspace_dir / client_msg_id` |
| 3 | 内核受理 | `src/ui/web_server.py` `_handle_chat` | 绑定回合与空间；`emit("user_message", …)` |
| 4 | 落带并分配序号 | `src/ui/turn_stream.py` `_record` → `src/ui/web_views.py` | **先落带后广播**：persist 分配 `view_seq` 并写回帧；序号同线永久单调 |
| 5 | 端上接收与裁量 | `store.ts` `handleServerMessage` | 边界守卫（workspace/session）→ 行存在性去重（序号已在屏上 ⇒ 整帧丢弃）→ 类型分派 |
| 6 | 落定（只有两条路） | `store.ts` `_appendRow` · `_mergeSnapshotRows` | ① 追加落定：尾部加一行（同序号幂等，已显示行不动）；② 对账落定：命中既有行只改内容、命不中追加尾部。整表按 seq 重排只发生在整线重建那一次 |
| 7 | 渲染 | `features/chat/MessageList.tsx` · `ToolLineRow.tsx` | 一行一项，key 取服务端键；类型按优先级分派；折叠区是该 item 的内部渲染 |

**渲染分派优先级**（`MessageList.tsx`）：分隔线 → 命令卡 → 工具行（隐藏则 `null`）→ diff 块 → 撤回行（`retracted`，不画）→ 空 assistant 行（`queued` 时画排队占位，否则 `null`）→ 普通气泡。

列表项只有一种：`ChatMessage`；「分组」是渲染期纯函数现算（`toolLineGroups` / `toolVisibility` / `diffPairing`）。隐藏行**只不画，仍在数组里占位**——删行会让它后面的行上移一格（跳）。

## 三、一条入屏通道

**事实的形状**

- 视图带（每空间一条 JSONL）是内容的唯一权威，逐帧带 `view_seq`——该线内单调递增，落盘时分配
- 快照接口返回 `{messages, latest_seq, epoch, workspace_dir, session_id, runtime, 三张折叠映射}`；`epoch = "{workspace_dir}::{subject}[#世代]"` 标识「哪条线」

**通道规则**

- 屏幕内容只由两种输入驱动：**快照**与**实时帧**；两者都必须携带 `workspace_dir`、`session_id`、`view_seq`，由端上同一个 reducer 应用
- 端侧合成的持久内容、无归属的直推帧、第二份历史接口，一律删除
- 端上只留 UI state（滚动位、展开态、草稿）与乐观回显（自己发的气泡、流式正文）

**订阅先于快照**

1. 进页面（刷新 / 切空间）时先在 WS 上订阅（连接即订阅，帧先入缓冲，上限 300；溢出优先丢「能从快照补回」的落带帧）
2. `state` 帧把 `workspaceDir` / `sessionId` 落定 → 缓冲按 `view_seq` 排序后回放（无序号帧排最后）
3. 快照落地后：丢弃 `view_seq <= latest_seq` 的帧，按序应用其余，**最后一次提交上屏**

**帧的裁量 = 行存在性**（`_hasRowWithSeq`）

| 情形 | 处理 |
|------|------|
| 行已在屏上 | **整帧丢弃**（实时 / 重连回放 / 快照三路都会送同一帧）；不产生行的状态帧（`turn_end` 等）照常放行 |
| 行不在屏上 | 走落定路径：正常帧尾部追加，迟到帧同样尾部追加 |

不设游标闸门、不做 gap 检测。「缺内容」由重连 / 刷新时按屏上最大 seq 减 50 补后缀承担（`topUpAfterReconnect`）。旧机制（三走向序号闸门、空洞缓冲、退避重试、按文本判重、`gateReady`）**已全部删除**。

**原子提交**：内容、runtime、线身份、折叠区在同一次状态提交里落定，中途只显示骨架。禁止「先渲染一半再补齐」，禁止「先铺旧内容再校正」。

**丝滑的正当手段**（都是「更早到达事实」，不是替代事实）：切换动作发起时并发预取目标空间快照；常驻 shell（只换内容区）；带 `after_view_seq` 的增量快照。

## 四、顺序不变量与落定（三条机制）

1. **内容行带序号**：落带的每一帧都由服务端分配 `view_seq`（同线永久单调），端上把序号挂在发生它的那一行上。
2. **追加即冻结**：任何一次状态落定只做**尾部追加**与**就地改内容**——已显示行的 id 与位置一律不动；同 `view_seq` 的行存在即幂等丢弃。整表重排（落带段按 `view_seq` 升序、未落带实时尾部按到达序排在其后）**只在整线重建那一次**发生。
3. **回放先排序**：边界缓冲回放入口先按 `view_seq` 排序，无序号帧保持到达序、排最后。

端上 `messages` 必须始终满足：落带段（带 `seq`）按 `seq` 升序；未落带实时尾部（无 `seq`）按到达序排在落带段之后。

| 会破坏它的路径 | 为什么危险 | 防线 |
|---|---|---|
| 迟到帧直接 append | 序号可能小于已渲染内容的最大序号 | 允许追加尾部（「上屏即冻结」的代价），位置在下次整线重建时按 `seq` 纠正；同一序号绝不重复上屏 |
| 边界缓冲回放按到达序送 | 先到的后帧与迟到的前帧交错 | 回放入口先按 `view_seq` 排序 |
| 增量 hydrate 整体追加 | 游标可能偏（他端动过、上一页生命的残留） | 同 `seq` 的行原地替换（id 与位置不变），只追加真正新增的行 |

## 五、折叠区契约：子智能体产出钉在发起它的那条 delegate 行里

子智能体的三个产出面（任务指令 / 过程 / 最终结果）都**不是主对话正文**，属于发起它的**那条 delegate 工具行**。**归属键由服务端给，端上只按归属键归集**，不允许从文本里猜归属。

| 映射（快照顶层字段） | 形状 | 归属键 | 来源帧 |
|---|---|---|---|
| `subagent_results` | `{tool_call_id: text}` | 子智能体任务 id（= delegate 工具行的 `tool_call_id`） | 落带 `kind=subagent_result` |
| `subagent_briefs` | `{父 call_id: 指令全文}` | 发起它的 delegate 行 call_id | `user_message` 帧带 `delegate_brief`（老数据 `delegate_task` / 正文以 `<任务指令>` 开头） |
| `subagent_diffs` | `{父 call_id: [帧…]}` | 同上 | 带 `parent_tool_call_id` 的 `tool` / `diff` 帧 |

- **不投影成消息**：`build_messages` 不把这三类帧投影成聊天行。落成气泡＝刷新后凭空多一条回复，且指令气泡会假扮用户输入。
- **过程正文同样钉在 delegate 行**：`subagent_chunk` **一律落带**（刷新 / 断线回放靠它），读端按 `parent_tool_call_id` 归集进 `subagent_texts[父 call_id]`，**不投影成主会话消息**。落带与投影是两件事：进带 ≠ 上屏。
- **缺父标识即不发**：任何子智能体帧（`subagent_chunk` / `subagent_result`）若缺 `parent_tool_call_id`，三端出口一律丢弃并记 WARNING——宁可丢，也不能退化成主会话正文。回归见 `tests/test_ui/test_subagent_frame_leak_guard.py`。
- **实时与快照同一套键**：WS 帧带 `parent_tool_call_id`，快照带上面三张映射；两端按 `view_seq` 去重后并进同一张表——刷新前后展开区内容一致。
- **手风琴组序固定**：任务指令 → 过程 → 最终结果（组名以此为准，判据在 `toolLineGroups.ts`，selftest 逐字断言）。**过程组**把同一件事的三个来源合成一条时间线：① 落带帧（子智能体自己的工具行 / diff，按 `view_seq` 升序）→ ② 活动树里「帧还没有的行」（在跑的工具）→ ③ 过程正文（`subagent_chunk` 累积的那段，排最后、不带标签）。①② 按 call 去重、**以帧为准**。计数合成一条（项数＝帧数 + 补进来的树行数，另有正文时追加 ` · X 字`）。最终结果独立成组并带标签。空组不出现；一组都没有则该 delegate 行不可展开。默认：任务指令收起，其余展开。组内限高、面板限高，超出组内滚动。折叠区内 diff 用顶格变体，左缘与同组工具行、过程正文对齐；活动树补给行保留 `depth` 缩进。
- **隐藏的过程噪音工具行（三端同一清单）**：真源是 `docs/protocol/coara-envelopes.json` 的 `display_rules`，生成三端常量（`src/core/display_rules.py` · `lib/displayRules.generated.ts` · Android `DisplayRules.kt`）。四条：`delegate wait`（同步点不是工作，一回合可能出现几十次）、`send_file`（效果是那一端的文件/图片卡片；CLI 端不会调用它、没有文件接收能力）、`todo park`（效果就是 park 的 message 气泡）、`plan` 的 action=plan 一种（它的效果就是计划审阅气泡本身；enter / exit 是模式开关，要上屏）。**只在渲染层过滤**：行照旧写在视图带里、照旧参与顺序不变量与快照对账，只是不画；折叠区条目与计数同样排除。取向「认不出来就不隐」。回归：`tests/test_ui/test_display_rules_shared.py`。
- **封顶**：快照的折叠映射只回游标之后的帧，call_id 数封顶 30、单 call 帧数封顶 100；端上再随消息窗口回收（只留 messages 里仍有该 delegate 行的 call、活动树在跑的 call，以及最近 8 个出现过 call）。
- **实现单一真源**：分组判据 `src/ui/web/src/lib/toolLineGroups.ts`（纯函数，selftest 直断言）；行渲染 `features/chat/ToolLineRow.tsx`（聊天流与折叠区共用一份）。

## 六、多端隔离与显示归类

**零镜像（硬约束，不设例外）**：每一端只显示归属自己端的产出——web 只显示 web 段的回合产出，CLI / 手机回合不进 web 气泡；子智能体的任务 / 过程 / 结果只投**发起它的那一端**，共看同一会话时各端只看自己发起的那部分。同空间时正文按段归属，跟话另起段。归属只有两把尺（[三端运行显示出站.md](./三端运行显示出站.md)）：**当前段**（谁最后注入，主会话产出跟谁）与**启动／发起端**（子智能体过程与结果、后台运行与完成、审批与文件，钉死不漂移）。

| | 端可以不一样 | 共看同一空间才一致 |
|--|-------------|-------------------|
| 例子 | 气泡、工具行、活动树、spinner、切空间 chrome、折叠展开态 | `message_history`、生效模型 + 顶栏模型显示、该空间 `/new` 后的 session |

**显示规则矩阵（主会话 `subject=root`）**

| 内容类型 | Web 聊天区 | CLI attach | 手机 |
|----------|------------|------------|------|
| 用户气泡 | `source=web` | 本端 | 房间 |
| assistant 正文 chunk | `isWebSource` | `cli_shows_source` | 段归属 + 角色前缀 |
| 工具行 | 聊天流内联一行 | scrollback | 房间（`[COARA_TOOL]`） |
| edit diff | `source=web` | diff 面板 | `[COARA_DIFF]` |
| 子智能体任务指令 / 过程 / 结果 | ✗ 折进 delegate 行展开区 | 折叠块 | `[COARA_SUBAGENT]` 折进 delegate 行 |
| 注入信封（后台结果、系统提醒…） | ✗ 不上屏 | ✗ | ✗ |
| janitor / daily | silent | silent | silent |

**走 `isWebSource` 门的 WS 类型**：`user_message` · `turn_start` · `turn_queued` · `chunk` · `turn_end` · 侧栏 `tool_*` · `diff` · `tool`。
**不走此门**：`command_result` · `continuation_input_injected` · `chat_turn_retracted` · `state` / heartbeat。

**跟话（web 在它端占回合时发消息）**：跟话 `user_message` 与开局用户行同形（同一 `TurnStream.emit_user_message`，含 `client_msg_id` / `attachments`），经微批时间线落带并广播；随后 `submit_continuation_input(source=web)`，后续 chunk 按段归属经 TurnStream 投递。前端每条 chunk = 独立 assistant 气泡（不续写旧泡）。

**出口唯一**：web 帧进入聊天区只有一条路——`web_server.py::_emit_end_frame`（kind 分派 + 注入信封闸 + 父标识折叠）。跟话流、唤醒回合流的 sender 一律复用它，**禁止再手写窄化映射**（历史事故：旁路 sender 只认 diff/tool，其余帧一律当正文，子智能体内容因此落成主消息气泡）。

## 七、服务端存储与快照

| 项 | 说明 |
|----|------|
| **路径** | 主对话：`<coara_home>/workspaces/<id>/web_views/conversation.jsonl`（**一个空间一条线**，`session_id` 不参与命名；`/new` 只是线上一个分隔帧）。模块会话：`web_views/{subject}__{session_id}.jsonl` |
| **写** | 唯一写入口 `view_recorder.record_view_frame` → `WebViewStore.append_event`（异步批量写，失败只记日志、绝不中断回合） |
| **读** | `GET /api/session/messages` → `handlers/session.py::_load_view_snapshot`（**唯一构造点**，切空间响应用同一个） |
| **对账键** | `view_seq`（快照 `latest_seq` / 端上 `hydratedSeq`） |
| **单调** | 同一条线内 `view_seq` **永久单调、不重置**：取「jsonl 尾部最大序号」与「sidecar 高水位」较大者 +1；文件被归档 / 清空 / 截断都不回退。重置只有 `WebViewStore.reset_line` 一条合法路径（世代 +1 → epoch 变化） |
| **与录像带** | `session_events.jsonl` 为全端冷备/审计；web 聊天区**不读**录像带投影 |

**帧类型**：`turn_start` · `user_message` · `turn_queued` · `chunk` · `tool` · `diff` · `files` · `error` · `divider` · `subagent_chunk` · `subagent_result` · `turn_end`。

**快照形状**：`{messages, total, latest_seq, workspace_dir, session_id, epoch, subagent_results, subagent_diffs, subagent_briefs, runtime}`；`limit` 默认 100、上限 500；`after_view_seq` 走增量；`workspace_dir` 走只读预取。`runtime` 与消息同源回来——刷新与切空间走同一条路径、同一份权威，不靠心跳推送。

**落带路径**：主路径是 `web sender → TurnStream._record → WebViewStore.append_event`（含 standby 流）；旁路只有 delegate 的两处直接落带（任务指令帧、无通道时子智能体最终答复的兜底），且互斥、必带 web 源守卫。落带先于广播——帧先拿到 `view_seq` 再发出去，端侧因此能与快照 `latest_seq` 对账。

**无在飞回合流时用 standby 流**：连接级兜底 sender（全局槽 `(web, "")`，只注册不注销）按帧归属找回合流，找不到就按 `(session, workspace)` 建/复用一条 standby `TurnStream`（不挂 task、不进 `_turns`），走同一条 `_record`。上限 `_MAX_STANDBY_STREAMS = 8`。

**微批**：`chunk` 与 `subagent_chunk` 在 **16ms** 窗口内合并成一帧（后者按 `tool_call_id` 分桶，每条 delegate 行一桶）。

**WS 首帧只带 runtime**：心跳每 5s 只推轻量 runtime（`session_id` / `workspace_dir` / turnActive / 占用端 / 会话花费），不投影全量 sessions。会话花费含子智能体消耗，token 与缓存命中率仍只算本会话自身；「占用」与「会话花费」只画在右侧 `StatusSidebar`。

## 八、刷新 / 切空间 / 断连时序

**原子提交**：`loadHistory` 的 commit 是**一次** `set`：`messages`（已过顺序归一）+ `hydratedSeq` + `lineEpoch` + `runtime` + 折叠区三映射。分两次 set 就是「先渲染消息、再补 spinner 与展开区」＝跳变。

**切空间：一次往返**。`POST /api/workspace/switch` 的响应直接带目标空间的权威快照（与 `/api/session/messages` 同源同形状）——端上「清边界 → 就地提交快照」一步完成，一次切换只出现两种画面：骨架 → 目标内容。

**分隔线的口径（三端不同，刻意如此）**：

| 端 | 切空间画线 | 理由 |
|---|---|---|
| web | **不画** | 不同空间就是不同页面，整页重建即天然分隔 |
| CLI | **画** | 单屏连续 scrollback，所有空间混在一条流里，需要视觉分隔 |
| 手机 | **画** | 同一个房间承载全部空间，同样需要分隔 |

「新会话」三端都画一条。

**hydrate**：请求带 `workspace_dir`（只读预取，不动运行时状态）；已有游标与内容时走增量 `after_view_seq = 屏上最大 view_seq - 50`（起算点是**屏幕上已覆盖到的最大 seq**），只补后缀；增量返回的 `epoch` 与本地不同 ⇒ 本次作废改走全量。

**进行中回合断连**：回合与 WS 解耦——`TurnStream` 在服务端继续跑，重连后 replay 尾部 + 快照已落带部分，两端按 `view_seq` 行存在性去重（同 seq 的行原地替换，绝不重复上屏），并按最大 seq 减 50 补拉尾部。

## 九、渲染与性能约定

优化不得破坏 I1–I10；任何「更快」的手段都以「已显示前缀不变」为前提。

| 项 | 约定 |
|---|---|
| 渲染窗口 | DOM 里固定最多 120 行（`MAX_RENDERED_MESSAGES`）。看更早内容靠**窗口上移**（`win.end` 是窗口右端的绝对行号：「加载更早消息」一次上移 100 行；到最早行时入口显示「已到最早」并禁用），不加深窗口。用户读历史时新帧不推动窗口；出现过「回到最新」按钮（手动滚到底也自动归位）。窗口绑定 `workspaceDir + sessionId`，切空间 / 新会话回到贴底窗口 |
| 行级跳绘 | 每行外层 `content-visibility: auto` + `contain-intrinsic-size`；只影响屏外行的布局与绘制，不改变行顺序（I8 不受影响），滚动条总高为估算值 |
| 输入区隔离 | `ChatInput` 与 `MessageList` 走 `memo`，传给它们的回调必须 `useCallback` 固定引用；心跳类高频状态（runtime）订阅**下沉到叶子组件**，不得挂在页面级（否则每次心跳重建整张列表） |
| 滚动 | 监听用 `passive` + rAF 合并，一帧最多量一次几何；不在一次回调里反复读写 `scrollHeight` |
| 派生计算 | 活动树 `rows()` 带版本缓存（结构未变返回同一数组引用）；工具行用 `useStore` 选择器直取自身相关派生值，不订阅整表 |
| 热路径 | 行存在性判重维护 `Set<number>`（O(1)）；重复自检在生产构建下降频；`computeMsgKey` 不用 `JSON.stringify` 做身份 |

## 十、打开 / 唤起 Web UI：两态判定

**规则只有两条**：没有标签就开新标签；已有标签（有活跃连接，或留存记录未过期）只抬窗 + 推 SPA 导航，**绝不开新标签**。

| 态 | 条件 | 动作 |
|----|------|------|
| `focus-active` | 本进程有活跃 WS 连接 | 推 `focus_window` + 系统层置前，不开窗 |
| `focus-recent` | 无连接，但最近有标签（跨内核重启记得、含被冻结的标签） | 只置前 + 推 focus，等它重连；等不到也只抬窗 |
| `open` | 没有活跃连接，且留存记录过期 / 从未有过标签 | 才 `webbrowser.open` |

标签留存记录落 `<workspace_home>/runtime/web_tab_presence.json`（信号：WS 建立、前端心跳、标签关闭 `bye`；判定 `last_seen_at > last_bye_at` 且未超 TTL）。**唯一入口** `GET /api/ui/open`（判定+动作都在内核侧）；`/api/ui/focus` 只做唤起判定、永不开窗。回归：`tests/test_ui/test_web_tab_presence.py` · `test_web_ui_open_window.py`。

## 十一、已知限制与仍是「猜」的地方

| 位置 | 现状 |
|------|------|
| 用户消息认领 | 首选 `client_msg_id`；无标识的老带靠内容 key 兜配（配不中则追加，宁可多一条也不删 / 搬已显示行） |
| 任务指令识别 | 老帧按正文前缀 `<任务指令>` 认 |
| 分隔线身份 | 命令输出前缀才升级为时间线分隔线 |
| 活动树父归属 | 无 `parent_tool_call_id` 时「恰有一个活跃 delegate」就认父 |
| 树行 label | TS 版与 Python 侧 label 格式不同源 |
| 附件挂位 | 找最后一条 user 行，再找其后 streaming / autoCreated 的助手行 |
| 迟到 / 补齐的行 | 只按到达序落尾部——它在历史里的正确位置暂时是错的，直到下一次整线重建按 `view_seq` 纠正 |
| 同文重复残余窗口 | 权威行既无 `client_msg_id`、内容 key 又对不上时，屏上会短暂出现两条同文行，直到权威帧到达就地认领 |
| 实时路与落带路不同构 | `divider` 只落带不广播；实时 `file` 帧的 kind 名与 seq 与落带 `files` 尚不统一；`command_result` 实时无序号而落带被投影成 `turn_start + chunk`；刷新后形态会变一次 |
| 条数常量 | 刷新取 200（前端）、切空间快照取默认 100（服务端）——同一把尺两个数 |
| 折叠区封顶 | 超 30 个 call / 单 call 超 100 帧的历史子智能体产出刷不全 |
| 纯图片跟话 | 靠文本匹配清徽标，空气泡可能清不掉 |
| 骨架态 | `viewReady` 表达「本空间内容是否已由权威快照落定」；超阈值给明确文案与重连入口 |
