# 空间切换设计

切空间是三端交互里最容易出错的一类动作：它同时动「服务端视图指针」「端侧显示态」「在飞回合的归属」三样东西，且由两次异步往返驱动。这份文档把不变量、链路、状态清单与失败模式钉死，改动前先对一遍。

## 一、不变量

1. 空间之间互不影响。一个空间里发生的事（说话、工具、新会话、空闲自动收尾）不得改变另一个空间的会话、显示或归属。
2. 动作自带归属。消息与命令携带「在哪个空间发出」，服务端按归属绑定回合；「端此刻在看哪个空间」这个指针只是解析失败时的退路。
3. 归属双键。帧上必须同时带 `session_id` 与 `workspace_dir`；端侧两个键都核对，任一不符即不消费。
4. 显示必落带。进入视野的内容必须先写进该空间视图录像带，再谈实时投递；实时通道不可达时正文仍落带。
5. 显示态成套。一个空间的显示态是五项一体：`messages` / `hydratedSeq` / `turnActive` / `currentTurnId` / `sessionId`。缺任何一项都会以「跨空间串键」的形式炸出来。

## 二、容器级隔离（早已成立）

- 会话按空间分开：`RootCoara._sessions[workspace_id]`，每个空间一份 coara、工作目录、session_id。
- 回合并发：会话内串行（每个 coara 自己的 `_process_lock`），空间之间并行；web 端另有同空间 FIFO（`_turn_tails`）。
- 输出寻址：端注册表键为 `(端, session_id)`；连接级兜底槽 `(web, "")` 靠帧归属分流。
- 录像带：每个空间一个 `workspaces/<id>/web_views/conversation.jsonl`。
- 空闲自动 /new：按 `workspace_id` 各自计时，只重启那一份会话。

## 三、切空间链路

服务端（`POST /api/workspace/switch`）：

1. `root.set_web_view_workspace(name)` —— 只换本端视图 pin，不动全局前台（CLI、手机、保险柜、占用、cwd 无副作用）。
2. 刷新自己的 trace store 与 `workspace_dir`。
3. 向活跃连接推 `state`：runtime 含 `workspace_dir` / `session_id` / `status` / `running`（= 视图 coara 的 `has_active_turn()`）/ `turn_source`。
   注意：runtime 快照未变时**不推送**，所以端侧不能依赖「切换必有推送」。

端侧（web）：

1. 收到 `state` → 比对 session 与 dir；只有 dir 变了才算真切。
2. `resetForWorkspaceSwitch(newDir)`：
   - 存走当前空间整套显示态（五项）进按空间缓存；
   - 恢复目标空间缓存（缺项按默认：空线、游标 0、空闲、会话键置空——**绝不继承上一个空间的会话键**）；
   - 递增 `hydrateGeneration` 作废在飞 hydrate；清活动树与侧栏事件。
3. 会话键以推送的 `newSid` 为准覆盖一次。
4. `ChatView` 见 `workspaceDir` 变化 → 增量 hydrate：`/api/session/messages?after_view_seq=<游标 − 50>`，按 `seq` 合并（同 seq 原地替换、新行追加），游标漂了也能自愈。
5. 之后到达的实时帧逐帧过边界守卫；不属于当前空间的帧不渲染，但若它是 `turn_start` / `turn_end`，会把那个空间的回合态（并按帧上的 `session_id` 刷新它的会话键）写回它的缓存。

CLI（attach）：连接注册时钉 `workspace_id`，回合按它取会话；出站按 `workspace_id` 过滤（不是本连接的流一帧不消费），pin 稳定，窗口极小。

手机（Matrix）：视图 pin 为 `_matrix_view_workspace_id`，回合流带 `workspace_id`，命令按视图解析；pin 由房间/视图驱动，同样稳定。

## 四、失败模式与修法（都踩过）

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 跨空间串显（A 的输出画到 B） | 帧不带 `workspace_dir`，端侧守卫拿不到输入只能放行 | 内核出帧统一盖 `workspace_dir`；端侧守卫严格（缺字段也不放行） |
| 正文凭空消失 | 端通道注册键与路由键不同源；连接级兜底槽被回合收尾注销 | 注册键与路由键同源；连接级通道打标不可注销；正文不可达时落带 |
| 切回来丢 spinner / 丢输出 | 缓存的显示态漏存会话键，恢复时回落到上一个空间的会话键 | 缓存带 `sessionId`；缺值置空；别的空间的帧顺手刷新它的会话键 |
| 切走期间回合结束，切回来凭空有 spinner | 那个空间的 `turn_end` 被边界守卫丢弃，缓存永远写着「在跑」 | 守卫丢弃处记账：把别的空间的回合态写回它自己的缓存 |
| 切空间窗口内发的消息落到错空间 | 服务端按「到达那一刻的视图指针」绑定 | 消息与命令自带 `workspace_dir`，服务端认归属 |
| 分隔线出现在错的位置 | 触发源太多（切空间、发消息、模型切换、时间空档） | 只保留「新会话」一条线：服务端落帧、端侧本地插线、回放还原、时间取帧 `ts` |

## 五、仍是单例，待收

- 端侧审批/保险柜弹窗、斜杠命令 spinner：全局一个，跨空间可能浮错地方。
- 内核全局前台指针：只应服务 CLI 行为；凡 web 路径读到它的地方都是隐患（已清：新会话分隔帧改用视图 coara）。
- 共享资源：provider 额度、工具沙箱、文件投递桥——影响排队与限流，不影响归属。

## 六、判据：刷新与切换同一把尺

不管刷新还是切换，目标只有一个：**任何时刻，端上显示的就是这个空间、这个页面当下该有的那份事实。**

- 事实只有一份：该空间的视图带（逐帧落盘的那条线）+ 它此刻的 runtime。
- 端侧一切手段（内存缓存、IDB 预览、增量拉取、seq 合并、滚动锚）都只服务于「到达这份事实」的过程不闪不跳，任何一个都不许成为第二份真相。
- 可验证性：任意时刻把端上显示与该空间录像带 + runtime 对一遍，必须一致。不一致就是 bug，不必再分「缓存旧了」还是「合并漏了」——那只是同一错误的不同表现。
- 由此两条硬约束：显示必落带（先落带再投递，否则「实时该有的样子」无从定义）；端侧不合成持久内容（只允许乐观用户气泡与流式正文，且落带后必须被等价替换，不留幽灵）。

刷新是极短间隔，切换是长间隔，走的是同一条路径、同一份权威。增量、合并、预览都只是手段，不是目标。


## 七、验收清单

1. 切走 → 切回：spinner 与后续输出都在。
2. 切走期间那个空间回合结束：切回不出现假 spinner，内容完整。
3. 切空间窗口内发消息 / 发命令：落在发出时的空间。
4. 两标签同空间：互不顶替。
5. nx ↔ 暄 双向来回：会话键、游标、回合态各自独立，不互串。
6. 新会话点一次：出现一条带时间的「新会话」线；其余动作一律不出线。
