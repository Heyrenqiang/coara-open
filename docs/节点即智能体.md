# 节点即智能体：工作流节点模型

> **Canonical**：工作流节点模型以本文为准。
> **注意（2026-09-08）**：执行层已剥离为独立 WDL 软件（仓库顶层 `wdl/` 子项目）。本文中的引擎实现引用（`src/coara/workflow_engine.py`、`src/workflow/core/`）已迁移至 `wdl/src/wdl/`，概念模型仍然有效，代码路径以 wdl 包为准。
> WDL 格式权威规范见 [`WORKFLOW_SPEC.md`](./WORKFLOW_SPEC.md)；引擎整体架构见 [`../wdl/README.md`](../wdl/README.md)。

---

## 1. 核心理念

> **节点即智能体。** 工作流图里只有一种节点：智能体节点。每个节点运行时都是一个完整的 `CoaraBase` 实例——拥有身份、工具循环、技能、守卫、trace、压缩、打断回滚，与 Root / delegate 子智能体同构。节点不是写死的脚本，而是会自主思考、调用工具、产出结果的智能体。

2026-08-16 起工作流收敛为单一内核：**图是唯一契约，节点只有一种**。并行、汇聚、分支、循环、重试都不是节点种类，而是图的形状（扇出 / 扇入 / `routes: one` / 回边 / `on: error` 边）。图上没有 if/for/while/parallel/wait/merge 节点，没有独立数据边。

---

## 2. 内核图模型

工作流由一张**图**描述（`src/workflow/core/model.py` 的 `FlowGraph`）：

| 组成 | 字段 | 说明 |
|------|------|------|
| 节点 `Node` | `id` / `task` / `input` / `routes` / `max_activations` | 节点 = 智能体：`id` 即身份名，`task` 是完整任务指令（目标/范围/方法/规则/验收/回报格式），`input` 是数据进模板，`routes` 是出边路由模式（`all` 缺省 / `one`），`max_activations` 是节点级激活上限 |
| 边 `Edge` | `from` / `to` / `on` | 边 = 唯一拓扑：`on` 缺省 `success`（正常完成投递），`on: error` 表示失败时投递（重试/兜底路由） |

WDL 文本就是这张图的**canonical 序列化投影**（`src/workflow/core/serde.py`）：固定键序、省略默认值、节点按 id 排序、边按 (from, to, on) 排序。`parse(emit(g)) == g` 逐字段恒等。图长什么样，文本就是什么样，不存在两套写法。

### 2.1 投影示例

```yaml
name: research_and_write
description: 调研主题后撰写报告

nodes:
  research:
    task: 调研主题并产出结构化要点
    routes: one
  write:
    task: 基于调研撰写报告
    input: "{{steps.research.text}}"

edges:
  - { from: research, to: write }
```

### 2.2 激活语义

- **首激活**：节点要等它全部"必需等待"边各有一个到达才动（源节点等待集为空，立即可激活）。
- **再激活**：回边（成环）与 `on: error` 边是"机会性触发"——上游完成即投递到达，节点再次激活。
- **路由**：`routes: all` 广播给全部出边；`routes: one` 每次激活只选一条——交互宿主（FlowCoordinator）由节点运行期 `report(next=…)` 挑，无人值守宿主按静态顺序取第一条。
- **上限**：每节点激活次数受 `max_activations` 约束（节点级覆写全局默认 100），触顶即失败终态。**图允许任意回边，循环终止由上限兜底**——循环边界显式、确定。

## 3. 节点执行与 delegate 池

引擎侧节点执行器 `_kernel_node_executor`（`src/coara/workflow_engine.py`）把每个节点当完整子智能体跑：

```text
内核图节点执行（WorkflowEngineRuntime._kernel_node_executor）
├── 构造 WorkflowNodeAgent（persona = {name: node_id, role: node_id}，
│       meta_task = 节点 task，profile = "delegate"）
├── _execute_delegate_node
│   ├── 计算池键：workspace | persona | meta_task | provider | model
│   ├── 从 delegate 池取空闲 CoaraBase 实例
│   │   ├── 命中 → start_new_session()（清掉上一步的对话历史）
│   │   └── 未命中 → 新建 CoaraBase + bootstrap_tools() + load_skills() + initialize()
│   ├── 构造 prompt（任务指令 + 【输入】模板 + 【来自上游】投递）
│   ├── subagent.process_message(prompt)   ← 完整 LLM + 工具循环
│   └── 取结果：最后一条 assistant 消息
│       → finally：实例归还池中
└── 发事件：node_started / workflow_step_update / node_completed / node_failed
```

**池化复用的两条不变量**（`_delegate_pool`，`dict[pool_key, deque[CoaraBase]]`）：

1. **并行分支不共享活实例**：acquire 在锁内 popleft，两个并行分支拿到的必然是两个不同实例；`message_history` 不会交叉污染
2. **串行复用先清会话**：复用实例在跑下一步前 `start_new_session()`，上一步的历史不外泄；但工具注册表、技能加载等初始化成本被摊薄

引擎关闭时统一 `shutdown()` 池中所有空闲实例。

## 4. 双宿主：同一张图，两处执行

| 宿主 | 文件 | 形态 | 用途 |
|------|------|------|------|
| FlowCoordinator | `src/coara/flow_coordinator.py` | 内存 / 交互 | 会话内编排：`orchestrator` spawn 登记 → run 点火 → wait 收尾，`routes: one` 由节点运行期挑后继 |
| KernelGraphRunner | `wdl/src/wdl/core/kernel_runner.py` | 引擎 / 持久 | 无人值守：SQLite 状态、崩溃恢复、触发器；执行 WDL 定稿文本 |

两个宿主消费**同一个图模型与同一套激活语义**（`src/workflow/core/semantics.py`），差别只在宿主职责（是否持久化、谁能挑 one 后继）。

## 5. 编排工具 orchestrator

激活 `workflow` 技能后注册 `orchestrator` 工具（`src/tools/builtin/orchestrator/orchestrator.py`），十二个 action 覆盖编排全周期：

| action | 干什么 |
|--------|--------|
| `spawn` | 登记 flow 节点（flow / node_id / prompt / depends_on / routes_to / routes_mode），默认停车 |
| `run` | 点火 flow（`flow=…`）或提交 WDL 定稿给后台引擎（`draft_id=…` / `wdl=…`） |
| `wait` / `status` | 等 flow 收尾 / 查各节点输出 |
| `save` | 把会话内图自动投影为 WDL 并落盘（`save(flow=…)`） |
| `save` / `load` | 存 WDL 草案（`wdl=…`，校验后 canonical 落盘）或落盘/恢复内存图（`flow=…`） |
| `result` / `delete` | 查实例结构化结果 / 删草案 |
| `update` / `edge` / `remove` | 运行中调整：改节点 task/routes、加删边、删未运行节点 |

节点是"先跑后文档"的执行单元：LLM 在会话里 spawn 一组节点真实跑一遍，跑通后 `save(flow=…)` 自动投影为 WDL 并落盘，再交后台引擎正式执行。

## 6. 与 Root / Delegate 子智能体的同构性

| 能力 | Root | Delegate 子智能体 | 工作流节点 |
|------|------|------------------|----------|
| CoaraBase 实例 | ✓ | ✓ | ✓ |
| 工具循环 / ReAct 回退 | ✓ | ✓ | ✓ |
| 技能 | ✓ | ✓ | ✓ |
| Trace 事件 | ✓ | ✓ | ✓ |
| 上下文压缩 | ✓ | ✓ | ✓ |
| 打断回滚 | ✓ | ✓ | ✓ |
| 运行进程 | Root 进程 | Root 进程 | 引擎子进程（KernelGraphRunner 宿主）或 Root 进程内（FlowCoordinator 宿主） |
| 实例复用 | 长驻 | 每次 delegate 新建 | **按池键复用**（delegate 池） |

节点身份：内核图节点没有独立的能力声明字段——节点名即 persona 名，任务即 `task`，统一走 `coaras` 子智能体路径。能力由运行时给定，不由 WDL 声明。

## 7. 决策表

| 决策点 | 选择 |
|--------|------|
| 节点类型 | **只有一种**：智能体（`id` / `task` / `input` / `routes` / `max_activations`） |
| 控制流 | **全是图的形状**：并行=扇出、汇聚=扇入、分支=one 路由、循环=回边、重试=error 边 |
| 数据流 | `input` 模板 `{{steps.y.text}}`（引用上游节点结果，模板引用即隐式依赖）或字面量种子；无独立数据边、无图级 inputs |
| 路由模式 | `routes: all`（缺省，广播）/ `routes: one`（每次激活选一条） |
| 循环终止 | `max_activations` 激活上限（全局 100，节点可覆写），触顶即失败终态 |
| 节点实例生命周期 | **按池键池化复用**，串行复用前清会话，并行分支各占独立实例 |
| 节点结果回传 | 最后一条 assistant 消息，作为 `steps.<节点名>.text` 供下游引用 |

---

## 8. 核心结论

1. **图是唯一契约**：节点 + 边，控制流全部塌缩为图的形状，WDL 是图的 canonical 投影，没有 if/for/while/parallel/wait/merge 节点与 exec/data 边。
2. **节点即智能体**：所有节点都是完整 `CoaraBase` 子智能体，与 Root/delegate 同构，经 delegate 池复用；能力由运行时给定。
3. **双宿主同一语义**：FlowCoordinator 交互编排、KernelGraphRunner 无人值守，消费同一图模型与激活语义。
