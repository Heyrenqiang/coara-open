# 重启机制设计

给 coara 加可控重启（调试便利 + 以后自动更新落地都需要）。这属「一步走错就彻底挂掉」的功能，顺序与回退必须先定死，再写代码。

## 一、为什么当初删掉

旧实现（`process_restart.py`）是：拉起新进程 → 立刻 `os._exit(0)`。新进程若在启动阶段就失败（端口未释放、参数不对、依赖缺失、环境变量没继承），旧进程已经退出，结果是一个谁都没接管的空壳：终端断了、手机也连不上。删掉是对的——问题不在「重启」这个能力，而在「没有确认就交棒」。

## 二、安全协议（顺序不可调换）

1. **落意图**：在 `<coara_home>/restart_intent.json` 写入 `{requested_at, reason, requested_by, launch_cmd}`。它是诊断与「上次重启是否成功」的唯一凭据。
2. **复用原启动方式**：新进程必须与原进程**同模式**（托盘常驻 / 前台内核 / 服务）。取 `sys.orig_argv`（Python 3.10+ 保留的原始启动参数）复现，而不是拼一条「看起来差不多」的命令。模式错了等于换了个程序。
3. **分离式拉起**：`subprocess.Popen(..., creationflags=DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP, close_fds=True, cwd=<原工作目录>, env=继承)`。新进程不随旧进程退出而死。交棒前旧进程必须让位（释放监听端口 + 释放 `<coara_home>/coara.pid` 实例锁），否则新进程会因抢锁失败秒退、或因端口被占无法监听；任一步失败则恢复监听与锁、旧进程继续运行。
4. **健康确认**：旧进程先让出监听端口并释放实例锁，再拉起新进程，然后轮询新进程是否已在端口上可连；可连即交棒。超时（建议 30s）内连不上即失败。**这一步是唯一允许交棒的凭据。**
5. **交棒**：确认成功即退出，不做任何端上提示——重启是内核自己的能力，不需要 CLI/web/手机看到「已重启」之类的话，也不必为它落带消息。端不需要被告知：它们下次连接时自然连到新实例。
6. **失败即回退**：任一步失败或超时 → 杀掉已拉起的子进程（若还活着）→ 删除 intent 文件 → **旧进程继续运行**，把失败原因作为可见错误回给发起端。绝不在未确认时退出。

## 三、实现落点

- `src/runtime/restart.py`：`launch_command()`（从 `sys.orig_argv` 推导，带降级与校验）、`async def restart_kernel(*, reason, requested_by) -> RestartOutcome`（协议 1–6 全在这里，含健康轮询与回退）。
- `src/coara/commands/restart.py`：注册 `/restart` 斜杠命令（owner only）。命令里只做一件事：调用上面的函数（成功即交棒退出、不产出命令结果；失败才把原因回给发起端）。CLI 与 web 共用同一命令层，两端自然都有。
- 启动路径：内核启动早期调用 `consume_restart_intent()`——把 `restart_intent.json` 归档为 `restart_last.json`，再删除意图文件——这样「上次重启有没有成功」永远可查。
- 日志：拉起、健康轮询、成功交棒、失败回退，各打一行带 `[restart]` 前缀的日志，调试时一眼能追。

## 三点五、静默指令（/restart 不产出任何可见输出）

`/restart` 是纯内部动作：三端都不显示、不落带、不推送。

- 成功路径旧进程 `os._exit(0)` 直接交棒，根本不产出命令结果——因此天然静默：web 不推 `command_result`、不写视图帧；CLI 不往 scrollback 打输出行；手机端不发房间消息。
- 只有失败路径才回一条可见错误（那时旧进程仍在运行，必须让发起者知道）。
- 不进入录像带，也不进视图文件：它没有内容，只是一次内核动作。刷新/回放因此不会看到任何痕迹。
- 日志里留 `[restart]` 前缀的一行（拉起 / 确认 / 交棒 / 回退），这是唯一的可观测面，且只在服务端。

## 四、边界

- 只在「有一个健康的旧进程」时可用；没有旧进程可回退的场景（首次启动、崩溃恢复）不走这条链。
- 重启期间的在飞回合：不做特殊处理——重启是显式动作，发起者清楚代价。未完成回合按既有规则呈现（无 `turn_end` 视为中断）。不追求「把内存状态传给新进程」：新进程从磁盘恢复是唯一事实源。
- 并发保护：同一时刻只允许一次重启（intent 文件即锁；存在未决 intent 时拒绝新的 /restart）。
- 权限：owner only，与其它会改变内核生存状态的动作同级。

## 五、验收

1. 正常路径：`/restart` → 成功路径不产生任何端上可见输出（旧进程交棒即退出，端不被告知；失败才有可见错误）→ 端口仍可达 → 日志里拉起/确认/交棒三段齐全 → `restart_last.json` 记为成功。
2. 失败路径（人为造）：把 `launch_command()` 改成一条必然失败的命令 → `/restart` 报错、旧进程仍在跑、intent 被清、没有任何「空壳」状态。
3. 端口占用路径：让新进程拿不到端口 → 超时 → 回退成功，旧进程继续服务。
4. 端无感知：重启成功后 CLI / web / 手机都不需要看到任何提示；新实例正常服务，端重连即用。
