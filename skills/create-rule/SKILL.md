# 规则编写 — ws.md / AGENTS.md / user_rules.md

按本技能帮用户落常驻文案。这些是**运行时注入给模型看的指令/概况**，不是给人看的 README。

## 落点（三选一）

| 落点 | 何时用 |
|------|--------|
| `<工作空间>/.coara/ws.md` | 本空间**概况**：目录文件、用户行为、可选其它；缺文件时注入占位「概况生成中」 |
| `<工作空间>/AGENTS.md` | 本空间**开发/协作指南**；缺文件则跳过，不造占位 |
| `<coara_home>/system/user_rules.md` | **跨空间**用户偏好；缺文件则跳过 |

默认：问概况 / 目录 / 用户在空间里说过做过什么 → `ws.md`；问编码约定 / 架构 / 怎么跑测试 → `AGENTS.md`；问语气、语言、个人习惯 → `user_rules.md`。

## 动手前确认

1. **写哪一个**（上表三选一；可一次改多个）
2. **目的**：要补充、纠正还是整体重写

对话里已说清的不要重复问。

## 共同写法

- 只写**现状事实**与可执行约束；不写「已移除 / 不再」类历史叙事
- 短、可执行；路径与工具名写具体
- 用用户语言写正文；代码、路径、标识符保持原文
- 用 `write` / `edit`；缺目录先建（如 `.coara/`）

---

### `ws.md`（工作空间概况）

- 路径：`<工作空间>/.coara/ws.md`
- 以系统消息注入（前缀「工作空间概况：」）
- 维护概况，是为了让未来在该工作空间工作更加高效

骨架（顺序固定）

```text
# 目录文件
……

# 用户行为
……（没有值得记的就只留标题、下面不写条目）

# 其它
……（无内容则整块省略）

上面是该工作空间的一些情况，仅供参考
```

- **目录文件**：空间物理样子，让智能体知道哪在哪。有 AGENTS.md 时只写进门地图并指向它，不要把 AGENTS 的目录树/架构长文抄进 ws.md
- **用户行为**：用户在该空间说过或做过、能帮助把握意图的事实。格式：情境（时间、问题）- 用户输入（想法、意图、观点）- 现状（完成情况、方案建议）
  例：`09-04 同空间开了两条 CLI（A/B），在 A 发消息后 B 的 Thinking spinner 也跟着转 → 用户认定同空间多 CLI 应与各端一样显示独立，B 不该跟 A 的回合转 → 已用 attach channel_id 把回合 trace 只推发起连接，B 不再误亮 spinner`
- **其它**：悬置方案、未决问题等；无可整块省略
- 宁缺毋滥，每一条都要能说出放在这里的理由；总量有限，动态变化；**不是**技术 changelog
- 若 AGENTS.md 与 ws.md 重复：把能放到 ws.md 的放到 ws.md 并去重

---

### `AGENTS.md`（工作空间指南）

- 路径：`<工作空间>/AGENTS.md`
- 适合：目录结构、构建/测试命令、架构约束、子智能体与工具用法等**给代理干活用的仓内知识**
- 缺文件不注入、不自动生成
- 与 ws.md 重复时：能放概况的放进 ws.md，AGENTS 去重

---

### `user_rules.md`（跨空间偏好）

- 路径：`<coara_home>/system/user_rules.md`
- 以系统提醒注入
- 适合：语气、回复语言、个人习惯等**与具体仓库无关**的偏好
