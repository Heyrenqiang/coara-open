# 调研技能（research）

在 Root 上下文中激活本技能后，按下列规范执行调研任务（无需 `delegate`）。

## 何时使用

- 多源信息、交叉验证、结构化报告
- 需结合代码库、配置、命令输出与公开网页/文档
- 交付物为文件 + 摘要（Word/Excel/Markdown 等）

## 何时不用

- 只在当前仓库找文件/符号 → `glob`/`grep` 或并行 `delegate(coaras)`（prompt 写明只读）
- 单步事实问答 → Root 直接工具
- 需要 **并行扫多个互不相干代码库** → 并行 `coaras`，不是本 skill

## 调研理念

- **问题先于答案**：弄清对象、范围、成功标准与边界
- **证据先于结论**：重要判断指向具体来源（路径、命令输出、URL、`[N]`）
- **多源交叉验证**：同一事实尽量两种独立来源类型印证
- **时间意识**：涉及时效话题遵守 `web_search` 工具描述（query 不写具体年份；`search_target` 写清要足够新的信息）
- **诚实边界**：证据不足时标注缺口，不编造来源

## 方法论要点

- 结构化拆解实体、关系、因果与政策/技术边界
- 广度 → 深度：先圈关键词与源类型，再对关键假设深度取证
- 一手优先：官网、监管文件、论文、厂商公告、仓库
- 冲突来源：比较时间、权威性，报告中说明分歧
- 搜索迭代：单 query 精准；结果偏了换实体词或相邻概念
- 时效核验：结论含「最新/现状/版本」时核对正文日期

## 成果形态

- 调研结果写入文件；回复给用户 **绝对路径 + 摘要**
- 正文建议：结论摘要 → 分维度论述 → 证据与来源 → 风险/不确定性
- 引用：正文 `[N]`，末尾 `[N] [标题](URL)`（Markdown 链接）
- 涉及时效：写明检索时间、信息截至时间、时间不确定性

## 工具纪律

- 事实必须来自工具，不能文字假装已查
- `web_search` / `web_fetch` / `read` / `grep` / `shell` 按工具描述使用
- 多步子课题用 `todo(action="update")` 自推
- 独立工具调用可并行；有依赖则串行

## 表达

- 清楚、完整、有条理；不寒暄、不 emoji
- 不复述工具调用过程
- 存在多选项时给简明对比
