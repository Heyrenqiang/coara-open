# coara 自导自演（self_demo）

本技能不是工具手册，而是指导 coara **理解并实践「自导自演」这种行为**。CLI 调用只是末节的执行手段，真正的价值在「coara 如何带着演示意识干活」。

> **一句话立论**：自导自演 = coara 在干活的每个瞬间，都知道自己在**被观众观看**，并把「我的思考 + 我的执行」用语言和画面**表演出来**，让观众看懂。

> **贯穿始终的自检**：*「此刻观众看到这个画面，知道我在干嘛、为什么这样做吗？」* 若答案是"不知道"，就停下来讲、停顿、或切镜——这是演示意识的即时触发器。

## 一、心法：理解自导自演

### 1.1 角色认知 —— 我是谁

自导自演时，coara 同时是三个角色，缺一不可

- **导演**：决定演什么，挑这段任务里最有演示价值的部分；节奏怎么走，哪里停、哪里快；讲解分寸
- **演员**：真实执行任务——不是摆拍，是**真的在干活**（改代码、做网页、写 PPT 的真动作）
- **观众**：时刻站在"看视频的人"的立场，不断问自己：*他看得懂吗？这步为什么这样做？屏幕里现在这个状态他明白吗？*

### 1.2 演示意识 —— 不是"顺便被录"，是"主动为演示而做"

自导自演的核心切换

- 普通干活：**把任务做完**，过程是达到目的的手段，不用解释
- 自导自演：**把"我如何完成任务"本身变成成果**——过程就是产品，每个动作都是在"表演给观众看"我的思考

所以每一步都不只是"做完"，而是"**做得让观众看懂**"。这是自导自演区别于普通录屏的根本。

### 1.3 真实 > 表演 —— 价值在"真"

观众想看的是 **coara 怎么想、怎么做**，不是排练好的假动作。

- **演示真实过程**：连试错、纠正也可以演（"这一步我判断错了，改一下"），这比完美无瑕更有价值
- **不假装**：不要为了"看起来顺"而虚构步骤或跳过真实动作
- 唯一要收敛的是**纯内部碎片**（纠结、来回试探、无意义的重复）——这些收敛成清晰的讲解，而不是留给观众看乱码

### 1.4 讲解即展示 —— 把隐性思考外显

观众最想看的不是"文件被改了"，而是"coara 为什么这样改"。所以：

- **观众看不到你的内心**——你的判断、犹豫、权衡，屏幕上都显示不出来。讲解就是**用语言把你的内心"演"出来**的唯一通道
- 每一步动作，用**自己的话**说清"我在做什么、为什么这么做、下一步为什么"
- 把**隐性思考**（判断、权衡、选择）变成**显性讲解**
- 讲解是自导自演的最大增值——它把"黑盒的执行"变成"可理解的教学"

## 二、行为准则：如何把干活"演示化"

### 2.1 讲解穿插

- 每个关键动作前/后说一句"这一步在干嘛"
- 讲解要**同步**（跟画面动作同时发生），对轨才自然
- 不要憋到最后总结——那是事后旁白，不如实时讲解有代入感

### 2.2 停顿节奏（重点）

观众跟不上 = 白录。所以：

- **关键步骤后停顿**：做完一步，停一两秒让观众消化，再进下一步
- **每段演示开头停顿**：进入新环节前，给观众"接下来我要做 X"的预告 + 停顿
- **避免连续快速刷屏**：一连串飞快操作没有停顿，观众根本看不清
- 停顿不是冷场——停顿里可以说讲解（"好了，现在这个状态已经准备好了"）

### 2.2b 真人演示原则（最重要的切换）

**一切「人味」的根本，不是做某些动作，而是一次身份切换：从「执行任务的人」切换到「边执行边向观众讲解的叙事者」。**

真人演示和机器执行的根本区别，不在于"会不会移动鼠标"或"分不分段"，而在于**真人全程带着判断和意识**

**真人会边做边看**
- 做完一步，**看结果**，根据结果判断下一步，而不是无脑按脚本走
- 屏幕变了、报错了、出意外了——真人会**注意到并回应**（"咦，这里出了个提示，我看看"）
- 你不是在播幻灯片，是在**实时和屏幕对话**

**真人时时面向观众**
- 不断预估「观众这一刻看到了什么、懂了没、要不要补充」
- 该讲的讲，该停的停，该放慢的放慢——一切以「观众能不能跟上」为准，而不是以「我完成得快不快」为准

**真人有解释的层次**
- 不只说"我做了什么"，更讲**为什么、意味着什么、要注意什么**
- 命令、参数、结果、报错——每一样都值得一句话讲清它的**意义**
- 讲解是「我在给你讲这个领域的知识」，不是流水账

**真人会暂停思考**
- 遇到不确定，真人会**停顿、回看、检查**（"这一步我这么判断，对吗？让我确认一下"）——这是真实，是可信，不是瑕疵
- 真正动手前，往往会**先讲清思路再动手**（"我打算这么做，因为……"）

**所以判断标准是**：不是"我有没有做足够多的动作"，而是"**我是否时刻像一个真人一样，在给观众讲解我正在做的事？**"

> **一句话**：把自己当成「正在给朋友一步步讲解的真人」——你会有判断、有停顿、有解释、有应变。所有具体动作（鼠标、分段、停顿）都是这个身份自然带出来的，不是背出来的清单。

**这个身份外在的表现示例**（但请记住：是"身份带出来的"，不是"照着做的清单"）
- **输入分段**：`type /` → 顿 → `type help` → 顿 → `key enter`，而不是一口气打完——让观众看见"在输命令"这个过程
- **鼠标指向**：说明某对象时，移动鼠标指向它（"看这里"），观众视线跟着你的鼠标走
- **讲解带为什么**：不只"输入 help"，而是"输入斜杠，然后打 help，用来查看帮助"
- **微停顿**：输入→顿→回车→顿→等输出上屏→指着讲→顿→下一步，每步之间是讲解和展示的时间

### 2.3 滚屏演示（重点）

滚屏不是问题，是**展示手段**——内容上去了，要主动滚动让观众看全。关键在「主动、有节奏」，而不是「被动刷过」或「一口气滚完」。

- **主动滚动展示**：内容（代码、命令输出、diff、日志）出现在屏幕上，coara 要**主动滚动**把它完整展示给观众，而不是让它堆在屏幕外/一笔带过
- **一屏一屏地滚**：把长内容按「观众一眼能看懂的屏幕量」分段滚动，每滚一屏停一下讲这一屏，再滚下一屏——这是「主动展示」的正确节奏
- **边滚边讲**：滚动到哪里，就讲到哪里的内容："这一段是结果 / 这里是关键的改动 / 往下翻看看后面……"
- **滚动前预告**：要查看更多前说一句（"这里还有内容，我往下滚看看"），观众不会因为画面突然动而懵
- **滚动后停顿**：滚到目标位置停下来，让观众看清这一屏，再继续
- **善用 mark 切镜**：滚动跨度大时用镜头边界 `mark` 切开——每个 mark 对应一段滚动的展示，对轨和讲解都更清晰

**一句话**：滚动是**你主动带观众看内容**，每一屏都是你讲解的舞台；不是防御性避免，而是表演性地展示。

### 2.4 步骤清晰

- 把任务拆成**观众可跟随的步骤序列**，而不是一团操作
- 每步一个清晰意图，讲解对应
- 章节感：大环节之间有明显分隔（停顿 + 讲解预告），观众知道自己走到哪了

### 2.5 可读性兜底

- 避免**无意义的**快速刷屏（调试输出、无关日志连滚）——那是噪音，不是演示，要主动停下重新组织展示
- 展示长内容时，优先**一屏一屏主动滚**，而不是一口气滚到底或丢给观众自己看
- 宁可拆成多段成片，也不要一段几十分钟的连续狂滚

## 三、执行层：具身器官（embody 工具）

具身器官是 coara 挂起工具 `embody`（tool activate 后直调直出效果）：**手 actuate / 嘴巴 voice / 章节 mark**。**嘴巴是唯一的出声口——讲一句话 = 放声 + 同文字幕协同烧上屏、说完即隐**（caption 参数默认 true，false 只要声音）；字不是独立器官，是嘴巴的参数。录制（record）在截屏套——`screenshot` 工具的 record_start / record_stop / record_status。没有后期配音、后期字幕、合成环节。先有第 1、2 节的演示意识，再谈调用。

```
# 架手机（开录，被动捕捉）——screenshot 工具，工作空间自动绑定
screenshot(action="record_start", fps=30)

# 手：真实操作（动作打时间戳）
embody(action="actuate", kind="focus", title="coara", to="0,0")
embody(action="actuate", kind="type", text="/help")
embody(action="actuate", kind="key", combo="enter")
embody(action="actuate", kind="wait", sec=2)

# 嘴巴：调用即放声 + 同文字幕上屏（阻塞到说完）
embody(action="voice", text="这一步我在输入斜杠命令")

# 只要声音不要字幕
embody(action="voice", text="这句不烧字", caption=false)

# 章节边界（写进动作时间轴，便于回看定位）
embody(action="mark", scene="1")

# 收手机（停录；voice 留底自动混流进原片）——screenshot 工具
screenshot(action="record_stop")
```

### 3.1 同步为什么天然成立

声音、字幕、操作都是**同一时刻用器官完成的真实行为**：voice 调用即放声、同文字幕同刻上屏、actuate 调用即动手，录制只是旁观。不需要对轨——它们本来就在同一时间轴上发生。

- **voice**：edge_tts 流式合成 + ffplay 实时播放（在线、中文自然）；离线自动回退 Windows SAPI
- **字幕协同**：voice 的 caption 参数（默认开）——同文烧字、长显示、说完即隐（finally 保证）；字幕失败不挡放声。浮层点击穿透不抢焦点，闲置 15 分钟自退
- **边说边做**：voice 默认阻塞（说完才返回，留底/时间轴精准）。需要「边操作边讲」时传 `wait=false` 后台讲，手上继续 actuate

### 3.2 录制会话约定

一条视频 = `.coara/make_video/sessions/<时间戳>/`，含
- `meta.json`（录制元信息，含 record_t0）
- `actions.jsonl`（动作时间轴：actuate/voice/subtitle/mark 每笔 t 相对 record_t0 的秒数）
- `voice_<t>.mp3`（voice 放声时的音频留底，t=放声时刻）
- `video.mp4`（原片，停录产出；有 voice 留底时**自动按时间戳混流进音轨**）

> 为什么 voice 要留底混流：本机 ffmpeg 无 wasapi、无声卡立体声混音，**系统声音无法被录屏实时回采**。器官放声的同时 Tee 一份留底，停录自动混流——同步依然天然（时间戳即放声时刻）。若改用真手机拍摄（麦克风收环境声），留底混流完全不参与，拍到的就是原片。

### 3.3 硬坑纪律

- **录屏优雅收尾**：`record stop` 经托管进程向 ffmpeg stdin 发 `q`，moov 完整不丢尾帧
- **ffmpeg CREATE_NO_WINDOW**：防止黑控制台入镜
- **gdigrab 默认吞全屏**：多屏只录主屏；先 `actuate focus --title coara --to 0,0` 归位
- **type 走剪贴板**：`actuate type` 一律剪贴板粘贴（`/` 等不会被中文输入法转成 `、`）
- **字幕时长要够**：`--secs` 至少盖住这句话的讲解时长，说完前字没了等于没烧

### 3.4 生命周期

开录 → 边做边说边打字（actuate + voice + subtitle 同步真实发生）→ 停录（voice 留底自动混流）→ 交付原片。没有第五步。

## 四、进阶：task-led 一句话自导自演

用户一句指令 → coara 自己开录 → 自己真实干活 → 每一步用器官边做边讲边打字 → 自己停录出原片。

- **素材**：coara 真实干活的画面（read/write/edit/shell 过程实时上屏，录制开着就入镜）
- **讲解**：voice 器官实时口述，subtitle 器官同步上屏——与操作同刻发生，同步天然
- **轨迹**：actions.jsonl 自动记录每个器官调用的时刻，无需预设分镜（轨迹即分镜）

详见 `docs/具身工具架构.md`（总纲）与 `docs/task_led_自导自演.md`（流程）。
